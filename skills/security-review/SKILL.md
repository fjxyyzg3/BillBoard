# 安全审查

## 确定审查范围

1. 读取适用的仓库规则、威胁模型和发布要求。项目规定了数据边界、敏感信息、严重度或验收门槛时，按项目规则执行。没有专项规则时，从受审系统的实际数据、权限和运行入口确定检查范围。
2. 确定受审仓库、基线和候选版本。Git 变更先用 `git status --short`、`git diff --stat` 和 `git diff --cached --stat` 定位范围，再审阅实际差异、本次新增文件及相关待推送提交。仓库公开或发布审查需明确受审快照、产物或运行环境。
3. 默认只读取证。修复、公开、推送、改写历史和修改生产配置按任务授权执行。需要读取远端或线上环境时，使用获准的访问身份并记录证据范围。

## 检查变更涉及的边界

- 审查**认证与授权**时，定位服务端实际执行的权限校验。以受信任的身份为依据检查请求的对象、操作和数据范围，核对角色和归属是否来自服务端可信来源。涉及会话、邀请或异步操作时，检查过期、撤销、重放以及最终使用权限时的校验。用针对性测试验证越权请求被拒绝。
- 审查**数据与输入**时，检查数据访问、写入、导入和导出是否遵守作用域及生命周期。重点核对不可信输入进入解析器或外部服务前的验证和资源限制，以及重试、并发、部分失败时的完整性。
- 审查**凭据与隐私**时，检查源码、暂存区、新增文件、样本、配置、构建产物、URL、客户端存储及日志等实际涉及的渠道。按项目策略识别敏感入口或私有标识。用 `git grep -il -E` 等本地命令仅输出候选路径，扫描暂存区时加 `--cached`，另查尚未跟踪的新增文件。仅记录类别、位置、状态和脱敏证据。
- 审查**部署与网络**时，同时核对受审配置和实际运行边界。逐跳确认监听地址、路由、防火墙或访问限制、管理入口、TLS 终止和适用的浏览器响应头。核对镜像构建输入及代理、应用和日志采集配置实际处理的数据。结论限于已核验的入口、身份、环境和产物。
- 涉及**仓库公开与历史暴露**时，拟更改可见性、发布独立公开副本或核实历史泄露均按[仓库公开与历史审查](references/repository-exposure.md)执行。日常公开推送核对待推送差异和新增提交的元数据。
- 审查**依赖与工具链**时，按实际安装入口和交付产物核对上游公告、解析版本、使用路径和修复证据。涉及 npm 公告、依赖解析或构建工具时，读取[npm 依赖安全审查](references/dependency-review.md)。

## 验证与报告

选择能证明受影响安全属性的证据，并满足项目规定的验证门槛。文档变更也应按范围核对路径、命令、配置变量及敏感信息。复用证据前确认其范围和输入仍适用。验证失败后保留原结果，补跑失败项及受影响范围，并合并证据确认覆盖。

1. **Findings** 按影响排序，给出文件或配置位置、触发条件和实际影响。区分已确认的泄露、公开后才会发生的暴露和尚待核实的可能性。没有阻塞项时明确说明。
2. **Verification** 记录确认过的快照和范围、实际执行的检查及结果。涉及远端时注明版本和访问身份，复用证据时注明仍覆盖的范围。
3. **Residual Risk** 记录范围之外、未检查或无法确认的风险，以及已接受的风险和对应授权范围。

发现疑似泄露时，先脱敏核实真实性、当前有效性和访问范围。已确认的阻塞问题应暂停相关交付，按项目事故流程和授权推进。其余可独立完成的审查继续进行。必需证据缺失或失败时，将对应范围标为待验证或未通过。阻塞问题解决且必需证据齐全后，再标记通过。
