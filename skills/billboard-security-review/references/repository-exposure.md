# BillBoard 仓库公开与历史审查

用于评估私有仓库原地公开、发布独立源码副本，或核实曾进入 Git 的敏感内容。日常向公开仓库推送时，核对待推送差异及新增提交的作者、提交者邮箱。发现历史线索时扩大到对应引用和托管内容。

## 确认可见范围

1. 核对源库和目标库的身份、可见性、受审提交与当前授权。工作区有多个远端时，使用只连接目标远端的干净审查副本。列出远端分支和标签（可用 `git ls-remote --branches --tags`），核对待公开树和这些引用可达的全部历史。查看作者及提交者邮箱、注释标签和提交说明。与登录身份重合的邮箱按隐私风险处理。
2. 用凭据扫描器（例如 Gitleaks，输出脱敏）覆盖受审历史。再做定向检查，覆盖生产入口、私有附件直链、备份标识、生产统计、家庭姓名、账号和订单标识，以及文档中指向旧快照的 SHA 或链接。对已知私有值仅在本地比对，记录类别和位置。报告附扫描范围和规则的局限，零命中只代表这些规则在该范围内未命中。
3. 复核 PDF、表格和压缩包等测试样本的实际内容及元数据，包括 PDF 文本层、表格隐藏内容和包内文件。公开样本使用合成数据。用合成字段验证脱敏规则，可对已人工复核的整份合成文件保留完整性摘要。真实姓名、卡尾、订单号等可猜测字段的摘要和原始长度也属于待清理线索。更改样本时运行相关脱敏检查，包括 `tests/unit/sensitive-fixtures.test.ts`。
4. 使用获准身份检查 GitHub 端的 Issue、PR 及其引用、评论、Release 及附件、Actions 日志和制品等实际存在的内容。另行核对已知关联 fork、缓存视图及旧提交的可读状态，限当前授权范围，仅记录状态和证据范围。鉴权读取与匿名读取分别取证，单个访问结果仅覆盖该对象、入口和访问身份。[GitHub 敏感数据清理说明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)

对真实凭据，按仓库事故规则通过获准的凭据管理渠道核实撤销或轮换状态。原地公开前按[安全审查的停止条件](../SKILL.md#停止条件)处理仍可读的敏感历史和托管内容。有关旧提交的托管状态无法确认时，在结论中明确该公开方案仍待验证。

## 验收独立公开副本

仅在当前任务授权的情况下创建、推送或改变可见性。需要保留旧库私有时，可以从已确认的源提交导出跟踪文件，在独立仓库清理并审查快照，使用 GitHub `noreply` 邮箱创建初始提交。保持两个仓库独立，复核提交没有父提交，且作者、提交者均使用预期邮箱。

1. 先保持目标库私有，完成本地扫描和对应验证。获准推送后，从实际目标远端重新克隆，复核远端 SHA、文件范围、分支与标签、提交历史及适用的托管内容。对本次涉及的已知旧提交做定向复核。以远端复核结果判定待公开内容。
2. 必需检查通过后，按授权确认目标库再变更可见性。使用无鉴权访问验证目标库及预期源码可读。任务要求源库继续私有时，复核源库的可见性和匿名访问状态。报告保留受审版本、访问身份、已确认的风险和未能验证的范围。[GitHub 仓库可见性说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/managing-repository-settings/setting-repository-visibility)
