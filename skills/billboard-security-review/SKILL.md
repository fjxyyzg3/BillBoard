# BillBoard 安全审查

## 概览

按实际变更面审查 BillBoard 的家庭数据隔离、财务完整性、凭据和外部暴露。只读审查收集并报告证据。公开仓库、改写历史、推送或变更生产配置按当前任务的授权执行。

## 审查流程

1. 确认仓库、分支和审查基线。用 `git status --short`、`git diff --stat` 和 `git diff --cached --stat` 界定范围，覆盖本次交付涉及的新文件、工作树、暂存区及待推送提交。结论对应实际受审的差异或快照。
2. 按下方清单检查相关区域。拟改变仓库可见性、发布公开副本或核实历史泄露时，读取[仓库公开与历史审查](references/repository-exposure.md)。涉及依赖公告、依赖解析结果或 npm 构建工具变更时，读取[npm 依赖安全审查](references/dependency-review.md)。
3. 按「验证选择」和 [AGENTS.md](../../AGENTS.md) 第 6 节选择本阶段验证，记录证据范围。必需证据缺失时将对应判定标为待验证。
4. 先报告发现项。阻塞问题已解决且必需证据齐全后，才标记该范围通过。

## 关键检查

### 认证与会话

- 读取或修改家庭数据的 server action、页面和 route handler 必须调用 `requireAppSession()`，或由已认证的 app layout/middleware 保护。
- 不要信任客户端传入的 `householdId`、`memberId`、角色、邮箱或用户 id 来做授权判断。
- `AppSession` 必须绑定原有效成员身份；旧 JWT、旧会话和待确认任务不能随账号重新加入取得新身份权限。无有效家庭账号只能访问受限账号状态。
- 凭据验证至会话创建之间须在同一账号锁内重验原邮箱、密码哈希、状态与成员身份。未映射旧 JWT 必须受签发时间及保留的敏感撤销审计约束；恢复失败不可重签更新 `iat`，也不可清理仍被兼容恢复依赖的撤销审计。
- 最终写事务必须再次核验账号、会话、有效成员、家庭和目标账本，使用与身份失效／OPS 撤销一致的并发锁；只在推理前检查不构成完整授权。
- NextAuth credentials 登录必须把密码验证保留在服务端，使用 `argon2`，使用 JWT session，并把 `id`、`memberId`、`householdId` 写入 session。
- 生产 `AUTH_SECRET` 不得回退到可用占位值。不要削弱登录限流，也不要用不同错误信息暴露“邮箱存在”和“密码错误”的差异。

### 家庭数据隔离

- 账号自助从本人有效 `AppSession` 派生账号；无家庭账号可管理本人但不能读旧家庭。OPS 平台邀请仅经本机受保护入口，家庭邀请仅当前负责人签发，不接受客户端决定家庭、角色或收件人。
- 邮件凭据仅存摘要、绑定用途且限时一次性；发信失败不消费邀请或改变密码，公开条件受理响应不得枚举邮箱。新账号验证后原子消费邀请，已有账号须本人登录、邮箱已验证且无有效家庭；旧会话不得升级到新身份。
- 成员退出／移除／转让与写账锁序一致，撤销不再合法的会话、邀请和恢复凭据，保持唯一负责人及历史统计。最后负责人退出不能绕过第四期关闭流程。

- 每个家庭数据查询或写入都必须按当前 session 的 `householdId` 收敛范围；成员视角必须从同一家庭的成员列表派生。
- 交易更新和删除必须确认目标属于当前 session 家庭，并且尚未软删除。
- 有效交易列表、报表和钻取查询必须包含 `deletedAt: null`。
- 不允许客户端传入的 `actorMemberId`、`createdByMemberId`、`categoryId`、draft id 或 mapping id 跨家庭生效。
- 家庭／账本／成员引用必须有组合外键或等价数据库约束；历史成员不会因退出而漏计金额，编辑其他字段不强制改挂历史归属。
- UUID 唯一性不能因新增账本被放宽；原成功／失败结果和输入摘要保持。多账本的新写入缺少明确上下文时拒绝，旧已提交 UUID 仅在原合法身份下查询；旧浏览器草稿只能落到 `acceptsLegacyDrafts` 标记的原默认账本，不能跟随新默认或按创建顺序猜测。
- 查看范围与新记账目标分别表达并授权，列表／搜索令牌／报表／钻取的账本过滤一致。归档历史可读且计入家庭总额，不能修改、软删除或移动；账本默认／归档操作限负责人，并与账务写入按家庭优先锁串行。
- 同身份切换账本保留原任务及 UUID，任务目标在开始时固定，不能增加每账本并发额度或重新发送原文。身份结束仍清除旧访问；晚响应不得复活旧身份草稿或覆盖新草稿。

### 财务完整性

- 持久化金额只能使用整数分 `amountFen`；不要用浮点数保存或比较持久化金额。
- 日期和范围逻辑必须保持 `Asia/Shanghai`。
- 分类类型必须匹配交易类型。内置分类名在数据库中保持英文，中文展示只放在 `src/lib/i18n.ts`。
- 不要引入会静默改写历史交易值的大范围编辑。

### 导入流水线

- 导入入口保持 `/records/import`；支持来源是随手记 `.xlsx`、微信支付 `.xlsx`、支付宝 `.csv`、招商银行借记卡交易流水 `.pdf`。
- 上传文件必须在解析前检查类型/扩展名并限制大小。不要记录原始账单行、备注、账号标识或上传文件内容。
- 导入交易必须写入 `source`、`sourceFingerprint`、`sourceImportedAt`；手工交易必须保持这些字段为空。
- 同源去重必须包含软删除交易。草稿确认在重试时必须保持幂等。
- 导入不得创建分类。映射必须按家庭收敛，并且只能指向现有启用分类，分类类型必须匹配交易类型。
- 大草稿确认必须使用批量读取/写入和 transaction timeout；避免在交互式事务内逐行访问数据库。
- 草稿固定目标，pending 原创建身份失效后停止确认并给出可解释状态；完成草稿与退款元数据作为家庭历史来源保留。同家庭共享草稿的既有授权不自动改为个人私有。

### 部署、网络与凭据

- 部署或公网入口有变更时，分别核对受审配置和实际运行边界，记录获准取得的入口、转发限制和发布产物证据。部署流程参照[家庭网络检查清单](../../docs/runbooks/home-network-checklist.md)。
- Git 跟踪文件不得包含真实账号、密码、token、生产域名、公网 IP、frp/ECS 主机或私有服务 URL。
- 向公开仓库推送时核对新增提交的作者和提交者邮箱，使用已核验的公开身份。
- 示例凭据只能以占位符形式出现在跟踪文件中。真实值只能放在未跟踪 env 文件或私有部署配置中。
- 生产公网入口保持 HTTPS 根路径；当前链路为 `HTTPS 域名转发服务 -> frps remote 3000 -> frpc -> 本地 127.0.0.1:3000 -> web:3000`，远端未部署 nginx。远端 `3000` 访问限制须按转发服务实际来源核验并最小化，不得无证据声称已对公网封禁。
- `compose.yml` 的 `web:3000` 只允许 loopback 发布，禁止 `0.0.0.0:3000` 或裸 `3000:3000`；生产数据库不得发布主机端口，`compose.dev.yml` 开发库仅绑定 loopback，默认 `127.0.0.1:5432`。
- Windows Docker Desktop 直接发布的 `3000` 必须只绑定 loopback，且只能给本机健康检查或 frpc 本地转发使用。独立 OPS 容器仅发布 `127.0.0.1:32768:3000`，不得进入公共 Compose 端口、域名转发服务、nginx 或 frp 映射。公网访问必须使用现有 HTTPS 根路径入口。
- `.dockerignore` 必须排除私有 env、备份和本地工作目录（含 `tmp/logs`），镜像不得携带这些内容；容器内 `DATABASE_URL` 的用户名、密码和库名必须正确 URL 编码，日志不得输出秘密。
- 引擎迁移必须在停止源写入后取得可恢复备份，恢复到核实为空的目标库，并比较全表行数和校验摘要，包括软删除记录及会话。保留源卷和备份，生产迁移不执行 seed；新库写入后的回退不得丢弃新增数据。
- Windows 启动固定使用 `desktop-linux`，发布输入和镜像 SHA 必须对应已验证、已推送的提交。登录任务采用 `AtLogOn` / `Interactive`，不能用登录前运行的假设代替实际检查；备份复制失败时保留已核验的本地文件并返回失败。
- 按实际 HTTPS 入口核验基础浏览器安全响应头；应用提供同源麦克风 `Permissions-Policy`，前置服务不得覆盖为禁用，不得假定已具备可选 nginx 示例的全部响应头。真实 hostname 和 TLS 设置只放在私有转发服务或部署配置中；nginx location 仅为可选示例，占位 frpc 配置不代表实际访问限制已核验。
- 音频能力链接的完整 URL、查询参数和音频不得写入外部转发服务日志；须核验实际服务及日志采集配置。应用的 `no-store`、短 TTL 和本地删除不能证明外部日志已关闭或音频已删除。
- `NEXT_ALLOWED_DEV_ORIGINS` 是私有开发配置；不要提交真实 host。

### UI 与浏览器暴露

- 验证／恢复／邀请仅使用私有配置的可信 HTTPS 根入口，fragment 凭据读取后立即清除，只留内存并经明确 POST 提交；不能放入查询参数、回调地址、日志或浏览器持久化存储。真实 SMTP 及实际 HTTPS／转发边界须有验收证据。

- 不要把凭据、原始导入数据、备注、source fingerprint 或批量/历史财务细节新增暴露到 URL、客户端日志、分析工具或持久化客户端存储中。
- UI 授权不是安全边界；即使隐藏控件被手动调用，服务端检查也必须拒绝越权访问。
- 新增 UI 文案必须同步更新 `src/lib/i18n.ts` 的中文和英文文案。

### 依赖与工具链

- 影响 Next.js、Auth.js、Prisma、上传解析、构建产物或部署的依赖变更，按[依赖审查步骤](references/dependency-review.md)核对公告、锁定版本和实际使用路径。优先复用能证明安全属性的测试，有覆盖缺口时补针对性回归。
- 没有明确需求和审查时，不要新增安全敏感包、认证 provider、遥测、远程日志或网络客户端。

## 验证选择

除非变更明显需要更多验证，否则使用以下默认规则：

| 变更区域 | 最小验证 |
| --- | --- |
| 仅文档（含根版本字段同步） | 核对路径、命令、环境变量、凭据与入口标识，检查版本字段一致性 |
| 认证/session/权限 | `npm run lint`、`npm run test:unit`、`npm run test:integration` |
| Prisma 查询/server actions | `npm run lint`、`npm run test:unit`、`npm run test:integration` |
| 登录/导航/表单 | 追加 `npm run test:e2e` |
| 导入 | 单元 parser 测试加集成导入测试；流程变更追加 e2e |
| 部署/网络/凭据 | 静态安全测试、针对性文本扫描和相关文档检查 |
| 公开仓库或历史泄露 | 按[仓库公开与历史审查](references/repository-exposure.md)复核目标快照、远端历史和托管内容 |
| npm 依赖安全 | 按[依赖审查步骤](references/dependency-review.md)验证各受影响锁文件、公告和调用方 |
| 任务分支开发检查点 | lint、受影响测试及本次安全属性验证；记录尚未运行的全量检查，不作为发布证据 |
| 合入／提交到 master、推送或发布代码、运行配置、依赖或测试工具链 | 执行 `AGENTS.md` 要求的完整验证，可复用仍有效的证据 |

全量验证中有失败时保留原始记录，排查后补跑失败文件和受影响范围。合并原始记录与补跑证据核对完整覆盖。因输入变化失效的证据需要重新验证。

凭据与入口扫描优先对受审文件做本地检查。可用 `git grep -il -E` 仅列候选路径，检查暂存内容时加 `--cached`，本次新增但尚未暂存的文件单独核对。报告只记录字段类别、位置、状态和脱敏后的证据。

## 输出格式

用中文返回审查结果：

- **Findings** 放在最前，按严重程度排序，并提供文件/行号引用。`P0` 表示主动泄露或跨家庭数据暴露，`P1` 表示很可能可利用的安全回归，`P2` 表示加固或测试缺口。
- **Verification** 列出受审范围、已运行的命令或检查及其结果。涉及远端时注明核对的版本和访问身份。复用验证时说明该证据仍覆盖的范围。
- **Residual Risk** 说明未检查、无法确认或本次范围外仍存在的风险。区分已证实的暴露、公开后才会发生的暴露以及尚未核实的可能性。
- 如果没有发现项，明确说明安全审查没有发现阻塞问题，然后列出验证和残余风险。

## 停止条件

- 如果发现疑似凭据、生产入口或真实隐私数据，先以脱敏方式核实真实性、访问范围与当前有效性。确认泄露后暂停相关交付，按 `AGENTS.md` 的事故响应规则推进已授权处置。
- 如果变更可能暴露或修改其他家庭的数据，不要在没有修复和回归测试的情况下批准。
- 如果必须验证的项目无法运行，不要宣称变更已验收；说明仍未验证的内容。

## 常见错误

| 错误 | 正确处理 |
| --- | --- |
| “UI 已经隐藏了那个选项” | 验证 server action 或查询会拒绝伪造输入。 |
| “draft id 很难猜” | 仍然必须用 `householdId` 收敛 draft 读写。 |
| “只是文档改动” | 仍要扫描真实 host、命令、环境变量和凭据示例。 |
| “软删除行不重要” | 普通视图排除它们，但同源导入去重必须包含它们。 |
| “金额只是展示用” | 持久化值保持 `amountFen`；只在边界格式化。 |
