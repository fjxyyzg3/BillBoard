# 记一笔页面效率优化设计

## 背景

`/add` 记一笔页面当前有三类体验问题：成员和时间下拉/选择控件外观不一致；分类以大按钮全部露出，占用较多移动端垂直空间；字段标题和控件之间显得偏紧。目标是在不改变数据模型和记账流程的前提下，提升移动端快速记账效率和整体表单观感。

## 假设

- 只优化 `/add` 记一笔页面，不改记录编辑抽屉。
- 不新增页面、数据库字段、用户配置项或分类管理能力。
- 常用分类按登录成员习惯统计；帮另一位家庭成员补记时，常用分类不跟随成员下拉变化。
- 日期和统计窗口继续按 `Asia/Shanghai` 计算。
- 备注仍提交到现有 `note` 字段，只改输入控件形态。

## 目标

- 分类选择默认显示常用项，减少进入提交按钮前的滑动距离。
- 成员和时间控件视觉一致，避免同一表单里出现两套下拉样式。
- 字段标题、控件和分类 chip 的间距更统一。
- 保持移动优先、默认中文并支持英文切换。

## 非目标

- 不改交易创建接口、权限模型、金额持久化规则或分类数据结构。
- 不新增固定底部提交按钮。
- 不新增自定义日期时间选择器。
- 不调整首页、记录页和导入流程。

## 页面结构

表单顺序保持不变：

1. 类型：保留支出/收入 segmented control。
2. 金额：保留表达式输入和预览。
3. 分类：改为常用优先 chip 区，折叠态显示 5 个分类和一个“更多”按钮。
4. 成员：继续使用 `IosSelect`。
5. 时间：保留原生 `datetime-local` 选择能力，但视觉样式对齐 `IosSelect`。
6. 备注：由大文本框改为单行输入。
7. 提交：保留在表单底部，不固定到导航上方。

## 常用分类排序

`/add` 页面服务端加载分类时，同时查询登录成员最近 30 个上海自然日内的有效交易，并按支出/收入分别计算分类优先级。

查询约束：

- 使用当前 session 派生的 `householdId` 和 `memberId`。
- `actorMemberId` 固定为登录成员。
- 有效交易必须包含 `deletedAt: null`。
- `occurredAt` 范围为最近 30 个 `Asia/Shanghai` 自然日起始时间到当前时间。

排序规则：

1. 当前类型下，使用次数高的分类排前。
2. 次数相同时，最近一次使用时间新的排前。
3. 仍相同时，使用现有分类默认顺序。
4. 没有历史记录时，完全使用现有分类默认顺序。
5. 默认选中当前类型下最高频分类；没有高频数据时选默认排序第一项。

## 分类交互

折叠态：

- 默认显示 5 个分类 chip。
- 显示一个“更多”按钮。
- 如果当前选中分类不在前 5 个里，折叠态用当前选中分类替换第 5 个常用项。
- 折叠态始终能看到当前选中项。

展开态：

- 点“更多”后只展开当前交易类型的全部分类。
- “更多”原位置变为“收起”。
- 切换支出/收入后恢复折叠态。
- 切换类型时默认选中该类型下最高频分类；没有高频数据时选默认排序第一项。

视觉方向：

- 分类 chip 比当前大按钮更低、更紧凑。
- 选中态继续使用现有 `--ios-blue` 和 `--ios-blue-soft`，但减少阴影存在感。
- 分类 label、chip 区、成员控件和时间控件使用统一的表单节奏。

## 文案

需要同步 `src/lib/i18n.ts` 的中英文文案：

- `更多` / `More`
- `收起` / `Collapse`

如实现中出现额外可见文案，必须同步加入中文和英文。

## 验证计划

实现阶段按改动范围验证：

1. 分类折叠、展开、选中项挤入、默认选中逻辑：`npm run test:unit`。
2. `/add` 页面创建交易仍能保存：`npm run test:integration`。
3. 创建支出主流程不退化：`npm run test:e2e`。
4. 通用代码质量：`npm run lint`。
5. 移动端 UI smoke：检查分类区高度、成员/时间控件一致性、标题和控件间距。

代码变更提交前按仓库规则运行完整验证，并执行 `skills/billboard-security-review/SKILL.md` 安全审查。

## 安全与隐私

- 新查询只基于当前 session 的 `householdId` 和登录成员 `memberId`。
- 常用分类统计只返回分类排序信息，不新增明细交易、备注、导入来源或 `sourceFingerprint` 暴露。
- 不把家庭财务明细写入 URL、客户端日志或持久化客户端存储。
- 不修改认证、授权、导入、部署或凭据相关逻辑。
