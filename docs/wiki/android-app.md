> 摘要：Android 客户端通过受限 WebView 访问现有 HTTPS 家庭账本，正式签名 APK 在公开帮助页分发，支持同源认证的应用内更新与红点提示。

# Android 家庭客户端

Android 客户端服务家庭自用，以 OPPO Find X10 Pro Max／ColorOS 17 为主要适配目标。应用使用系统 WebView 加载现有 HTTPS 根路径站点，保留现有账号密码、服务端 AppSession、家庭归属、账单导入及语音记账规则。账本和业务处理仍由现有服务端负责；客户端联网使用，网络不可用时提示用户重试。

WebView 使用应用独立的登录状态。原生层负责窗口与键盘适配、返回导航、文件选择、麦克风授权和 APK 更新。更新桥只允许指定 HTTPS origin 的主框架发送固定状态、检查、下载、安装和取消命令，不接受 URL、文件路径或任意原生调用。应用内导航及录音授权限制在配置的 HTTPS origin；外部网页交给浏览器，TLS 错误不能跳过。文件导入使用系统选择器，录音按需申请麦克风权限。

正式 APK 通过现有 HTTPS 服务公开分发，后续 APK 保持相同包名与签名并递增版本以支持覆盖安装。公开安装包包含连接服务所需的地址；真实入口仍不得写入 Git 跟踪文件或历史。签名私钥、密码及本地构建配置保存在 Git 之外，未发布产物不公开，也不新增第三方托管。

网页功能随服务端部署更新；原生容器、权限行为或内置服务地址变化时重新构建并分发 APK。签名材料需要独立备份，不能用临时 debug 签名替代正式签名。模拟器和真实 OPPO 设备的验证结果分别记录，浏览器自动化测试不代表真机 APK 已验证。

## 教程与首次安装

`/help` 提供无需登录的中英文完整使用教程和 Android、Windows 下载入口，可从登录页、手机“更多”和桌面侧栏进入。`GET /api/downloads` 提供各平台最新发布版本和大小等下载信息，`GET /api/downloads/android` 提供当前正式 APK；公开信息来自 APK 发布清单，不使用网页版本代替安装包版本。未发布或不可用时明确显示状态，不影响教程或另一平台下载。

首次安装及尚无更新桥的旧版升级使用手机浏览器打开帮助页下载；原生壳限制普通安装包下载，已安装且带更新器的客户端使用“应用更新”。公开下载不授予账号或家庭权限，账务功能继续要求有效登录及家庭身份。新增或更新网页帮助内容不需要重建 APK。

## 家庭密钥

家庭加密遵循[家庭账务加密约定](household-encryption.md)。支持家庭密钥桥的 APK 使用 Android Keystore 保护应用私有码包，只允许已配置 HTTPS origin 的主框架按原账号／家庭／成员身份保存、取用和清理；不增加任意路径、URL 或原生调用。正常启动保留 IndexedDB 中受保护的草稿和待确认 UUID；显式退出／身份结束时定向清理，HTTP 缓存与网络安全清理继续保留。

网页仅在本次请求正文提交所需材料。明确退出、账号或成员身份结束清除可用现场，同身份会话到期可保留受保护包用于重登录；原生层不决定服务端授权。二维码摄像头按需、同源审批，拒绝时仍可粘贴；普通浏览器和尚未支持密钥桥的旧 APK 分别使用对应本机能力，不宣称已通过新桥真机验证。

## 应用内更新

登录后启动及回到前台时限频检查已发布 APK，手动检查可以立即重试。移动端“更多”按钮和“应用更新”菜单项显示红点；横屏宽布局在侧栏保留更新入口。更新比较原生已安装 `versionCode` 与 APK 发布清单，不比较网页 `package.json`；仅发布网页不会触发 APK 红点。查看更新说明、下载或取消安装均不清除红点，重新读取到已安装版本不低于发布版本后才消失。普通浏览器及尚未带更新桥的旧 APK 不显示该原生入口。

面板显示当前 APK、新版本、下载大小、中英文说明和进度。“下载并安装”要求先确认已保存未提交内容，安装前再次核对没有录音、待确认记账、编辑保存或导入处理。下载期间关闭面板、切换页面或进入后台会取消自动安装意图，下载完成后由用户再次点击安装。未知来源权限返回同样需要再次点击；系统最终要求用户确认，拒绝或失败后旧版本仍可使用。安装会关闭应用，本机未提交草稿不能保证在重启后恢复。

应用内更新的 `GET /api/android/update` 清单和 `GET /api/android/update/<sha256>` APK 仍通过现有 HTTPS 服务、有效 `AppSession` 提供。原生只向固定同源路径传递 WebView Cookie，禁止下载重定向；Cookie 不交给 JavaScript。APK 写入应用私有空间，校验大小、SHA-256、包名、递增版本、最低系统要求及当前受信签名，然后交给系统安装器。服务容器只读挂载本机发布目录，不接触签名私钥。发布先写入不可变摘要文件，再原子切换 `latest.json`；应用内版本下载不依赖变化中的 latest。

`1.46.1` 及更早客户端需要先手动覆盖安装一次带更新器的 APK，之后才能在应用内升级。覆盖安装始终复用原包名和正式签名，不能以卸载重装绕过签名问题。

可重复构建、签名保管、版本码与手机安装流程见 [Android APK 构建与家庭分发](../runbooks/android-apk.md)。
