> 摘要：文字与长按语音共用自然语言记账服务；录音结束立即进入应用会话后台队列，豆包转写后由 Agent 解析收支，成功轻提示，已提交请求按 UUID 安全恢复。

# 自然语言收支记账

“记一笔”的自然语言模式提供文本框和“导入”按钮，支持一次输入至多 2,000 个字符、合计 20 笔人民币收入、支出或混合交易。任意交易信息缺失、含糊或不支持时整段不入账；成功后显示总笔数及实际包含方向的收入／支出合计，纠错使用现有记录编辑／删除入口。

未提日期和时间时使用首次受理的上海时间，相对日期始终基于同一参照；只给日期使用当日 `00:00`。支出归实际付款成员，收入归实际获得收入的成员，未明确时均归当前登录成员。外部资金提供人不是收入归属，礼物受益人不是支出付款人，创建人始终为提交者。这是 AI 辅助手工输入，交易来源字段保持空值，文件账单继续走原有导入流程。

工资、奖金、报销、独立退款、投资及其他明确收入使用现有启用收入分类；独立收到的退款及所有报销新增正金额收入，不自动查找或抵扣历史支出，不改变文件账单退款处理。

同一段输入明确描述同次消费的付款及退款、找零或未用预付款退回时，以整数分相减，只新增一笔正净额支出，沿用原消费的付款成员、分类和日期，证据范围覆盖付款及退回。备注只描述原消费事项，不保留付款退款经过、原金额、退回金额、净额或计算过程。例如“电动车充电花了一块钱，退回了 2 毛 8”记一笔 `amountFen: 72`、备注为“电动车充电”的支出。无关消费、不同成员、独立退款及报销不相互抵扣；关联或金额不明确、净额为零或负数时整段纠错，不猜测或静默跳过。

自然语言记账的备注使用输入语言简述交易事项，保留商品、商户、受益对象或收入来源等有意义的细节，不照抄整段输入，也不重复结构化字段已经表达的金额、日期和付款成员。

本人账户互转、家庭成员之间的纯转账、外币及记录修改／删除仍不支持；明确收入的“转账到账”描述可以记录，不能只按付款渠道关键词拒绝。

## 长按语音与两阶段请求

短按“记一笔”仍导航至记账页；长按在当前页打开录音浮层，松开自动识别并记账，上滑松开取消。单次最多 60 秒，到限停止采集但等松开才提交，仍可取消。浮层也提供键盘可操作的开始、停止提交和取消。尚未发送时，等待麦克风授权期间松开、失焦、页面隐藏或站内路由／筛选变化均结束本次录音，迟到授权不能重新开启录音。松开发送后立即释放麦克风与输入占用、收起浮层，可以继续录音或其他记账操作。

浏览器生成 16 kHz、单声道、16 位 PCM WAV，发送至同源 `POST /api/voice/transcribe`。服务端在 2 MiB 请求上限内校验真实音频结构、长度和时长，校验 AppSession、同源及成员调用额度后保存临时 WAV，以短期能力链接请求豆包录音文件识别 2.0 的 `submit/query`。提交与轮询共用 30 秒总预算，取得有效文字后、返回前再次检查会话；不承诺秒级完成。供应商仍处理中、超时、取消或刷新均不会继续后台记账。转写接口不调用 Agent、不写账、不生成自然语言 UUID。

应用级 `VoiceAccountingQueue` 持有每次已发送录音的独立任务，串行完成转写与账务提交，兼容 ASR 每成员单任务和 Agent 全局单任务约束。队列跨站内路由和筛选变化保留，失焦或页面隐藏不会取消；浏览器挂起可能暂停后续客户端调度，恢复后继续。文字与语音的模型提交共用串行调度器；语音使用同源 `POST /api/voice/entry`，不占用文字、手工提交的 Next.js Server Action 队列。新 HTTP 入口复用原服务的 AppSession 校验、推理后复核、家庭／成员归属、审计与缓存失效。

只有即将发送账务请求时才把任务 UUID 写入成员作用域的 sessionStorage 并读回校验；存储不可用时保留文字并显示处理入口，不发出账务请求。正在录音的浮层、文字表单、每个语音任务及纠错文字各自拥有状态，旧任务完成不会关闭新录音或清空其他草稿。成功在前台显示自动消失的轻提示，页面隐藏或录音浮层打开时暂缓展示；失败或未知结果只显示处理入口，不自动打开浮层。未确认结果自动查询原 UUID，确认前后续语音继续排队；明确失败修正后使用新 UUID。

成功刷新当前页面数据，保留筛选，只清理已知发起入口的本次快照，保留其他未提交草稿。缺少金额或成员含糊时整批失败，浮层保留转写文字供修改后主动新建请求。转写可能把金额识别成另一合法金额，结果仍通过记录页的现有编辑／删除入口纠正。

任务结果中的“查看记录”固定原任务账本，使用全部日期和成员，避免当前页面的其他账本、日期或成员筛选遮住结果；目标归档后仍可查看原历史。语音取消须等待音频创建及清理工作真正结束，再释放数据库处理占用，不以取消等待代替实际停止。

## AI 与数据边界

AI 处理和语音识别由本人分别选择并按账号跨设备保存；首次使用前说明当前供应商及发送内容，未选择的能力不接新任务。文字记账与导入智能推荐需要 AI，语音记账需要两项；账号页可关闭，手工路径始终可用。

关闭后仅拒绝新任务，服务端已受理的一次任务在原期限内可继续完成。语音上传先有界占用资源，完整 WAV 校验通过后才原子复查本人选择、身份及目标并受理，绑定本次音频摘要；提前发送请求头或浏览器排队均不算受理。该次受理覆盖原录音转写、原输出解析及入账。跨阶段延续须绑定原输入、身份、账本、任务和有限期限，不能换正文复用。能力开关不改变业务授权，撤销会话、身份结束、家庭关闭或目标归档仍阻止不合法的后续写入；原 UUID 终态可查询但不重新外发。关闭不撤回已发给供应商的数据。

复用独立 `import-agent`，通过自然语言协议调用 WheelMaker Hub（Codex）的 Responses API。两类任务共用内部认证、单任务互斥、服务端模型配置和清理；统一使用 `WHEELMAKER_BASE_URL`、`WHEELMAKER_API_KEY`，模型 `IMPORT_AGENT_MODEL` 默认 `gpt-6-luna`，推理强度 `IMPORT_AGENT_REASONING_EFFORT` 默认 `high`。每次任务新建独立临时请求，设置 `ephemeral: true`、`store: false`，不复用 Hub Session ID，不自动重试或回退。BillBoard 不再运行本地 ACP／Codex CLI 或管理其登录；分类建议仍遵循它原有的数据范围。

Agent 总预算保持 45 秒，应用等待保持 55 秒，请求租约保持 75 秒；服务失败或预算用尽返回固定错误，保留原有 UUID 确认与恢复机制。Responses 完成状态、助手文本、JSON 大小和业务结果由应用校验；Hub 的输出 token 参数不保证限制实际输出，迟到或超限结果不能用于入账。取消沿用 [导入分类 Agent](import-category-agent.md) 的 HTTP 服务边界：BillBoard 等待本地请求与清理结束，Hub 收到取消后负责停止或隔离运行器；不宣称两侧资源释放具有跨网络的严格先后保证。

自然语言任务通过 `natural-language-entry.v2` 发送本次输入、上海时间参照、带类型的匿名收支分类及当前家庭成员显示名称，不附加历史账本、原始文件、真实数据库 ID、账号或会话凭据。WheelMaker API 地址和 Key 只在 Agent 私有环境中使用，不传给 web、OPS、浏览器或构建参数；内部 `IMPORT_AGENT_TOKEN` 不传给 Hub。每笔结果显式包含交易类型，所选分类必须同类型；金额始终为正整数分，方向由类型表达。输入与候选名称都是不可信数据，Agent 不访问数据库，也不执行模型工具调用。应用在调用前和落库前检查 AppSession、成员、分类、整数分金额及日期。

豆包语音接收本次音频的短期能力链接、随机请求标识及必要识别配置，不接收账本分类、成员候选或账号。`VOLCENGINE_ASR_API_KEY` 来自豆包语音控制台，所属项目须开通录音文件识别 2.0，固定资源为 `volc.seedasr.auc`。`VOICE_AUDIO_PUBLIC_ORIGIN` 是供应商可访问的 HTTPS 根 origin，不含账号、路径、查询参数或 fragment，应用仍从根路径部署。两项私有配置仅注入 web，不注入 Agent、OPS、浏览器或构建参数。

WAV 写入 `os.tmpdir()/billboard-voice` 下的进程私有目录；Linux 生产目录权限为 `0700`、文件为 `0600`，Windows 开发继承当前用户临时目录 ACL。最多 16 个租约、活动文件总量 32 MiB、TTL 45 秒。完成、取消和过期都会删除租约与文件，启动时及短期延时清理过期遗留文件；生产 Compose 提供 40 MiB、`nosuid,nodev,noexec` 的 tmpfs，容量包含崩溃遗留文件，不进入持久卷或备份。供应商通过随机 256 位 token 的 `GET/HEAD /api/voice/audio?token=...` 取音频，不要求 cookie；能力链接和本地文件路径全程不暴露给前端，也不交给记账 Agent。它是短期持有即授权的下载能力，不能写入日志或分享。应用不持久保存转写任务；本地删除不代表供应商侧删除或留存承诺。

当前公网链路为 `HTTPS 域名转发服务 -> frps remote 3000 -> frpc -> 本地 127.0.0.1:3000 -> web:3000`，应用使用根路径，远端未部署 nginx。音频下载端点提供 `no-store`、`nosniff`、`no-referrer`；实际转发服务及日志采集仍须核验并关闭音频路径（含尾斜杠）的完整 URL、查询参数和音频记录。短 TTL、本地删除和 `no-store` 不能关闭外部日志。仓库 nginx 配置仅是可选自管代理示例，其禁日志、尾斜杠拒绝和安全头设置不代表真实服务已部署或验证。

Next.js 开发配置忽略音频 URL 的请求日志，并关闭 Server Function 参数日志；生产默认不记录 incoming requests。应用错误使用固定信息，音频、能力 token、原文和供应商原始响应不进入日志。远端 `3000` 访问限制应按转发服务实际来源核验并最小化，本地应用端口仍只发布 loopback。

公网录音需要 HTTPS、安全上下文及浏览器授权；应用通过 `Permissions-Policy` 为同源页面设置 `camera=(self)`、`microphone=(self)`，禁用 geolocation、payment、usb，前置转发服务不得覆盖为麦克风禁用。应用全站提供 CSP、禁止嵌入的 `X-Frame-Options: DENY` 及仅约束当前 HTTPS 主机的 HSTS；页面脚本使用每次响应的随机 nonce，连接保持同源，原 AudioWorklet 仍可加载。实际入口与浏览器兼容验证按[网络检查清单](../runbooks/home-network-checklist.md#ingress-and-routing)执行，不能以可选 nginx 示例代替。转写的 2 MiB 限制由端点独立执行，不能用它收紧原有账单导入上传范围。

## 一次提交与恢复

服务端按当前家庭、提交者和请求 UUID 管理提交。AI 在数据库事务外运行，每次受理只发起一次模型请求；只有最终经校验的结果进入一次账务提交，全部交易及成功结果在同一个短事务中写入。重试重放原结果，不重开成功或明确失败的终态。过期尝试只有仍持原快照且未结束操作时可以恢复，迟到尝试不能写账。

成功快照保存总笔数及两类各自笔数／整数分合计，不从后来被编辑或删除的交易重算。旧未版本化快照来自纯支出功能，以原笔数／金额等值展示为支出；旧收入或退款拒绝结果继续保持终态，使用新功能须主动提交新 UUID。新页面声明结果能力；旧页面无法可靠展示新摘要时保留待确认 UUID，刷新后查询，不能误报为支出合计或确定未入账。

刷新仅保留当前标签页的请求标识并查询状态。查无记录时先原子建立关闭标记，与首次受理竞争；关闭先完成则旧 UUID 永不执行，首次受理先完成则返回已有状态。不能仅凭一次查无记录就宣告未入账。

文字及旧客户端待确认 UUID 沿用 `billboard:natural-language-pending:v1:<memberId>`，刷新后仍由原全局浮层恢复，不猜测旧来源、不导航、不清空文字草稿。新语音任务在 `billboard:voice-pending:v1:<memberId>` 只保存已提交账务的 UUID 数组，刷新后通过 `GET /api/voice/entry` 逐个查询；存储中没有音频、正文、金额或财务明细。网络错误只能确认原 UUID，不能重新识别或换 UUID 自动提交。转写及排队阶段禁止查询自然语言 UUID，因为未知 UUID 的查询会永久关闭该请求。原文字入口的存储不可用降级行为保持不变。

后台处理限定于当前应用页面会话，不是持久化 worker。刷新、关闭页面会丢失尚未提交的音频和转写任务；已经发出的账务仍受服务端幂等保护，刷新查询不会重复入账。退出应用会话时终止未提交队列和转写，迟到响应不能再提交账务；已提交请求标识保留供安全确认。

原文只保留在当前页面和本次处理内存，成功后清除，不承诺刷新恢复。需要修改的终态失败只保存经校验的问题类型和规范化文本偏移，有原快照时可以重放定位；原文丢失时仅显示固定提示。原文、模型输出及财务明细不进入 URL、日志、诊断或浏览器持久化副本。
