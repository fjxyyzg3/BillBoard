# 账单分析退出应用后继续生成

## 目标

手机锁屏、关闭应用或网络中断后，已经提交给服务端的月度、年度账单分析继续执行。用户下次打开应用，可以在报告列表查看生成进度、最终报告或失败原因，无需保持页面和长连接。

当前生成接口把客户端连接取消信号传递给整个分析任务，重开后的任务恢复又依赖 `sessionStorage` 中的 UUID。本设计将执行生命周期交给服务端，客户端只提交任务、查询状态和读取报告。

## 决策基线

### 需求决策

- 本次覆盖锁屏、切后台、关闭浏览器或应用、刷新及客户端断网。完整请求到达并由服务端接管后，这些动作不再取消任务；请求未完整送达或未获准提交时，不承诺生成。
- 报告列表统一展示生成中、已完成、失败和已取消，并展示真实阶段及已完成批次。重开后从服务端发现任务，不要求手机仍保存 UUID。暂时无法查询时显示状态未知，不把它当成任务失败。
- 延续家庭共享和每个“月或年、所选期间、账本范围、归属成员范围”只保留最新成功报告的规则。列表在该范围下展示最近一次生成尝试的状态；重新生成期间及失败、取消后仍能打开原成功报告，不增加历史正文版本列表。
- 任务状态和报告由同家庭当前有效成员共享查看。取消仍限原发起成员的原有效登录会话；其他成员或同账号的新登录会话只读，不接管原任务。
- 主动取消、主动退出登录、原会话撤销或过期、原账号或成员身份失效、家庭关闭、加密模式变化及超时，继续按原规则停止任务。关闭本人 AI 选择对已正式受理的固定输入仍沿用原同意规则，不授权新增输入或新任务。
- 服务器进程退出、升级重启或断电后不自动续跑。确认原执行者已停止后，将未完成任务收敛为中断，允许用户手动重新生成；保留已有成功报告。
- 保留 Astra、完整分批分析、原调用额度及耗时上限。生成入口、原数据披露、月年与筛选范围、报告语言和中文／英文切换不变；本次不增加系统推送、邮件通知或自动定时生成。

### 技术决策

- 在现有自托管 `web` 进程中运行有界后台任务，采用短请求提交和短请求查询。任务由服务端运行器持有，脱离生成 HTTP 响应和浏览器观察连接；不新增独立 worker 容器、外部队列或跨重启的执行材料。
- 沿用 `POST /api/reports/analyze` 的同源正文操作、身份校验、16 KiB 输入上限、携钥 POST、`no-store` 和 `no-referrer`。生成操作返回最小 JSON 提交回执，进度改由状态查询读取，不再依赖 NDJSON 长流。
- 复用 `BillAnalysisReport` 和 `BillAnalysisRequest`。报告槽表示固定期间与范围，任务回执表示一次尝试。新任务在登记时关联同家庭报告槽；最小阶段和批次进度扩展到请求已有的受保护 `definition`，不保存可重新执行的明细、模型输入或中间发现。
- 运行器独立拥有原身份、任务控制器、原截止时间、执行占用、固定快照及限时加密上下文。解密材料只供该任务在有界内存内使用，不能引用已随提交回调结束而释放的请求上下文，也不能与其他请求共享可清除的 key ring 对象；材料不能写入数据库、日志或文件。
- 保留原 AppSession、成员、家庭、UUID、模式代次、输入摘要和资源租约的绑定。执行中的授权、每次模型调用扣额和最终写入仍以原身份核验；家庭只读查询使用当前有效会话授权，不替换执行身份。
- 沿用原分析档位：全流程最多 8 分钟，租约 9 分钟且不续租，原全局／家庭／成员并发与窗口、单次调用时限、批次数和字节上限均不变。总截止从首次生成请求开始计算，返回回执、重开和状态查询均不重设截止。首次资源繁忙拒绝提交，不新增等待队列；后续本地额度等待仍计入原预算，不重试已尝试的供应商调用。
- 使用当前 Next.js 支持的 `after` 跟踪后台完成 Promise，并由运行器保留任务引用和统一清理责任。注册、异常处理和清理不依赖客户端连接成功结束；不能仅调用未跟踪的 `void generate()`。

## 设计视图

### 功能设计

用户在现有月／年入口发起生成，收到“任务已提交”后可以离开应用。准备阶段显示正在获取和检查账目，正式受理后显示分批分析、等待额度、汇总或保存。任务范围和语言在提交时固定，后续修改界面筛选或重新打开页面均不改变它们。

报告列表保留现有入口和分页回看，以期间和筛选范围为一项。每项包含最近一次生成状态及该范围已有的最新成功报告。新的生成尚未完成时，状态与旧报告同时展示；新生成成功后原子替换旧正文。没有旧报告的失败项只显示状态和受控原因，不伪装成已经生成的报告。

应用启动、回到前台或打开报告列表时，按当前家庭权限获取服务端状态。前台有活动任务时进行有界间隔查询；进入后台或关闭应用只停止查询。查询失败保留未知状态并允许再次查询，不能自动发起生成、换 UUID 或重复扣额。原发起会话可以从重新发现的任务继续执行取消操作，其他会话不展示取消入口。

用户主动取消后，界面先显示正在停止。服务端确认本地执行和供应商 HTTP 请求清理结束后，显示已取消并释放资源。若报告先保存成功，则取消返回已完成。服务器中断后，状态在完成执行者停止核验及回收后变为中断；核验前保持停止处理中或状态未知，不能谎称资源已经释放。

### 技术设计

#### 整体方案

生成接口负责完整读取和验证请求、解析原身份与解锁材料，并把任务交给运行器。运行器登记请求和原 AI 执行占用，接管独立的任务上下文，再向接口提供提交回执；接口无需等待 Astra 返回。`after` 观察同一完成 Promise，运行器负责捕获所有终态与清理异常。HTTP 断开、响应写入失败和前端卸载不再触发任务控制器。

后台仍调用现有快照、分批、Agent、证据校验和报告保存流水线。取数、预检和固定输入正式受理的界限保持：进入 `RUNNING` 前完成一致快照、总量检查、分批计划及本人 AI 选择复核，首次供应商扣额和调用晚于正式受理。准备阶段也由运行器负责清理，不因客户端离开而丢失所有者。

状态查询和报告列表读取数据库中的回执及报告。客户端不需要连接任务所在进程，查询也不创建执行者。成功状态以数据库保存事务为准；内存中的进度、Promise 完成或网络回执都不能代替已提交的报告。

#### 关键结构与状态

| 对象 | 职责与边界 |
| --- | --- |
| 任务运行器 | 在现有 owner 登记上持有任务 Promise、取消控制器和限时上下文；一个 UUID 只能产生一个执行者。仅任务结束后清理内存引用及解锁材料。 |
| `BillAnalysisRequest` | 保留原幂等、授权和 owner 字段；受保护定义增加可选阶段、已完成批次及总批次。进度只由匹配的 owner／租约推进，不得覆盖终态。 |
| `BillAnalysisReport` | 在新任务获准登记时建立或复用同范围槽，并通过同家庭关联保留生成尝试；正文和成功代次仍只在最终保存时更新。 |
| 家庭只读状态 DTO | 仅包含范围及获准标签、任务状态、真实进度、受控错误、时间和可查看的成功报告。服务端派生 `canCancel`；不暴露原 AppSession、owner、租约、模式凭据、原始输入或内部交易映射。原 UUID 仅向有权操作原任务的会话提供。 |

数据库状态继续使用 `PREPARING`、`RUNNING`、`STOPPING`、`SUCCEEDED`、`FAILED`，以受控错误区分取消、中断和其他失败。查询不得把超时但仍未停止的执行直接当作已释放的失败任务。

报告列表按报告槽的 `updatedAt`、`id` 倒序分页，每页最多 20 项，并以这两个字段组成游标。新任务登记和终态更新槽的活动时间，单纯进度更新只改请求回执。每个槽只加载最近尝试及必要的活动状态，不扫描或解密该家庭全部历史回执。回到前台刷新首页，加载更多时按稳定槽 ID 合并去重；排序期间出现更新不触发生成。新增查询所需的普通索引按数据库迁移维护，不建立可推测财务范围的明文 hash 索引。

现有成功报告和历史 UUID 回执继续可读，不重写原终态或输入摘要。旧请求没有新增进度字段时显示通用状态；原先没有报告关联的历史失败回执不做批量解密回填。无合法范围的 `NOT_ACCEPTED` 关闭标记不是报告列表项。加密转换、换钥和财务恢复须识别扩展后的受保护定义，继续拒绝恢复可执行任务，不复制 AppSession 或内存任务上下文。

#### 实现流程

1. **校验和交接。** 接口校验原会话、同源请求、范围及解锁材料。先建立受 `after` 跟踪的运行／清理所有权，再进入请求锁、家庭锁及原资源事务完成幂等登记；只有数据库登记与运行器接管均成功，才返回任务已提交。同 UUID 重复请求只读取原结果，不激活第二个执行者。交接完成后的连接断开不再取消。`after` 注册失败时不得登记任务或领取资源；登记确定未成功时清理临时上下文。登记已提交但无法激活执行时，仍由原运行器负责停止本地工作、在原锁下核对匹配的 owner／lease 并收敛失败和回收。提交结果未知时不得调用模型或当作未受理重发，由同一运行器保留核对与清理责任；核对前保留安全占用，核对后按实际登记结果收敛，不能留下只有进程仍活却没有执行／清理责任人的任务。
2. **准备及正式受理。** 在原总预算内完成一致快照和全部分批预检，复核同意后固定输入并进入 `RUNNING`。无数据、超限或授权变化不调用模型。断连后不得重新取数替换已固定输入。
3. **分析和进度。** 按原流水线逐批分析并汇总，在阶段切换、批次完成及额度等待时持久化最小进度。进度更新校验原 owner、租约、身份与任务状态；等待和推理期间不持有长事务，也不按查询次数扣额。
4. **重开和未知回执。** 家庭只读查询从当前会话发现现有任务。原会话仍可用已保留的 UUID 查询原回执；不存在回执时沿用与首次登记相同请求锁下的 `NOT_ACCEPTED` 关闭机制。暂时无法确认提交结果时保留未知，不自动重发。只读家庭发现接口不写该关闭标记，不替其他会话接管任务。
5. **取消及保存。** 原发起会话通过显式取消请求持久标记 `STOPPING`，执行者用原轮询检查及本地控制器停止。取消和最终保存沿用相同锁序；最终事务复核原身份、范围、模式、租约与活动代次，成功后才返回可读报告。
6. **结束及中断回收。** 正常结束或受控失败后，等待本地模型 HTTP 请求及清理结束，收敛回执并清除活动指针，释放原执行占用、上下文和内存引用。数据库清理失败保留安全占用及本地 `settled` 回收责任，后续在原进程内也能重试清理；待回收期间只保留必要的所有者信息，不延长原始输入和解密材料的存活。进程硬停止后，复用已停止 owner 证明及 Windows 退休容器监督收敛为中断，不凭 TTL 释放活执行者，不重新获取租约续跑，也不增加远端 Hub 停止确认接口。

### 预估改动面

- `src/app/api/reports/analyze/route.ts`：短请求提交、家庭只读任务发现、查询和取消的权限分离；移除生成对响应流取消的依赖。
- `src/lib/reports/`：运行器、服务拆分、请求进度、报告槽关联和分页状态 DTO；保留现有分析计算与 Agent 协议。
- `src/lib/encryption/` 及恢复校验：任务独占的限时解锁上下文、旧新受保护定义兼容；不放宽其他请求的密钥生命周期。
- `src/lib/resources/`、`prisma/` 与 `ops/reports/`：复用原资源规则及停止证明，仅调整任务交接、必要索引和中断状态；不新增长驻密钥或可执行输入表。
- `src/components/bill-analysis-*.tsx`、客户端控制器和 `src/lib/i18n.ts`：统一状态列表、启动及前台查询、取消权限和中英文文案。
- `tests/unit/`、`tests/integration/`、`tests/e2e/`：交接、断连、重开、状态权限、取消／保存竞态、加密上下文、额度及硬停止回归。原“断连即取消”断言调整为本次行为，显式取消和授权失效测试继续保留。
- 更新 [账单分析 wiki](../wiki/ai-bill-analysis.md)、相关运行维护说明及接口事实；[上一版 spec](2026-11-02-ai-bill-analysis.md) 作为已交付历史基线，本 spec 批准后覆盖其客户端断连取消、仅应用页面会话继续及列表只含成功报告的约定，其余约束继续适用。

## 验收

- 生成已提交后手机锁屏、刷新、断网或关闭整个客户端 → 服务端继续原任务，所有观察连接消失期间仍完成分批、汇总和保存；真实自托管 Next 运行形态下，以隔离虚构家庭和受控 Agent 延迟验证，不以保留浏览器页面的测试代替。
- 关闭原浏览器上下文并清除其中的 `sessionStorage`，用仍有效的原登录状态重新打开 → 报告列表发现原范围任务及实际进度，完成后能读取报告，供应商调用总数不因重开增加；浏览器端到端测试。
- 提交响应丢失或重复提交原 UUID → 查询得到原回执或按原锁收敛为未受理，最多一个执行者和一套原调用计数；接口集成及竞态测试。其他家庭或原身份失效后重建的身份不能查询旧家庭任务。
- `after` 注册异常、登记已提交后接管异常、登记提交结果未知及回收数据库暂时不可用 → 原运行器承担全部部分失败的核对与清理；无模型重复调用、提前释放或无人负责的 `PREPARING`，数据库恢复后不重启进程也能收敛；交接故障注入及租约／内存上下文检查。
- 家庭其他有效成员或同账号的新会话打开列表 → 能只读查看获准状态及成功报告，不能取消原会话任务；伪造取消和跨家庭 ID 均被服务端拒绝，DTO 不含执行凭据；真实数据库授权测试。
- 同范围重新生成、失败或取消 → 列表状态正确，旧成功报告仍能打开；只有新成功事务替换正文，不产生历史正文版本列表；存储集成及浏览器测试。
- 超过 20 个报告槽、相同活动时间及翻页期间任务状态变化 → 游标有稳定次序，前台刷新及加载更多按槽去重；最近失败和旧成功正文同时可见，查询不会解密扫描全部历史回执；数据库查询及浏览器分页测试。
- 前台查询、回前台刷新及查询失败 → 展示真实阶段、批次或状态未知，停止观察不停止任务；不生成假进度、不写入重复任务、不重新扣额；控制器与接口测试。
- 主动取消与最终保存竞态 → 取消先提交则禁止保存，清理完成前保持停止中；保存先完成则返回成功；服务集成及本地 HTTP 供应商取消测试。
- 主动退出登录、OPS 撤销、成员失效、家庭关闭或加密模式变化 → 后台任务不能继续调用或提交越权结果，旧报告保留，本地工作结束后释放占用；沿用原锁序的集成测试。
- 加密家庭在提交请求返回后继续分析 → 独立任务上下文仍可完成原输入处理和加密保存；同一时间其他请求结束不清空它的材料，终态后上下文不可复用且无明细、密钥或中间结果落盘；加密集成、释放测试及日志／文件检查。
- 服务器任务进程被硬停止或正式服务重启 → 确认原 owner 已停止后显示中断并回收，不自动调用模型、续租或重建执行输入；活 owner、未知实例和仅 TTL 到期不能提前回收；独立进程与监督脚本验证。
- 总时限、原 AI 并发与额度、无数据及超限 → 继续受原预算约束；页面退出及查询不会释放占用或增加额度，预检失败不调用模型，失败保留旧报告；资源、服务和真实数据库测试。
- 旧报告、无新增进度的旧回执、转换／换钥及 v1／v2 财务恢复 → 按各自原授权和校验规则读取，不恢复 AppSession 或在途执行；兼容性集成测试。
- 中文和英文移动界面 → 列表、状态、原因及取消权限一致，关闭应用后重开可回看；浏览器端到端及移动视口检查。
- 实施验收 → `npm run lint`、`npm run test:unit`、`npm run test:integration`、`npm run test:e2e` 及 BillBoard 安全审查按仓库规则通过，再执行适用 Git 和发布收尾；本草案自审不冒充实现或运行验证。
