# AI 对账独立页面与人工核对

## 目标

把扫描、后台任务、历史报告和结果操作集中到独立对账页面，从记录页进入，减轻首页内容负担。为仅提供关联线索的结果增加人工核对入口，让用户确认具体重复记录、选择保留项并预览应用，解决当前提示看似可选、实际点击无响应的问题。

现有行为以[AI 对账说明](../wiki/ai-bill-analysis.md)和[原 AI 对账规格](2026-11-05-ai-bill-reconciliation.md)为基线；本规格定义入口迁移和人工等额去重，未扩大的规则继续沿用。

## 决策基线

### 需求决策

1. **入口与范围。** 在记录页提供“AI 对账”入口，目标为 `/records/reconcile`；首页移除完整对账模块，手机底部和桌面主导航仍保留原三项。独立页面继续按月／年、账本、归属成员扫描，默认带入记录页可用的月／年和归属范围；其他时间模式进入时明确显示本月范围，由用户确认后发起。记录页的搜索、分类、收支类型或金额筛选不暗中成为扫描条件。
2. **原有能力。** 保留后台扫描、家庭共享任务及报告、取消和原 UUID 结果核验。全局轻量任务／结果提示继续保留，查看报告统一进入独立页。既有可应用建议继续勾选、预览和一键应用；原 AI 可信度、自动保留项与退款／报销证据规则不变。
3. **人工核对。** 对当前对账报告的关联提示（`kind: notice`）提供明确的“人工核对”操作，替换该提示上无法操作的复选框。每个人工组只能从同一提示的原记录中选择，至少两笔，必须同家庭、同账本、同原 `actorMemberId`、同收支方向、同整数分金额。用户明确确认这些记录重复，并指定其中一笔保留；其余所选记录软删除。未选中的提示记录不受影响。
4. **人工判断的边界。** 人工确认可以补足同笔事项关联或时间精度不足；它不是 AI 高可信判断，不默认勾选整条提示，也不解释 AI 正文中的引用串来决定分组。人工组仅做等额去重，不修改金额，不创建记录，不执行退款／报销抵扣。跨账本／成员、异向、异额、归档或已失效记录仍不可提交。
5. **保留原记录。** 用户指定的保留项优先于现有自动排序，其 ID、金额、日期、分类、归属、创建者、备注、来源、指纹和原 UUID 不变；不把其他记录的字段拼接到保留项，不重写已完成导入或自然语言结果。软删除仍参与同源导入去重。
6. **统一应用。** 人工组确认后加入本次待应用选集，与原 AI 可应用建议共同预览、一次提交。全部参与记录（包括保留项）互不重叠；任一参与记录、报告代次或来源依赖失效，整批零改账、零部分审计。未知结果只查询原 UUID，不重放选集。
7. **存量与局部处理。** 现有 v1 对账报告可打开并进入人工核对；当前报告代次有效、没有重扫且本次参与记录未变化时可应用，无须仅为启用入口重扫。旧消费分析报告仍只读。一条提示包含多组线索时，成功只标记实际参与的记录，其余记录可继续核对。同一报告代次中已参与成功应用的记录不再复用；需要重新组合保留项时重新扫描。
8. **界面与交付。** 保持移动优先，中英文同步。状态须说明能否操作、禁用原因及下一步；表单、记录选择、保留项和应用结果可用键盘操作。采用已确认的单个 feature 提交流程；本 spec 随实现提交，完整验证和安全审查通过后执行适用发布。

### 技术决策

- 复用 AppShell 内共享的扫描／应用控制器和既有 API，增加独立页面及其最小页面数据加载；不通过首页统计、趋势或分类查询间接加载对账页。加密家庭同步接入 `householdPages`、`PageView` 和受保护的 `/api/household/view` 分流。
- 保持 AI 报告正文 v1 和现有存储实体。人工选择作为独立、显式版本化的应用意图传入，服务端从报告断言解析真实交易，不能靠改变 `notice.canApply` 或客户端金额补丁授权。
- v1 输入、规范化摘要、已有终态回执及查询关闭标记继续按原协议解析；v2 应用协议承载人工组。新回执在现有 `BillReconciliationApplication` 受保护载荷中保存人工决定及真实交易映射，不新增明文财务索引，不为本次增加数据库实体或恢复格式版本。
- 沿用家庭优先锁序、有效身份／会话复核、账本可写校验、快照与来源依赖检查、分块写入、最小审计和短事务。人工路径仅替代关联判断，不能绕过这些检查。
- 沿用 AI 输入、批次、共享额度、结果正文及执行期限；新扫描需要本人 AI 同意，关闭 AI 选择后仍可人工核对已获准查看的报告。人工核对不调用供应商。应用请求仍受 16 KiB 正文上限约束，超限不截断；回执读取同时受原数量／字节预算和合法报告正文大小的约束。

## 设计视图

### 功能设计

记录页的“AI 对账”链接进入独立页面，保留账本与成员范围，并展示实际月／年扫描范围。用户可调整范围、发起扫描、查看当前任务、进入家庭共享历史和打开报告。浏览器返回记录页应恢复原 URL、筛选和滚动位置；直接访问对账页时也提供返回记录页的入口。首页只保留原有统计和分析界面，全局任务提示中的报告链接跳转到独立页。

结果区分别呈现原可应用建议和关联提示。可应用建议保留既有操作；关联提示展示原因、原记录和“人工核对”，不显示一个不可操作的选择框。没有可组成合法人工组的记录时显示具体原因；归档、重扫、记录已处理及快照冲突均有对应说明和恢复／重新扫描路径。

人工核对流程为：

1. 用户从当前提示的具体原记录中选择至少两笔，并逐笔查看日期、金额、分类、归属、来源和备注。界面区分不同金额／方向／归属的候选，不能把多对线索自动选成一个删除组。
2. 用户明确选择保留项，并确认所选记录属于同一笔重复记账。显示“保留此笔／软删除其余所选”的逐笔预览；缺少选择或不满足条件时不能加入选集，并说明原因。
3. 加入待应用选集，显示“人工确认去重”标记和保留项。应用前可以修改或移除人工组；不把人工组写回家庭共享的 AI 正文，也不改变模型给出的可信等级。
4. 待应用区汇总人工组和勾选的 AI 建议，展示整体及分日／分月收入、支出、结余、笔数变化。去重会改变结余，沿用原确定性预览，不套用抵扣的“整体结余不变”结论。
5. 用户一键应用后冻结原选集。成功刷新账目与处理状态；冲突指出受影响项目并提供重新扫描；结果未知时保留核验入口。处理提示中的一组后，其他互不重叠的记录仍可加入新选集。

界面中的“保留原记录”是动作预览，不画成可点击按钮。只有真正可用的按钮、链接、复选框或单选框承担操作，并具备名称、焦点及禁用说明。未提交的人工选择仅保存在当前身份及原 `reportId/generation` 绑定的内存中，同一浏览器应用实例内切换页面后可恢复。切换月份、账本、成员或打开其他报告只切换对应草稿，不能把旧 refs 或保留项解释为新报告记录；原报告换代时草稿失效并要求重新核对。刷新或身份结束后不从普通本机存储重建人工选集。已提交请求继续按原 UUID 核验，不随草稿失效而替换、清除或重放。有未提交人工选择时，在浏览器支持的场景提示未保存修改，不承诺移动系统强制关闭后保留未提交选择。

### 技术设计

#### 整体方案与当前依据

当前 `HomeView` 直接渲染 `BillAnalysisPanel`，共享 `BillAnalysisProvider` 已位于 AppShell，因此页面搬迁不应搬走后台控制器。`makeSuggestion` 把 `kind: notice` 固定为只读、动作均为 `keep`；结果组件给它渲染禁用复选框，原记录卡片也没有操作入口。这与用户截图的“关联提示、点击无响应”一致。本次补上人工核对路径，而不把原只读 AI 提示直接变成交易动作。

页面加载器只提供已授权的账本、家庭历史成员、范围和界面所需数据；报告正文仍通过受保护正文接口获取。加密路径与未加密路径使用同一功能视图，解锁材料和财务选集不进入 URL、日志或初始加密 SSR。后台任务完成、未知回执恢复和历史查看的跳转都使用新的对账路径。

人工动作由独立纯函数派生：明确保留 `keepRef` 对应原记录，其他组员派生 `delete`，不复用会自动挑选保留项的 `canonicalRefs`。原 AI 动作仍按原关系及证据重算。两类动作合并前分别校验，再按任务内 ref 和真实交易 ID 双重检查重叠；客户端和服务器共用确定性预览规则，服务器重新计算最终结果。

#### 关键结构与边界

| 对象 | 约定 |
| --- | --- |
| 原 v1 应用输入 | 保留原 `requestId/reportId/generation/suggestionIds` 及原摘要构造，不补默认字段后重算旧摘要。 |
| v2 应用输入 | 显式 `version: 2`，沿用原 UUID、报告及代次，包含 `suggestionIds` 和 `manualGroups`；至少有一个 AI 建议或人工组，人工单独应用允许 AI 建议列表为空。 |
| 人工组 | `{ noticeId, refs, keepRef }`。`noticeId` 必须为同一报告中的 `kind: notice`；所选 refs 均属于其 `evidenceRefs`，组内引用唯一、保留项属于该组。客户端不提交真实交易 ID、金额、归属或动作补丁。 |
| 选集数量与字节 | 单个人工组最多 500 笔；AI 建议和人工组的总数最多 200 项，合计最多 1,000 笔不同参与记录。16 KiB 正文限制优先，超限在提交前提示缩小选集；不自动拆成多个提交。 |
| v2 摘要 | 包含用途、协议版本、报告及代次、排序后的 AI 建议 ID，以及按确定规则排序的人工组。每组包含来源提示、排序后的 refs 和明确保留项；改变分组或保留项属于不同输入。重复组、重叠或无效引用不能经规范化悄悄修正成可执行输入。 |
| 受保护应用事实 | 版本化保存原输入摘要、原终态与预览、实际参与记录 IDs，以及每个人工组的提示／refs／真实 IDs／保留项／软删除集合映射。旧报告正文换代后仍能识别原人工决定，不能只保存可被下一代复用的 `rN`。 |
| 已处理状态 | 从同报告、同代次成功事实投影到任务内 refs。人工组不把父 `noticeId` 写入代表整条 AI 建议已执行的 `outcome.suggestionIds`。涉及已参与记录的 AI 建议变为不可再应用；提示中未参与的其他记录继续可核对。 |
| 抵扣事实 | 人工去重参与集合与抵扣消费集合分开。人工软删除重复收入不新增“退款已抵扣”事实；新格式的 `consumedIncomeIds` 只记录真实抵扣消费，原 v1 回执不改写。 |

同一报告代次的成功应用参与记录不复用，成功次数受实际报告记录数的一半约束；记录数量上限不代表该规模一定能通过正文预算。保留原成功回执读取的 200 笔、解密后 JSON 累计 1 MiB 上限，采用明文路由元数据分页。解密前另按现有密文封装膨胀及条数推导有限的物理载荷预算，不能把 1 MiB 直接当作相同的密文字节上限；原来源／应用证据扫描预算也不增加。公开 DTO 只投影当前报告最多 1,000 个引用的处理状态，不把全部回执或内部真实 IDs 返回。新增成功事实若会超出相应读取预算，在改账前整批拒绝这次新增，既有报告仍可读取。

AI 报告正文仍遵守原 200 项建议、1,000 笔记录和 64 KiB 上限；这些限制同时生效，正文大小可以先于记录数量触顶。人工选择及处理状态不是新的模型正文。人工组不占用额外模型批次，也不读取报告之外、期外或其他家庭的交易补齐候选。容量验收使用能通过真实报告生成预算的合成数据，不能向数据库注入超过正文预算的报告来证明可完成规模。

#### 实现流程与异常收敛

1. 当前有效身份打开报告，服务端验证家庭、报告用途、成功代次及所存快照的结构／引用，返回原结果及局部处理状态。读取不要求所有快照记录仍与实时账目完全一致；已处理或未选记录的后来变化不阻断旧报告展示。首次应用才对本次参与记录执行第 4 步的实时校验。关联提示可提供人工核对能力；重扫期间不接受同槽旧报告的新应用。
2. 客户端组装人工组并预览；应用时生成原有身份绑定 UUID，冻结两类选集。只持久化原有非财务核验指针，人工 refs、保留项、金额和备注不写普通本机存储；重开只查询原 UUID。
3. 服务端先严格解析协议和规范化摘要；事务按家庭、当前成员／账号／会话、稳定账本序、应用 UUID、报告加锁。既有回执按其原版本和摘要返回原终态，不因保留项后来被合法修改／移动／归档或报告换代而重算历史决定。改保留项或分组复用原 UUID，返回冲突但不覆盖原回执。
4. 对首次应用，从服务器报告断言解析全部参与交易，复核选择来源、同向等额、同账本／归属、保留项、已处理事实及重叠，批量比较最新业务字段、软删除状态、来源依赖与可写状态。身份、会话、家庭和加密模式按原锁序再次验证；不接受客户端自报家庭或成员。
5. 原 AI 建议按原证据规则派生动作，人工组按此次明确选择派生动作，重新计算混合预览。全部检查和容量预检通过后，在同一短事务内分块写交易、最小 `LedgerAuditLog` 和成功回执；人工保留项无写入，软删除沿用 `TRANSACTION_DELETED`，审计不附金额、备注或 AI 正文。
6. 任一业务检查失败，整批不改账；能够安全保存时先提交原 UUID 的稳定拒绝，再返回明确拒绝。不能安全写回执或提交结果未知时只返回未知／请求级访问错误。查询关闭仍先原子保存 `NOT_ACCEPTED`，阻止迟到执行；同 UUID 重试、跨成员竞争及失效身份不得产生重复改账。
7. 成功后逐条投影参与事实，刷新账目。相同提示的其他组可继续处理；已参与记录不能在当前代次再用于人工组或 AI 建议。原始扫描正文和既往完成结果不被回执刷新改写。

新回执格式纳入现有加密转换、换钥、v3 捕获／删除检查点和恢复校验；v1／v2 恢复包仍按各自固定实体集合验证，v3 实体集合不变。恢复验证新格式自身结构、原摘要和同家庭历史引用，不按当前记录金额或账本重新判定历史人工决定；保留项后来正常编辑、移动、归档后，原终态仍有效。恢复不重建 AppSession、执行租约或自动应用能力。

### 预估改动面

- `src/app/(app)/records/`：增加独立对账页、最小 loader/view 和记录页入口；`home/view.tsx` 移除内嵌面板，不顺手重做首页。
- `src/components/bill-analysis-*.tsx`、`bill-reconciliation-panel.tsx`、相关控制器与 `src/lib/i18n.ts`：新路径跳转、人工核对、选集／保留项、混合预览、局部处理与中英文状态。
- `src/components/encryption-gate.tsx`、`src/lib/encryption/view-data.ts`、`src/app/api/household/view/route.ts`：增加独立页的加密分流。
- `src/lib/reports/` 与 `src/app/api/reports/reconcile/`：版本化人工意图、确定性动作、统一原子提交、回执映射、局部状态及有界读取；复用现有实体、后台 owner 和资源机制。
- `src/lib/encryption/` 与相关测试：新受保护回执结构、转换和 v3 历史恢复兼容；不增加生产 seed 或本次无关迁移。
- 单元、真实开发数据库集成与移动端端到端：覆盖下面验收；使用合成账目复现截图结构，不把用户截图或真实账目正文写入仓库。
- wiki 目标为更新 `docs/wiki/ai-bill-analysis.md`，按实际实现同步 README 和受影响的加密／运维说明；原功能 spec 作为历史基线保留，不回填成新实现。

## 验收

- 记录页进入、浏览器返回、独立页直接打开、中文与英文手机／桌面 → 入口可达，首页不再显示完整对账模块，主导航仍三项；记录页原筛选和浏览器返回位置可恢复；组件与实际浏览器验证。
- 月／年、账本、成员切换以及记录页的非月年模式或额外搜索／金额条件 → 对账范围明确可见，不暗中使用记录页私有筛选或开始扫描，不读取期外补配；范围及接口集成验证。
- 扫描后离开页面、关闭全部客户端、重开任务、取消及未知结果核验 → 保留原后台生命周期，所有查看报告跳转到独立页，重开不重发扫描或修改；受控 Agent 和真实 Next.js 进程端到端验证。
- 含多种金额、多对记录、日期／描述不完全一致的单条关联提示 → 有明确人工核对入口，只处理所选同向等额子集，未选记录保持；合成截图结构的组件和浏览器回归。
- 人工指定信息较少、无来源指纹或较晚创建的一笔保留 → 始终保留用户指定原记录，原金额／字段不变，其余所选软删除；纯函数和真实数据库验证。
- 同一提示分两次处理互不重叠的组 → 首组仅标记实际参与记录，次组仍可操作；父提示不整条变成已处理，已参与记录和相交 AI 建议不能再次使用；状态投影及成员共享验证。
- 未提交人工组后切换月份／账本／成员、打开其他报告或原报告换代 → 选择始终绑定原身份、报告和代次，不能误套到新 refs；换代要求重新核对，原已提交 UUID 仍只核验；客户端状态及浏览器验证。
- 不足两笔、未指定保留项、组内重复引用、保留项不在组内、伪造提示或引用 → 客户端明确说明，服务端拒绝且不改账；协议和越权接口验证。
- 人工组跨家庭／账本／原成员、异向／异额、归档、软删除或已失效记录 → 任何字段伪造都不能绕过约束；真实数据库及加密路径验证。
- 仅人工、仅 AI 和二者混合选集，以及通过不同 refs 指向同一真实交易的重叠 → 统一预览与实际收入／支出／结余／笔数及日月分布一致；重叠拒绝，任何一项冲突均整批零修改、零部分审计；真实事务、并发和故障注入验证。
- 同 UUID 连点、改保留项、改分组、改 AI 选集、响应丢失和查询关闭先到 → 至多一次生效，原摘要／终态稳定，未知只查询，关闭标记阻止迟到；接口、数据库与浏览器验证。
- 人工保留或删除导入记录后重新导入原文件 → 原 ID／UUID／来源／指纹等保留，软删除记录继续占用来源，原流水不复活；实际导入→人工去重→重新导入集成验证。
- 人工删除重复收入、原已抵扣收入和证据不足的退款／报销 → 人工结果不生成新的抵扣事实，也不能借人工组执行净额抵扣，既有自动规则及原回执不被改写；证据及回归测试。
- 原 v1 对账报告、旧分析报告、原成功／拒绝／查询关闭 UUID、报告换代及本人关闭 AI 选择 → 合法存量对账线索可人工核对且不调用模型，新扫描仍需 AI 同意，旧分析只读，旧摘要和回执原样返回；兼容及共享报告回归。
- 在真实 64 KiB 正文预算内生成含多组线索的报告，逐组完成全部互不重叠人工核对 → 报告始终可打开、局部状态准确；有界分页、预解密字节检查及容量集成验证。正文、请求数量／字节或回执读取预算超限时受控拒绝；新增回执超限须整批零改账，已有报告保持可读，不把单独的数量上限宣称为实际可完成规模。
- 当前会话撤销、成员离开／重新加入、家庭关闭、加密切换及其他成员竞争 → 统一锁内拒绝失效写入，其他合法成员可见局部处理状态但不能取得他人 UUID；授权／模式竞态集成验证。
