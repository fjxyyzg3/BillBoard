# 首页月度结余趋势与累计结余

## 目标

在首页现有趋势卡片中增加月度结余趋势和累计结余视图，让家庭在同一筛选范围内查看每月收入减支出的结果，以及逐月累加后的结余。

## 决策基线

### 需求决策

- 趋势卡片按「收支趋势 / 结余趋势 / 累计结余」顺序提供三个视图，默认展示收支趋势。保留原收支趋势的统计粒度和查看记录交互。
- 两个新视图固定按月统计，严格跟随首页时间、成员和账本筛选，不设置独立时间范围。选单个月时显示一个数据点；年份、全部、近三个月和自定义范围按所含月份展示。
- 结余趋势使用折线图，每个点表示该月与所选时间范围交集内的收入减支出，允许负值。部分月份只统计交集内的记录。
- 累计结余使用折线图，从所选范围起点以 0 开始累加各月收入减支出，允许负值。范围外历史结余不作为期初余额，累计值表示已记录账目的结余，不表示实际资产余额。
- 两个新视图仅使用所选范围内的账目，不为新图读取范围外账目。
- 无记录月份的收入、支出和结余均为 0，累计值延续。无记录提示与数据读取失败分别处理，不将查询失败显示为 0。
- 新增文案同步支持中文和英文；手机、触屏和键盘均可切换视图、选择月份并读取数值。

### 技术决策

- 沿用 `src/lib/reports/`、首页共享 loader / view 和现有 SVG 图表实现，不新增图表依赖、数据库字段、迁移或后台任务。
- 日期按 `Asia/Shanghai` 计算，金额聚合及派生值始终使用整数分。复用现有首页范围解析、截至上海当天的截止规则，以及自定义范围在最早账目月份前省略空月的策略；不改变主范围及首页其他统计。
- 月度桶、当月结余和累计计算使用共享纯函数。未加密查询与已加密请求内的解密查询输出相同的月度数据结构和计算结果；加密页面继续通过原携钥 POST 加载，初始 HTML 不新增财务数据。
- 月度数据使用首页既有家庭、账本和成员授权范围，排除软删除记录，保留历史成员及归档账本的既有可读统计语义。
- 复用现有报表已聚合的收支数据构建月度结余序列，不因新图新增交易查询或逐月查询。未加密路径保持数据库批量聚合；加密路径保持现有事务快照及解密批量读取。已有范围选项及首页其他分析组件维持原行为。
- 图表只接收获准的聚合值、日期及明细链接。视图切换在客户端完成，不重新请求数据，不向 URL、日志或持久化客户端存储新增财务数据。

## 设计视图

### 功能设计

趋势卡片保留当前位置和外层布局，在卡片内增加三项视图切换。进入首页默认展示收支趋势；切换只影响卡片内部图表、图例、说明和所选月份详情，不改变首页筛选或其他统计。

两个新视图的横轴均为月份，纵轴为金额，折线支持正值、负值和跨越零轴。结余趋势显示各月结余原值，累计结余显示逐月累加值。纵轴包含零基准，详情用带符号金额表达正负结果，不能只靠颜色。

点击、触摸或用键盘选择月份后，在图表下方显示该月有效日期段、收入、支出、当月结余和笔数；累计结余视图额外显示累计值。数据点只有一个、所有值为 0 或各值相同时，图表仍能选中并正确展示数值，坐标计算不产生无穷值或无效位置。

所选月份有记录时，详情提供「查看当月记录」链接，日期仅覆盖该月与主范围的交集，并保留账本、成员及返回原时间范围的上下文。累计点不直接解释为单月记录总额；详情同时展示当月结余和累计结余，明确链接所指月份。没有当月记录时不展示无意义的明细链接。

筛选变更后，三个视图使用新范围的数据，旧选择不能展示与新数据不匹配的详情。沿用首页既有加载和错误处理，无记录时提供说明。

### 技术设计

#### 整体方案

`loadHomePage` 继续负责从有效 AppSession 派生家庭身份、授权成员和账本范围，并将解析后的首页范围传给 `queryHomeReport`。报表结果在原收支 `trend` 之外增加独立的月度结余序列，原收支图和其他首页组件继续使用原字段。

月度结余序列从原收支趋势的已聚合结果派生：原序列按日统计时，按上海月份合并收入、支出和笔数；原序列已按月统计时，复用各月聚合值。共享纯函数计算当月结余并按时间升序累加。新图不需要新增交易查询，也不改变首页汇总、分类和其他分析的数据范围。

`TrendChart` 负责将报表数据转换为可序列化的图表输入和明细链接，客户端图表负责切换、选点、坐标及详情。复用现有触屏选点、方向键、Home / End 和可见焦点机制；新增切换控件具有可访问名称和明确的选中状态。

#### 月度数据

每个月度点包含月份键、当前桶起止时间、收入、支出、当月结余、累计结余和笔数。两个新视图共用这份序列，分别取当月结余和累计结余作为折线值。

月度计算采用以下定义，所有日期边界均为上海时间且包含首尾当天：

| 数据 | 定义 |
| --- | --- |
| 当前桶 | 当前自然月与首页所选范围的交集。自定义范围沿用已有范围压缩策略，只省略最早账目月份之前的空月，展示范围内的中间空月必须保留。 |
| 当月结余 | 当前桶内收入合计减支出合计，单位为分。 |
| 累计结余 | 从所选范围起点到当前桶末尾的各月当月结余之和，初值为 0。 |

例如，自定义范围为 5 月 10 日至 6 月 6 日：5 月点只统计 5 月 10–31 日，6 月点只统计 6 月 1–6 日；第二个累计点等于这两个日期段结余之和。范围外的 5 月 1–9 日和 6 月 7 日以后账目均不影响新图。

#### 实现流程

1. 原首页入口或加密携钥 POST 完成会话、家庭、账本和成员授权后，解析既有主范围并按原流程生成首页报表。
2. 复用原收支趋势的已授权范围内聚合结果。已加密路径保持现有 `financialSnapshotOptions` 事务及范围内解密聚合，不另设明文统计存储。
3. 共享计算函数构建月度序列，计算各月结余及累计结余。首页汇总、分类和原收支趋势维持原逻辑；最后一个累计值等于同筛选范围的首页结余。
4. 首页视图组装月度链接和中英文标签，将数据交给图表。客户端切换图表并提供文字数值、键盘选点及有记录月份的明细入口。
5. 数据读取失败沿用页面错误处理，不缓存失败为零值；筛选或数据变化时清除失效选择，避免展示旧范围详情。

- `tests/integration/report-query.test.ts`、`encryption-imports-reports.test.ts` 和相关账本范围测试：查询、隔离和双路径一致性。
- `tests/e2e/`：首页视图切换、筛选、月度明细、移动与键盘交互回归。

## 验收

- 默认进入首页及切换三个视图 → 顺序为「收支趋势 / 结余趋势 / 累计结余」，默认收支趋势，原收支粒度和原明细行为保持，两个新图均为按月折线；组件与首页 e2e 通过。
- 所选 1–3 月结余依次为 `300000、-100000、200000` 分 → 结余趋势依次为原值 `300000、-100000、200000` 分，累计结余依次为 `300000、200000、400000` 分；范围外账目不影响两图，也不为新图新增范围外读取；纯函数和查询测试通过。
- 本月仅到 6 日、自定义跨月、完整月、月末、闰年及上海日界 → 月度桶仅包含自然月与主范围的交集，5 月 10 日至 6 月 6 日案例只统计两个有效日期段；范围单元与查询测试通过。
- 月份、年份、全部、近三个月、自定义范围以及筛选成员／账本 → 新图与其他首页统计使用同一主范围，最后一个累计值等于首页结余；查询及 e2e 通过。
- 空月份、空家庭、只有收入、只有支出、负月结余、负累计、全零和单点 → 零值、累计延续和无记录提示准确，图形坐标有效；聚合与组件测试通过。
- 自定义起点远早于最早账目 → 主范围及汇总不变，新图沿用现有空月压缩并保留有效月份之间的空月，不枚举数千年的空桶；查询回归通过。
- 不同家庭、伪造成员／账本、软删除、历史成员及归档账本 → 新图保持原授权与可见性规则；集成测试通过。
- 同一测试数据分别走未加密和加密家庭 → 当月结余、累计结余、月度桶及明细范围一致；缺码或失效身份不能加载财务数据，初始加密响应不包含新图聚合；加密查询及页面入口测试通过。
- 选择有记录月份并进入明细 → 仅显示该月与主范围交集内的记录，账本、成员和返回原范围上下文保留；空月不提供明细链接；首页 e2e 通过。
- 手机中文／英文及键盘操作 → 三个切换项和月度详情可读、可操作，金额符号和有效日期明确，页面无横向溢出；移动 e2e 与可访问性检查通过。
- 新图读取失败或筛选后选点失效 → 使用既有错误处理或清除失效详情，不将失败或旧数据展示为新范围零值；针对性测试通过。
- 实现交付 → `npm run lint`、`npm run test:unit`、`npm run test:integration`、`npm run test:e2e` 全部通过；按 `skills/billboard-security-review/SKILL.md` 输出 Findings、Verification、Residual Risk。版本一致后将 spec 与实现合为同一 feature 提交，合回并推送 `master`，按既有生产脚本重启并完成健康检查。
