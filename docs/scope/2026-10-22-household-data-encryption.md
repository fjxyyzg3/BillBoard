# 家庭可选账务加密与按请求临时解锁

## 目标

让家庭自行选择是否加密全部账务。开启后由家庭持有解锁密钥，服务端仅在单次请求或已受理任务的有界执行期内临时持钥处理业务；支持安全开启、关闭及保持加密的独立换钥。未开启的家庭保持现有使用方式，所有状态均保留家庭共享、快速记账、历史复盘及既有数据。

## 决策基线

### 需求边界

#### 家庭开关与转换边界

- 加密是按整个家庭统一选择的可选能力，覆盖所有账本、归档历史及下述保护范围，不能按成员或单个账本分别开关。已有及新建家庭默认未加密，只有当前有效负责人可以明确开启、关闭或独立换钥；普通成员可查看当前状态，OPS 不代改保护方式或代解锁。
- 未加密状态沿用现有获准账务的存储和使用方式，不要求家庭解锁码，也不宣称对维护者静态不可读。开启加密后才适用账务密文落库和客户端持钥规则；认证、授权、AI／语音选择、日志最小化和私有导出等既有边界不因关闭而放宽。
- 开启前须建立并可靠备份候选家庭码及恢复材料；关闭须提供当前有效家庭码，并明确确认整个家庭账务将恢复为未加密存储。持有账号密码、OPS 权限或点击关闭都不能替代密钥；所有解锁材料丢失时不能关闭加密找回账务。
- 开启／关闭是完整的数据转换，不是即时布尔赋值。转换期间暂停该家庭的新写入和新导入、AI、语音及导出任务，收敛已受理任务；完整源视图可继续按原模式只读及查询原 UUID 结果，目标暂存不可见。其他家庭不因该转换被停写。
- 关闭经明确受理后会开始生成隔离的未加密目标，可能早于最终模式切换产生持久化明文；中止关闭不能撤回这些已产生的副本。失败清理和保护说明须覆盖该目标、旧行版本、WAL 及备份，不以恢复源模式宣称从未生成明文。
- 转换核验完成后原子切换整个家庭的可用模式及代次。失败、中断或结果未知时不得展示半份数据、跳过无法转换的历史或猜测切换结果；只能根据原操作回执恢复、明确终止或继续核验，不把客户端开关值当作服务端状态。
- 独立换钥仅在已加密的稳定状态提供，全程保持密文存储，不要求先关闭加密；开启、关闭和换钥在同家庭内互斥。再次开启使用新的随机密钥及不复用的加密周期，并更新模式代次，不复用已停用密钥或让旧设备按旧代次提交。

#### 保护目标与披露边界

- 已加密家庭采用客户端持钥、服务端按请求临时解密的静态数据加密。控制运行中服务端的维护者仍可能取得密钥和明文，不承诺运行时对维护者不可读，也不称为端到端加密。
- 已加密家庭当前生效存储中的账务正文、草稿、映射、任务结果、搜索或导出中间产物不得留下明文。服务重启后，仅凭数据库、备份、服务配置、登录 Cookie、JWT 或账号密码，不能恢复其账务解密能力。未加密家庭的合法明文及已盘点的旧副本不能被误报为已清除；保护范围按家庭、模式和实际已核验副本说明。
- 加密内容包括金额、收支类型、交易发生日期、分类关联、备注、账本名称、导入文件名与明细、外部成员名、原始行字段、来源信息及指纹、分类／成员映射、退款关联、自然语言结果与金额摘要，以及 AppEvent 中的业务摘要和 metadata。旧输入摘要、旧结果及旧事件业务内容保持原值并纳入加密保护，不因迁移重新生成。
- 服务端允许持久化授权与同步必需的元数据：账号和家庭成员关系、内部家庭／账本／成员／记录 ID、原请求 UUID、操作时间、修订、模式代次、加密周期和密钥版本、密文大小、同步／软删除／任务状态、最小审计及不含业务值的资源用量。加密路径的幂等和去重索引只能使用受密钥保护的不透明标记，并明确其相等关系泄露；不能把金额、交易日期、分类关联或原始摘要作为明文旁路索引。
- 公共内置分类定义继续按现有英文名称存储；已加密家庭记录使用哪个分类属于加密内容，未加密路径沿用原关联。账号资料、登录密码哈希、家庭成员身份和负责人角色继续按现有认证规则管理，不以本次加密代替账号权限。
- 云端 AI、语音及导入分类推荐继续沿用本人按账号分别选择、默认关闭的规则。服务器和供应商会接触本次主动提交的输入及处理结果；家庭密钥不发送给模型、转写供应商或分类 Agent，历史账目不自动加入模型上下文。不得以开启某项能力推定其他能力的同意。
- 用户主动提交给维护者的诊断说明属于显式分享内容；诊断不能自动附带账务、密钥、解密缓存或请求正文，输入处须明确提示不要粘贴家庭密钥和账务。

#### 业务事件审计与 OPS

- AppEvent 是保护范围内的独立副本。已加密家庭的事件明文只允许事件 ID、通用操作类型、已核实的家庭／成员 ID、操作时间、固定且无查询参数的 pathname，以及必要模式／封装版本；原 summary、metadata.transactionType、source、业务 count 和其他业务内容纳入家庭加密 payload。新增事件按 schema 拒绝未知字段，存量原字段按本节完整保留；不得把收支方向、来源或实际交易笔数改写进另一段明文摘要。
- OPS 对已加密家庭及转换中的家庭只展示上述最小元数据和由通用操作类型生成的固定标签，不取得家庭密钥、解密事件 payload 或从交易／草稿补出业务信息。今日和七日活动统计继续按事件行数计数，不改为累计 metadata.count 或实际交易笔数；稳定未加密家庭沿用现有审计行为。
- 仍在现有留存范围内的历史 AppEvent 随家庭进行双向转换、再次开启及备份恢复：原业务 summary 和 metadata 逐值保留，事件 ID、时间、类型及归属保持，不通过删除内容或只隐藏 OPS 页面解决。AppEvent 沿用现有 90 天留存及新增事件触发清理规则，转换不重置 createdAt、延长留存或复活已清理事件。
- 事务后的事件写入也须根据服务端真实模式、代次及合法原请求上下文决定可写内容。业务已经成功而事件迟到导致原上下文失效、加密路径缺少当前有效密钥或遇到模式／密钥版本变化时，只尝试记录白名单通用事件，不能持久化原业务明文、排队补写原文、借用其他请求的密钥或要求用户重做已成功记账；事件失败不改写原 UUID 的成功结果。
- 无家庭的登录／安全事件继续按原最小规则记录，不从客户端猜测家庭归属。OpsAuditLog 和 LedgerAuditLog 继续保留各自必要的安全／授权审计，不依赖家庭解锁码，也不套用 AppEvent 的业务 payload 或 90 天清理，尤其不得清除仍被会话撤销校验依赖的审计。

#### 家庭密钥与恢复

- 家庭首次开启加密时，由负责人在客户端建立一份高强度随机共享解锁码。它是加密凭据，与登录密码、账号恢复链接和普通访问 Token 分开；不允许用短口令、账号密码、家庭名或其他可猜内容替代。
- 有效成员登录后通过粘贴或本机二维码导入家庭解锁码；家庭自行通过可信渠道分发和备份。邀请链接、邮件、页面 URL 和公开领取链接不携带家庭密钥。
- 负责人负责加密开关、首次建立和手动换钥。其他有效成员可以导入、使用、备份并协助恢复现有码，不获得发布家庭模式或新密钥版本的权限。身份和角色均由当前有效 AppSession 派生。
- 可信设备记住密钥，日常业务自动取用，不要求个人另设解锁密码，也不引入逐设备审批或设备白名单。保存按原账号、家庭及成员身份隔离；明确退出、切换账号或成员身份结束时清除本机密钥、解密缓存及该身份不应继续保留的现场。远端无法可靠擦除用户已复制的密钥或离线设备副本。
- 登录会话到期时停止新的业务，清除可使用的内存解密上下文；可保留按原身份隔离的加密本机密钥包和待确认 UUID，供同一有效身份重新登录后恢复。不得延长原 AppSession，或让重新加入产生的新成员身份继承旧身份现场。
- 共享解锁码本身承担家庭备份／恢复凭据的作用，不再新增一套个人恢复秘密。仍持有可用密钥的有效成员可以帮助家庭恢复；备份和所有客户端的解锁能力都丢失时，维护者不能恢复。密码重置和 OPS 操作不自动解锁账务。
- 成员退出、移除或失效时撤销在线访问，不强制换钥，也不因此暂停其他有效成员的正常记账。家庭自行决定何时更换密钥；换钥前，旧码持有者如另行取得后续密文仍可能解密。这是已接受的边界。
- 手动换钥需生成新共享码及新的数据密钥版本，新写入和新修订使用新版本；当前新码仍能打开获准的历史密钥。旧码已解密的历史和已有副本无法收回。
- 换钥发布前，负责人必须已可靠保存并回读验证新码、密文恢复包和受保护的轮换恢复状态。响应丢失、客户端崩溃或存储失败不能使已提交的新码仅剩内存副本；结果未知时保留旧／新候选材料，先查询原操作，不生成另一套密钥或把未知当作失败。
- 每个保留的加密恢复点必须有可验证的配套密钥材料。已加密时由当前共享码及独立密文恢复包覆盖历史版本；关闭期间仍须保留最近的可用码及相应恢复包供旧加密备份恢复，再次开启时将所需历史密钥纳入新码保护的恢复包。无需额外个人密码或永久保存历代旧码；关闭开关、恢复明文现库或单独恢复数据库都不等于旧加密备份可解密。

#### 业务兼容与迁移范围

- 保留现有两人家庭及邀请制多家庭、多账本、历史成员、归档账本、成员筛选和家庭汇总。权限只来自当前有效身份；持有正确密钥不能恢复旧身份、越过家庭边界或修改归档账本。
- 金额在加密前及解密后的规范数据中继续使用整数分 amountFen，日期和范围继续按 Asia/Shanghai。分类类型、成员归属、来源去重、退款抵扣和批量确认规则保持；普通有效查询排除软删除，同源导入去重包含软删除。
- 手工、自然语言和语音记账、导入、编辑、软删除、移动、搜索、报表和 Excel 导出继续提供。计算和文件解析／生成可留在服务端内存中，不要求浏览器批量解密历史并完成业务运算。
- 新写入仍固定家庭、成员、账本及原 UUID。同身份切换账本保留各账本草稿和在途目标；重试沿用原请求快照及 UUID，不因加密随机数、刷新、换钥或未知结果生成新 UUID。旧已完成结果不重算，不改变来源或成员引用。
- 开启及关闭均转换现有有效及软删除交易、pending／completed 导入草稿、全部映射与退款元数据、旧自然语言结果和输入摘要，以及留存中的 AppEvent 业务 payload。账号、历史成员、账本、原业务与事件 ID、关联关系、有效会话的到期及撤销状态保持。部署本功能只登记原家庭为未加密，不强迫其建立密钥或先迁移账务才能继续使用。
- 旧数据库卷、WAL、备份、恢复副本、已知导出和其他明文产物单独盘点。需保留的恢复点应有经过核验的密文替代；未处理副本和供应商已接收内容不得宣称已消失。实际删除／覆盖遵守已核实清单、数据保留及对应具体授权，不能以本 spec 代替尚未明确的破坏性操作范围。

### 技术决策

- 服务端家庭配置维护 UNENCRYPTED、ENABLING、ENCRYPTED、DISABLING 状态、单调递增的模式代次及唯一转换操作。请求按原有效身份取得的服务端状态路由，不能根据是否携钥、旧客户端协议或客户端开关值猜测模式；加密模式的缺钥／错误密钥永不触发自动降级。
- 模式代次用于并发授权，建立／终止转换屏障及发布新模式均使旧受理代次失效；密文使用独立的不复用加密周期标识，历史密文、包封密钥和恢复包保留其原周期绑定。普通模式状态变化不能改写旧密文的认证上下文，再次开启不能复用此前周期的版本空间。
- 转换屏障、模式切换和独立换钥使用同一家庭优先锁序及代次检查。数据在隔离目标中分批转换，保持唯一生效源；最终短事务复核原授权、模式／版本、源修订及全量核验结果后切换生效视图。转换状态与回执可持久化，密钥不能持久化；转换中不允许新业务写入源或目标。
- 加密以家庭为边界，账本不各自持钥。采用高熵随机家庭主密钥、版本化随机家庭包封密钥及逐实体修订的随机内容密钥：家庭主密钥保护含历代包封密钥的密钥包，各版包封密钥保护该版实体的内容密钥，内容密钥加密正文。主密钥只由客户端持久保存，服务器的历史密钥包和内容密钥也只能以密文保存；单独取得它们和服务配置不具备解密能力。
- 采用成熟标准原语和平台密码 API：256 位随机密钥、AES-256-GCM 认证加密、HKDF-SHA-256 用途隔离。每次新加密使用新随机 nonce，新的数据修订不能复用旧内容密钥／加密上下文；禁止自创密码算法或用普通 SHA-256 摘要充当加密。封装格式有明确版本，绑定家庭、加密周期、实体种类、记录 ID、账本／成员关联、修订及密钥版本，防止密文串换和降级。
- 家庭主密钥或等价解密材料仅通过受保护 HTTPS 请求正文传入，不写入 URL、Cookie、JWT、session 数据、环境变量、数据库、Redis、文件、任务持久化参数、日志、诊断或遥测。请求入口不得复制、记录或向 Agent 转发整个含密钥的参数对象。
- 服务端不建立按家庭或登录会话复用的内存密钥缓存。解密上下文绑定原 AppSession、账号、成员、家庭、任务 UUID、目标账本和执行期限，只属于该请求或已完整受理的任务。结束、失败、取消或到期后停止使用并尽力清理可控字节缓冲与引用；不声称能证明垃圾回收运行时立即擦除所有内存副本。
- 每个受保护操作都先核验 AppSession、同家庭范围及服务端模式，再按模式取得业务上下文。最终写入、结果领取／返回前复核原身份、账本、模式代次及资源租约，沿用现有家庭／成员／账本锁序。正确密钥不授予其他会话解锁状态；加密路径的无效或缺失密钥不能退回明文读取或创建半个任务。
- 数据库负责授权范围、引用约束、修订／幂等及模式对应索引；加密路径在一致快照内分批解密、验证、筛选和聚合，未加密路径沿用现有查询语义。加密家庭不保留用于继续运行原 SQL 的明文金额／日期／分类列、物化报表或可由服务端固定密钥解开的旁路副本。两条路径共享业务校验，不能通过提前截断或只计算当前页改变统计。
- 本机密钥使用按原身份隔离的受保护密钥包：浏览器使用 IndexedDB 和 Web Crypto 本机保护材料；Android 使用 Keystore 保护应用私有密钥包，并通过仅可信同源主框架可调用的窄接口取用。后台 Cookie 不交给 JavaScript，禁止加入任意原生调用、路径或 URL 桥。
- 开启／关闭由显式受保护转换流程执行，不由普通启动、seed 或单独 prisma migrate deploy 自动执行。需要对既有物理存储完成明文副本替换时，继续使用干净的 PostgreSQL 17 数据卷和专门维护流程；目标按家庭已确认模式保存，未选择加密的家庭仍可存储原获准账务。单家庭在线转换只证明当前生效数据已转换，不能宣称旧行版本、WAL、源卷或备份已清除；这些副本仍按清单和授权受控处理。

## 设计视图

### 功能设计

#### 建立、导入与日常使用

新家庭及升级后的既有家庭默认未加密，可按现有权限直接记账，不先要求建立家庭码。家庭管理入口显示全家庭当前保护方式、转换进度及实际保护边界，负责人可以显式开启或关闭；只有 ENCRYPTED 状态开放独立换钥。选择开启后才要求建立密钥和备份，未完成不能被标记为已加密。已加密家庭的普通成员没有密钥时仍可管理本人账号，但账务入口显示导入引导，不能用账号登录或 OPS 重置替代解锁。

密钥页面归于账号／家庭管理入口。负责人可在相应状态建立和更换密钥；已解锁的有效成员可显式显示、复制或备份现有码。二维码是仅本机识别的数据格式，包含格式、家庭及版本校验，不是带密钥的网页链接；视频帧、图片及解锁码不上传。摄像头不可用或权限被拒绝时可粘贴导入。

浏览器或 App 在加密模式首次导入后保存该原身份的受保护本机密钥包。重新打开时，先验证当前身份和服务端模式／代次，再按需取得本机密钥并随解密业务请求提交；未加密家庭不自动上传旧码。首屏可先显示不含账务的加载／导入状态，不把密钥放进页面 HTML 或服务器返回的组件属性。设备存储不可用时提供当前运行会话使用方式和明确的重新导入提示，不能改为把密钥托管服务端。

切换账本不改变家庭密钥或已开始任务的目标。缺失、错误、其他家庭或过期版本密钥分别收敛为重新导入／刷新版本提示，保留合法待确认 UUID，不清空已提交结果或自动重发业务输入。退出或身份改变后，迟到响应不能重新保存旧密钥、显示旧账务或覆盖新身份草稿。

#### 开启与关闭加密

开启时，负责人先建立候选家庭码，保存并回读验证新码、密文恢复包和候选恢复状态，再提交转换请求。服务端建立家庭转换屏障并收敛在途任务，在隔离目标逐批加密原账务，核验字段、关系、来源与原 UUID 结果后切换为 ENCRYPTED。旧页面不能继续按明文协议入账，其他有效成员须导入新码；存量数据或备份材料未核验时不显示完成。

关闭时，界面明确说明所有账本将停止当前静态加密保护，之后维护者可读取持久化账务，且旧加密备份仍需密钥及恢复包。负责人确认并提供当前有效码后，服务端按相同屏障和核验流程转换到未加密目标，最后原子切换为 UNENCRYPTED；旧码失效或缺失时拒绝，不通过账号密码或维护者入口解锁。转换关闭前仍按原加密模式访问，不能因为已点关闭而提前开放明文接口。

转换期间显示准备、转换／核验、待确认及明确终态。中断后按原操作 UUID 查询；客户端从受保护候选状态或独立副本恢复材料，以当前合法身份重新核验后续作，不把重登录视为过期旧请求获得提交授权。只有确认提交或确认旧请求再不能提交，才切换本机模式／清理候选；不能把超时或回执缺失解释为已恢复原状。

关闭成功后，各客户端以服务端模式及代次停止自动携钥并清除当前可用解密上下文；本机明文／密文草稿升级遵循原身份、账本及 UUID，不自动重发。在关闭前已独立备份的最后可用码及恢复包继续由家庭保管，直到依赖的加密恢复点完成受控替代或被新包覆盖。再次开启建立全新密钥及加密周期，将保留恢复点所需历史包封密钥纳入新包；不通过关闭再开启替代日常换钥。

#### 业务处理与请求结束

手工和编辑表单保持现有字段及校验体验；服务端按已确认模式取得现有内容，加密路径在请求内解密、校验并加密落库，未加密路径不取家庭密钥。列表、搜索、报表和导出按获准范围及一致模式处理；返回内容使用 private/no-store 等适用控制，禁止共享缓存、预渲染产物或错误报告持久化明文。

文件导入继续在服务端解析受限文件。草稿、重复候选、映射和退款来源按家庭当前模式持久化，批量确认仍采用批量查询、分块写入和事务 timeout。两种模式下的 Excel 均只输出获准家庭及上海日期范围内的可见字段；服务端生成时使用有界内存或加密私有临时文件，领取重新授权，无公开下载 URL。

自然语言、语音和导入推荐继续要求既有本人选择。服务端仅将完成该次请求所需的输入、候选和最小样例交给供应商；解密材料不进入内部 Agent 协议、子进程环境、命令行或供应商请求。音频仍只使用受控短期内存／tmpfs 和现有清理边界，不进入持久卷或备份。

完整有效输入及所属模式所需材料正式受理后，任务可在现有有界执行期内完成；客户端切页或同意开关关闭不改写既有任务。会话／成员失效、账本不可写、模式代次变化或租约失效阻止最终提交。取消须等解析器／供应商实际停止后释放占用和按需取得的解密上下文，不能先释放后继续处理。

服务进程退出会失去临时密钥，不能由持久化任务参数自动恢复解锁或重放原文。恢复后的客户端携原 UUID，按当前合法模式提供所需材料查询确定结果；已加密结果需合法密钥解密领取，未加密家庭不要求家庭码。未完成请求按既有有界失败／恢复规则处理，不能凭缺失密钥伪称未入账或创建新任务。

现有 OPS 最近事件继续显示通用操作、时间及获准归属；加密及转换状态使用固定通用标签替代原业务 summary，不增加家庭密钥输入或账务详情入口。活动计数仍基于同一批事件行，保护业务 payload 不改变统计口径；关闭完成后的展示按稳定未加密规则处理，不能在关闭请求刚受理时提前暴露。

#### 手动换钥与恢复

负责人客户端在 ENCRYPTED 且已解锁的稳定状态生成新共享码和新家庭包封密钥，全程不进入 UNENCRYPTED，不写明文暂存，也不执行两次全量模式转换。先备份新码及新码保护的密文恢复包，并从实际保存的副本回读校验家庭、密钥版本及历史包封密钥完整性，再允许发布。轮换恢复状态同时受保护地保存原身份、模式代次、原操作 UUID、预期旧版本、候选新版本、候选密文包摘要及旧／新解密材料；界面显示“准备完成、发布中、待确认、已完成或未提交”状态，不在收到成功响应后才首次保存新码。

历代家庭包封密钥纳入新码保护的密钥包，当前新码可读取历史。新记录和新修订同时生成全新的内容密钥，不能只改包封而继续用已暴露的旧内容密钥加密新正文。服务端仅在该操作内临时使用旧／新解密材料，核验历史密钥可用后原子切换当前版本；轮换回执只持久化操作、身份、版本、密文包摘要、期限和终态，不保存解密材料。

发布结果未知时，客户端重新打开后从受保护状态或已验证的独立恢复副本恢复同一候选操作，查询原 UUID 及当前版本后再收敛。未确认前不丢弃旧／新候选材料，也不自动生成新 UUID 再次换钥。本机存储不可用的会话模式，必须先完成独立恢复文件的保存与回读验证；无法完成时不允许该设备发布换钥，提示在具备可靠保存能力的设备操作。

新请求不再接受旧主密钥版本。换钥与在途写入按家庭并发边界串行，旧版本迟到写入明确失败，不继续加密到退休版本，也不部分入账；已提交结果仍可用新码读取。家庭自行将新码分发给保留成员，旧设备显示重新导入提示。成员退出本身不触发该流程。

仍持有码或可用本机密钥的有效成员可向家庭提供现有码；若需发布新版本，仍由当前负责人操作。维护者只处理既有账号及会话管理，不新增读取家庭码、解锁共同账务、代登录或绕过权限的恢复入口。

家庭加密恢复备份由当前共享码和密文恢复包组成，分开按家庭自行保管；恢复包不是新的明文密钥或个人恢复秘密。首次／再次开启及每次新增包封密钥版本／换码时，都要在发布前生成并核验对应恢复包，在家庭保管的独立导出或已有私有备份介质中保留副本，不能只依赖在线数据库。关闭期间保留最近的可用码及恢复包，不再日常携钥；正常加密写入的逐实体内容密钥随实体密文包封保存，不要求每记一笔重新导出家庭恢复包。

### 技术设计

#### 整体方案

```mermaid
flowchart LR
    Client["可信客户端：家庭模式与按需本机持钥"]
    Request["请求／有界任务：授权、服务端模式、按需临时解密"]
    Storage["按家庭存储：未加密正文／账务密文、密钥包、必要元数据"]
    Provider["AI／语音：获准的本次输入，不接收家庭密钥"]
    Client -->|"HTTPS 正文：业务输入；加密路径附临时解密材料"| Request
    Request -->|"授权结果，private/no-store"| Client
    Request <-->|"固定模式／代次及同家庭范围"| Storage
    Request <-->|"本人已选择的最小处理内容"| Provider
```

请求接入层负责身份、来源、大小、格式及服务端模式校验；应用服务在加密路径取得不可跨请求复用的解密上下文，未加密路径不建立家庭解密能力。存储层仅提供获准家庭、当前生效模式及代次的数据，隔离转换目标不对业务查询开放。业务纯函数继续处理整数分和上海日期，不承担密钥持久化。所有成功、失败、超时和断连路径都通过同一生命周期收敛清理；断连不表示已正式受理任务立即终止，允许继续的原任务在原期限内真实收敛后才释放其密钥，不因此保留到新请求。

含密钥的请求经过实际 HTTPS／转发链路，必须核验前置服务、框架、追踪及错误收集不记录请求正文和解密材料。现有转发拓扑及 loopback／OPS 边界保持；不能用应用 no-store 代替外部日志控制，不能承诺防范 TLS 终止方或受控服务进程在运行时读取明文。

#### 关键结构

| 结构 | 持久化内容与职责 |
| --- | --- |
| 家庭加密配置 | 稳定模式／转换方向、模式代次、当前生效源、加密周期、格式及当前密钥版本、密文密钥包；不存主密钥或可由服务器固定秘密还原它的副本。 |
| 加密实体封装 | 版本、nonce、认证标签、密文及关联上下文；覆盖交易、账本名称、导入草稿／行／映射、退款元数据、自然语言结果、旧摘要及 AppEvent 业务 payload。 |
| 授权与引用元数据 | 原家庭、账本、成员、记录 ID、UUID、修订、软删除和操作时间；复用或补足同家庭组合约束，不从密文或客户端声明重新认定权限。 |
| AppEvent 与 OPS 最小视图 | 原业务 summary／metadata 按家庭模式保存，密文绑定原事件 ID、家庭和加密上下文；OPS 仅取得允许的明文列和固定通用标签，不持有家庭密钥或可还原业务内容的旁路摘要。 |
| 模式对应查询／幂等标记 | 加密模式使用不透明标记，派生按用途、加密周期与密钥版本隔离，不能暴露原金额、来源指纹或输入摘要；未加密模式保留原语义。转换、再次开启及换钥后仍识别原 UUID、去重及获准历史，不扩大 UUID 唯一键。 |
| 请求解密上下文 | 仅内存存在的密钥集合、原身份、账本／请求和截止时间；不能序列化进 session、队列、错误或结果，也不存全局／会话密钥池。 |
| 客户端私有存储 | 原身份绑定的受保护家庭密钥包及加密模式草稿／待确认快照；任何模式都不向普通 localStorage、sessionStorage、日志或隐藏 DOM 保存原始密钥，加密模式也不在其中缓存明文账务。未加密草稿沿用原身份及 UUID 规则。显式导入／显示密钥仅在本机交互期间渲染，结束后清理，不能写入初始 HTML、隐藏字段或数据属性。 |
| 模式／轮换恢复状态与回执 | 客户端受保护保存候选操作及所需解密材料；服务器只保存原身份／操作 UUID、源／目标模式与代次、版本、候选密文包摘要、转换进度、期限和提交／终止状态。回执与模式／版本切换同事务提交，不包含业务原文或密钥，不形成会话密钥缓存。 |
| 密文恢复包与恢复点清单 | 恢复包由当前或关闭期间最近的可用家庭码保护完整历史包封密钥集合，绑定家庭、加密周期、格式、密钥版本和完整性信息；清单记录备份标识／摘要、各家庭快照模式／代次、加密周期、所需密钥版本及可用恢复包标识，不包含明文密钥。 |
| 隔离转换目标 | 分批转换及核验的目标数据、源修订与进度；模式提交前不成为业务源。开启生成密文，关闭经明确确认后生成获准未加密目标；转换之外的临时资源不因此放宽。 |
| 私有临时资源 | 有界、带期限、仅允许本次请求领取的加密导出／快照；进程异常遗留也不能成为明文账务副本。 |

已加密家庭的原金额、日期、分类和备注 Prisma 条件、SQL 聚合及排序须迁入解密后的业务层；未加密路径沿用现有查询并使用相同业务规则。公共分类定义和授权引用仍可数据库查询；两条路径都不能扫描其他家庭后再在内存过滤，也不能因提前分页漏掉符合条件的记录。历史成员及归档账本遵循原查看范围，写入目标仍单独校验。

#### 请求与存储流转

客户端先固定原身份、账本、模式代次和 UUID，再按已确认加密状态自动附带本机密钥。服务端完成认证及范围校验后，从家庭配置确定真实模式，核验请求代次；加密路径打开对应家庭密钥包并验证密文格式和认证关联，未加密路径不借用其他请求的密钥。两者均校验规范金额／日期／分类和原请求一致性；原无效草稿行的 raw 字段及错误状态逐值保留，不能强转交易、修正或丢弃。加密路径缺失或无效密钥在业务受理前拒绝，不扣处理额度或写入半个草稿。

只读业务在一致快照内按模式分块读取、按需解密并计算，完整保留过滤、总数、排序、上海区间、成员及账本范围；资源预算限制中止时给出可重试失败，不能把不完整统计显示为完整结果。两种模式的导出都保持一致快照和结果领取复核；私有临时文件由本次有界执行的临时资源密钥保护，仅获准请求可在执行范围内打开。临时资源密钥与家庭解密上下文分开，未加密家庭不因此新增家庭码或长期共享解密秘密。

写业务在短事务内按原锁序复核账号、AppSession、成员、家庭、源／目标账本、当前模式／代次、所需密钥版本及租约；只在全部满足且无转换屏障时按受理模式保存数据、幂等结果及最小审计。结果领取／返回同样复核模式代次，不把旧任务改挂到新模式。加密随机材料不改变请求 UUID 或语义一致性，网络未知结果保留精确待确认快照；不能靠每次重新加密后的不同字节判定为新业务。

现有事务后 recordAppEvent 调用统一通过事件写入边界，在同家庭锁序内读取真实模式／代次，并核验可信来源的原业务上下文及所需密钥版本，不能信任调用者缓存的加密开关。加密业务 payload 只在当前请求仍有合法上下文时写入；否则仅尝试保存白名单通用事件，不缓存明文详情等待下一请求。手工、编辑／删除、自然语言、导入及页面事件均使用同一规则，审计失败不触发账务重试或覆盖已提交结果。事件新增和留存清理也与转换屏障协调，避免源核验后补入明文、丢失已接受事件或将已清理事件从目标恢复。

已受理任务可在当前有界执行中持钥，但排队任务、替换输入和新请求不能继承旧任务的密钥或同意。结束后停止访问、覆盖可控缓冲并释放引用，清理完成信号与真实解析／供应商终止一致；不得用全局缓存、跨会话解锁或外部共享密钥存储维持可用性。

#### 换钥发布与未知结果收敛

客户端先生成唯一轮换 UUID 和固定候选密钥包，在受保护本机状态及独立恢复副本中保存可恢复材料，并完成实际回读／解密校验。旧码、候选新码和操作信息仅在该原身份的本机保护边界或家庭保管的恢复副本中存在；临时恢复副本中的秘密也须加密保护，当前候选新码作为其解锁凭据，不额外引入个人秘密。

发布分为受保护的元数据准备和携钥提交。准备请求由当前有效负责人在 ENCRYPTED 稳定状态建立绑定原 AppSession、原成员、家庭、模式代次、预期旧版本、候选密文包摘要及有界期限的轮换回执；此时不激活新版本，也不保存密钥，并阻止同家庭开启／关闭竞争。客户端取得确定的准备回执后才上传本次旧／新解密材料。服务端在短事务内复核原身份、负责人角色、模式／代次、期限、预期版本及候选摘要，将密文密钥包、当前版本和已提交回执原子落库。同一 UUID 及同一候选只能提交一次，重复请求返回同一结果；候选变化则冲突，不能重开已结束操作。

断连或重启后，当前有效 AppSession 只可在原家庭和原成员身份范围内查询自己的轮换回执及当前版本，查询这类不含密钥的状态不要求先能解开新版本。已提交时须验证候选版本和密文包摘要、用新码回读已生效包后，才将新码设为本机当前值；仍在准备／处理期则保持待确认，可在原会话、期限和候选仍有效时重试同一提交。原会话结束后，新会话只能查询原操作，不重新授权旧在途提交；负责人需在原尝试明确未提交并终止后，才可显式发起新操作。

超时或取消只有在服务端将原回执收敛到明确未提交、并保证迟到请求不能再提交后，才允许放弃候选。回执缺失、摘要／版本不一致或状态无法确定都保留为未知，不凭“查不到”清除候选或推断失败。成功时还需确认新码及对应恢复包仍有可回读的独立副本；确认成功或明确未提交后，才清理不再需要的本机候选恢复状态。显式退出／身份结束仍清除本机可用密钥，后续只能由合法身份和家庭独立备份恢复，不扩大旧身份权限。

#### 跨密钥版本的备份恢复

每个保留恢复点的清单按家庭记录快照模式／代次、加密周期、格式及实际需要的包封密钥版本；备份系统可保存密文恢复包及其标识／摘要，但不能取得或保存家庭共享码。含密文的恢复点所需恢复包必须独立于在线数据库可取得，覆盖全部声明的历史周期／包封密钥，并用当前或关闭期间最近有效码认证加密。较新的同家庭恢复包只要经过完整性验证且覆盖快照所需版本，就能用于较旧恢复点，不强制依赖 dump 内由旧码保护的旧密钥包。未加密家庭的快照不虚构加密保护，也不能因同库其他家庭缺钥而误认为自身需解锁。

每次换码在发布前完成新恢复包的独立保存与回读验证，在恢复点清单中只登记为候选，不替换现有生效的恢复材料关系。确认轮换已提交且新包仍可独立回读后，再将其标记为当前可用包；明确未提交时清理候选也不能破坏原恢复点。旧备份的数据正文无需因此重写，不能通过仅保留在线库的新包来维持可恢复性；只要还有保留恢复点依赖某版包封密钥，就不能从当前恢复包中删除该版历史密钥。

含密文的恢复点以当前或关闭期间最近有效码、覆盖旧版本的独立密文恢复包、原备份及其摘要／配置作为规定灾备材料；这不要求永久保留历代旧码，也不把旧主密钥交给维护者托管。在线轮换使用的临时候选恢复副本与长期灾备恢复包分开：前者可能含旧／新候选主密钥，只在客户端／家庭自主保管的加密副本中存在，终态确认后清理；后者只包含由可用码保护的历代包封密钥及校验信息，不包含旧／新明文主密钥。

关闭加密前必须独立保存并回读验证最近有效码及恢复包，对仍保留的加密恢复点继续保持配套关系；关闭后不把这些材料存为服务端明文或随本机当前密钥一并销毁。再次开启时使用新码、新加密周期及新模式代次，通过最近有效码打开既有恢复包，将仍依赖的历史包封密钥并入新包，发布前独立核验，确认提交后才更新清单关系。若所需材料缺失，不能假定从当前明文库或新码恢复旧密钥；对应转换保持未完成并保留原可用数据，不自动放弃恢复点或删除旧备份。

恢复在空的隔离环境中先核实授权范围和材料一致性，逐家庭按源／目标模式回读比较交易、导入来源和结果摘要及原恢复点计数／内容证据。含密文的源或目标才要求相应客户端临时解密材料，验证恢复包绑定、格式、周期及版本覆盖并实际解密，不要求未加密源／目标提供家庭码。仅 pg_restore 成功、文件可读或数据行数相同不能标为账务恢复成功。恢复目标采用经核验的当前家庭模式／密钥配置，仍须落实备份后的撤销、停用和已确认删除，不凭旧备份的负责人／会话状态自行恢复授权。

恢复目标的当前保护方式与快照当时模式分别核验。旧未加密快照恢复到当前已加密家庭时，先在隔离环境完成加密转换及核验再开放，不能直接恢复旧模式造成降级；旧加密快照恢复到已明确选择未加密的目标仍须先提供合法解密材料并验证范围，不能靠目标开关绕过。关闭期间的加密恢复使用最近有效码及其独立恢复包，重新开启后使用覆盖所需历史版本的新包。

恢复密文所需的恢复包缺失、可用码无法打开它、版本覆盖不足或材料属于其他家庭时，保留源备份和隔离目标，停止对应解密恢复并准确说明缺失材料；不自动丢弃家庭、忽略无法解密记录或使用维护者密钥补齐。演练必须在在线数据库、当前客户端缓存均不可用的条件下，只使用上述规定材料证明可恢复。

#### 家庭转换、存量迁移与切换

应用升级只为既有家庭建立明确的 UNENCRYPTED 配置和初始代次，保留全部原数据及会话，不因家庭未准备密钥或已关闭而强制转换／恢复身份。后续家庭显式开启、关闭分别预检当前有效负责人、源模式／代次、数据关系及本次密钥与恢复包准备；独立换钥不走这条全量数据转换流程。

家庭转换先在统一锁序内建立屏障，拒绝新写入／资源任务，等待已正式受理的原任务实际完成或安全终止，再取得源视图一致快照及核验基线。不替未携钥的旧任务借钥，也不把旧加密任务改成明文写入；模式代次和屏障阻止迟到提交／领取。转换中读源视图仍校验原身份、所需密钥及快照一致性，其他家庭照常服务。

服务端以受保护的有界批次将源视图转换到隔离目标，持久化不含密钥／业务原文的进度，按方向保存目标正文；批次绑定建立屏障后的当前转换代次，源视图保留原加密周期及修订。恢复批次必须重新取得合法请求和所需客户端密钥，不能从队列或 session 恢复解锁。原请求会话失效后只能查询原尝试，先保证它已终止且迟到请求不能提交，才能以新受理请求复核授权及源修订后复用已核验的转换进度；不得给旧在途请求续权。

转换覆盖全部原字段及历史来源，包括留存 AppEvent 的原业务 summary 和完整 metadata，逐批按源／目标模式回读、按需解密后与原值比较，同时校验各表计数、原 ID／引用、家庭／成员／上海月份／收支／软删除分组摘要、导入去重与退款关系、旧 UUID 结果及事件行数／留存语义。原输入摘要、sourceFingerprint、已完成结果和原事件业务字段按目标模式保存原内容，不重新哈希、解析或重算；加密发布前清除当前生效事件列中的原明文业务值，原内容保留在家庭密文 payload 中。核验记录只保留必要计数、受保护摘要和 pass/fail，不输出账号、密钥、原始行或真实入口。

批次重试和进程中断不得产生重复交易、重复草稿或半个有效家庭；暂存状态不对普通业务开放。所需密钥／恢复包未验证、无合法负责人、家庭关闭或身份关系异常只阻止对应的显式转换／解密恢复，不阻止其他未加密家庭正常升级使用；不猜测归属、不代设维护者密钥，也不通过恢复旧身份绕过现有停用／关闭规则。只能按已核实本人／原负责人及具体范围的受控流程解决后继续对应目标。

完整源／目标内容、索引、历史引用、所需恢复包和目标备份实际恢复均通过后，在短事务中复核原 AppSession、成员及负责人、家庭／账本状态、操作预期的转换状态／代次、源修订及目标核验版本，原子发布整个目标视图、新模式代次和成功回执。结果未知先查原操作，不重建候选；明确未提交时终止所有批次，隔离清理目标并确认无迟到提交后才解除屏障。关闭失败已生成的明文副本仍须盘点，不因业务回到源模式而忽略。

开启成功的家庭拒绝旧客户端明文协议；未加密家庭的旧兼容请求仅按已核验源模式受理，并在最终写入复核配置代次，不能在切换后继续提交。两种模式都不按缺钥或客户端声称模式自动切换。浏览器原草稿按当前模式升级，同一身份和 UUID、原默认账本识别保持；缺少旧码时不丢弃原密文草稿或将待确认 UUID 当成未提交，也不自动重发。

涉及物理明文副本替换的正式维护仍须预先完成私有隔离恢复演练，收敛所有数据库写入者与在途任务，取得最终一致快照及私有备份，在干净的新 PostgreSQL 17 卷按各家庭模式恢复并全量比较，不执行 seed。未加密家庭继续保留获准明文；已加密家庭只能写入密文及允许元数据。新库／备份实际恢复、同一已验证版本私有 smoke 和原身份检查通过后才切换实例；单家庭锁不能替代实例维护停写。

新库、新卷和新备份不自动处理旧库行版本、WAL、旧快照或导出。逐项核实需保留恢复点的密文替代与恢复能力后，按已授权清单处置已知明文副本；未处理、不可核验或供应商侧历史保留单独记录，不能宣称普通文件删除等于介质不可恢复。

切换前失败保持目标隔离，原库和备份只按已核实恢复范围使用；不得先清空原库证明迁移。模式／实例切换后接受新写入，失败处理须保全并核验最新数据，优先向前修复；任何回退不能用旧快照覆盖新增账目、复活旧会话或恢复已确认删除的数据。家庭当前视图加密不等于底层已无旧明文；副本处理完成前，只能按具体已验证范围报告静态保护已生效，不能承诺点击开关即可清除旧存储。

## 验收

- 新建家庭、旧版本升级及同库混合家庭 → 默认未加密且无需先准备密钥，原账务／会话保持，未加密家庭照常使用；各家庭状态准确且不相互借钥或降级；升级、混合模式及端到端证据。
- 开启、关闭及独立换钥权限 → 仅当前有效负责人作用于整个家庭及全部账本；普通成员、OPS、失效身份和客户端伪造模式均不能切换；权限与并发回归证据。
- 家庭首次开启 → 先保存并回读验证新码／恢复包，全部交易、软删、草稿、映射、退款及旧结果保持原值，核验后才整体切为加密；其他家庭正常，旧明文副本范围准确披露；基线对照、存储检查及端到端证据。
- 关闭加密 → 当前有效码和明确确认缺一不可，缺失／错误／跨家庭码不能受理；确认后隔离目标可生成明文，完整核验及原子发布后才开放未加密业务；旧加密备份不被删除；授权、转换及存储证据。
- 转换中查询、在途导入／AI／语音／导出及换钥竞争 → 完整源视图只读、目标不可见，新任务暂停，原任务真实完成或终止后取快照；迟到提交／领取不能跨模式，开关与换钥互斥；并发、取消和一致快照证据。
- 转换中断、丢响应、崩溃、原会话到期或负责人失效 → 查询同一操作确认唯一终态，未知时保留候选；续作重新核验且不恢复旧请求授权，明确未提交须阻断迟到批次，源数据保留；故障注入及恢复证据。
- 旧客户端／离线草稿／在途请求跨模式代次或再次开启 → 不跟随客户端开关自动降级、不把旧任务改挂新模式，不重用旧密钥／配置代次或重发 UUID；旧兼容请求也执行最终代次复核；协议及跨周期回归证据。
- 关闭后再次开启 → 日常未加密请求不携旧码，新开启使用全新密钥，仍保留的加密恢复点所需历史密钥纳入新包并验证；缺失材料时不完成对应转换、不丢失当前账务或自动放弃备份；浏览器／App、备份清单与恢复证据。
- 中止关闭及恢复不同模式的旧快照 → 中止不掩盖已产生明文副本；旧明文快照不能直接降级当前加密家庭，旧密文不能因目标未加密而绕过解锁，恢复仍落实后续撤销／删除；隔离恢复及失败证据。
- 家庭负责人建立随机共享码，普通成员导入并使用 → 不新增个人解锁密码、设备审批或服务端密钥托管；浏览器／App 流程及角色越权回归证据。
- 已加密家庭在服务端冷启动，仅有数据库、配置及有效登录态 → 无客户端解密材料不能读写账务，账号自助仍可用；未加密家庭不被错误要求导入密钥；集成与端到端证据。
- 已加密家庭同一成员多请求、同家庭不同成员并发 → 一个请求的密钥不解锁另一个请求或会话，缺钥／错误／其他家庭密钥不产生业务副作用或部分扣额；并发、隔离及资源用量证据。
- 正常结束、错误、取消、超时、断连及进程退出 → 请求解密上下文不进入可复用缓存；已正式受理且允许继续的原任务不因断连提前丢钥，在原期限内真实收敛后清理，解析／供应商停止前不提前释放占用；恢复后不从持久状态找回密钥；生命周期和故障注入证据。
- 在途提交期间退出、移除、停用、关闭家庭或 OPS 撤销 → 原身份及租约最终复核阻止迟到写入／领取，其他家庭正常；集成竞态及端到端证据。
- 可信设备关闭重开、同身份会话到期、退出、切换账号及重新加入 → 正常重开自动取用，过期先重登录，原 UUID 依原身份恢复；退出／身份改变清除可用密钥，旧响应不复活现场；浏览器及 Android 真机证据。
- 家庭码备份／本机二维码导入 → 密钥不出现在 URL、Cookie、初始／SSR HTML、隐藏字段、数据属性、日志、诊断或二维码网络请求中，拒绝摄像头仍可粘贴；网络与存储检查、权限回归证据。
- 负责人独立换钥 → 始终保持 ENCRYPTED，不经关闭／开启或落地明文；新码读取获准历史，新写入及新修订使用新版本，旧版本新请求被拒绝，在途竞态不部分入账；普通成员换钥被拒绝；集成、存储检查及端到端证据。
- 换钥发布前本机保存失败、独立备份取消／损坏或回读不符 → 新版本不激活；仅会话模式也必须先验证独立恢复副本，否则禁用发布；存储失败与客户端流程证据。
- 换钥提交后丢响应、客户端崩溃／重开、原会话到期、同 UUID 重试及回执异常 → 使用受保护候选状态或独立副本恢复，先查询原操作并验证唯一生效版本；提交最多一次，未知状态不清候选、不生成新码重试，明确未提交后迟到请求不能提交；故障注入、并发与端到端证据。
- 成员退出但家庭未换钥 → 账号在线访问被撤销，其余成员不被强制换钥或停写；已持旧码的固有限制在隐私说明中准确呈现；行为及文案检查。
- 无码且所有客户端解锁能力丢失 → 不存在维护者、密码重置、邀请或 OPS 代解锁入口；恢复失败流程及安全审查证据。
- 已加密家庭的交易、草稿、映射、退款来源、旧摘要／结果、账本名称及 AppEvent 业务 payload → 当前生效数据库视图及相应备份中仅有密文／允许元数据；金额、日期、分类关联、sourceFingerprint、输入摘要或原业务事件内容不以原值藏在索引和日志，历史明文副本另行盘点；按家庭及代次的合成金丝雀扫描与数据库检查证据。
- 含现有 AppEvent 的家庭开启、关闭及再次开启 → 原 summary／完整 metadata 可按授权回读且逐值一致，ID、时间、类型、归属及事件行数保持，已清理事件不复活；开启后收支方向、来源及业务笔数不留在明文事件列或 OPS 摘要；转换、备份恢复和金丝雀扫描证据。
- 业务已提交后事件跨代次／期限迟到，或遇到换钥、转换屏障、加密路径密钥不可用及事件写入失败 → 仅尝试最小通用事件，无明文队列／日志和跨请求借钥；原 UUID 结果仍为成功，不要求补钥重做或重复入账，事件及留存写入不能破坏转换核验；并发、故障注入及结果一致性证据。
- OPS 查看已加密／转换中家庭及无家庭登录事件 → 仅获准最小元数据和通用标签，今日／七日仍按事件行数统计，不解密 payload 或从其他实体补出业务值；稳定未加密行为、AppEvent 90 天规则及独立安全审计不受破坏；OPS 权限、展示、统计及留存回归证据。
- 篡改 nonce、认证标签、家庭／实体／账本／成员关联、修订或密钥版本 → 解密失败或拒绝更新，跨家庭密文无法复用；标准向量、篡改与权限测试证据。
- 手工、文字、语音和导入重试／查询原 UUID → 保留原请求一致性、目标账本及已完成摘要，不因随机加密、编辑、换钥或网络未知结果重复入账；旧格式与跨账本回归证据。
- 两种模式的列表／搜索／筛选／排序／报表／钻取及 Excel 对照基线 → 有效／软删除、归档账本、历史成员、上海日期和整数分结果一致，不存在提前分页造成的漏计；合成明文基线对照和集成证据。
- 支持来源的导入、映射、同源去重、退款和大草稿确认 → 原格式、成员归属、批量事务及去重边界保持，无原始账单持久化旁路；parser／集成／端到端证据。
- Excel 导出 → 一致快照、同家庭及日期范围、历史成员／归档账本、可见字段和精确整数分保持，私有临时资源不留明文，领取复核及异常清理通过；文件内容、权限及故障恢复证据。
- AI／语音选择关闭、已受理后关闭、排队新输入及转写延续 → 原同意和固定 UUID／身份／账本／摘要规则保持，家庭密钥及历史账目不进供应商请求；协议、供应商桩和真实边界核验证据。
- 原有容量边界 → 20 MiB／2 万业务行导入、受限 XLSX／PDF 解析、10 万行／32 MiB 成品导出及现有资源窗口保持；加密与内存计算下完成容量和取消验证，不静默降低上限或输出截断统计。
- 合成旧库含软删、完成／未完成草稿、退款、旧 UUID、历史身份及各种会话状态 → 默认未加密升级保留原值，显式双向转换后的原字段、关系、金额／笔数分组及结果等值，重跑／中断可恢复；专用转换与实际恢复演练证据。
- 显式转换目标缺失所需密钥／合法负责人、已关闭家庭或异常关联 → 对应转换拒绝并保留源数据，不代设密钥、猜测归属或恢复权限，不阻塞其他未加密家庭升级；合成失败用例与维护预检证据。
- 物理明文副本替换的正式切换 → 全实例写入者已收敛，干净新 PostgreSQL 17 卷按各家庭已确认模式保存，可恢复备份、同一已推送版本和私有 smoke 均已核验；旧明文副本清单及未处理范围明确，单家庭逻辑转换不被误报为底层已无明文；维护演练及核验记录证据。
- 备份后至少换钥一次，在线库和客户端缓存均丢失 → 仅用原备份、当前共享码、覆盖旧密钥版本的独立密文恢复包及规定摘要／配置，在空环境恢复并实际解密全部目标账务、来源和旧结果；恢复点清单及跨版本隔离演练证据。
- 跨版本恢复缺失／损坏密文恢复包、错误共享码、版本不足或跨家庭材料 → 不标记恢复完成，不丢弃无法解密记录或代设维护者密钥，源备份保留且目标继续隔离；失败用例及多家庭范围验证证据。
- 新版接受写入后回退 → 最新交易、撤销、停用和已确认删除结果均保全，不恢复旧快照覆盖；隔离演练证据。
- 家庭密钥不在服务端持久化及已加密范围不落明文的承诺 → 实际 HTTPS 终止及转发服务、应用日志、追踪、崩溃／堆转储、临时目录、镜像、备份和客户端存储逐项核验，准确区分未加密家庭和已盘点旧副本；无法核验的边界列为对应保护声明与上线阻塞，不能仅凭源码声明通过。
- 交付 → 应用和运行配置改动通过 npm run lint、npm run test:unit、npm run test:integration、npm run test:e2e 及适用 Android／容量／迁移验证，完成仓库安全审查、版本与 Git／发布收尾；仅 spec 审阅不构成这些运行证据。
