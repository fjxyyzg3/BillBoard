# AI 对账分组与多选保留

## 目标

把人工去重从“选择参与记录、指定单个保留项、逐组确认”改为按组查看疑似重复账单、直接勾选需要保留的记录，再统一预览和应用，减少来回选择的操作。

本规格以[现有 AI 对账](../wiki/ai-bill-analysis.md)和[独立页面与人工核对规格](2026-11-05-ai-reconciliation-workspace.md)为基线，替换其中人工分组、单项保留和逐组确认的交互。原 AI 可应用建议、退款／报销抵扣、扫描及后台生命周期继续沿用。

## 决策基线

### 需求决策

1. **分组范围。** 在当前报告每条 `kind: notice` 的关联提示内，按同账本、同原归属成员、同收支方向、同整数分金额细分。不同提示不合并，不把全量账目按金额重新找重复，不读取报告外或期外记录。分类、来源、备注及日期差异不再拆组；分组只是人工核对的候选范围，不证明这些记录属于同一笔交易。
2. **排序与默认项。** 组内按交易时间从早到晚；组与组也按各组最早交易时间从早到晚排列。时间相同使用任务内 ref 的数字序稳定排序，组间仍相同时再按提示 ID 和组键固定顺序。日期与展示统一为 `Asia/Shanghai`；日级、补齐及未知精度标签沿用，不把补齐时间显示为精确时刻。每个可操作组首次初始化只勾选排序后的第一笔，不优先挑信息最多或来源更完整的记录。
3. **勾选含义。** 复选框统一表示“保留此笔”。一组可勾选多笔，但至少保留一笔；未勾选的记录明确显示“待删除”，实际应用时软删除。全选保留表示跳过该组，不改账、不占用成功处理记录，也不创建空操作回执。不足两笔可操作记录的候选只展示，不产生默认去重动作。
4. **统一确认。** 人工组直接展示记录与保留复选框，不再要求选择参与记录、单独选择保留项、勾选“同一笔重复记账”或逐组加入选集。所有有效组的默认选择直接进入待应用预览，未调整的组也按默认选择处理。用户最后点击一次“应用”确认整个选集；打开报告、初始化默认项或调整勾选均不改账。
5. **预览与改账。** 每组展示保留与待删除数量，整体展示本次删除数量、金额变化及原有整体／分日／分月预览。应用前明确说明未调整的组也会处理。保留项的原 ID、金额、日期、分类、成员、创建者、备注、来源、指纹及 UUID 均不变，不合并字段、不执行人工抵扣；软删除继续参与同源导入去重。
6. **冲突与失效。** 同一记录不能同时参加两个有删除动作的人工组，或人工组和已勾选 AI 建议；保留项也属于参加记录。冲突必须提示并阻止提交，不能静默抢占、合并或取消选择。用户可将某组设为全部保留，或取消相交的 AI 建议。已处理、归档、重扫及快照变化继续受原限制；任何参与记录失效均整批零改账。
7. **状态与兼容。** 草稿仍绑定当前身份、报告 ID 与成功代次，仅存浏览器应用内存。同代次重渲染、轮询和切页返回不得覆盖人工勾选；刷新或关闭应用后重新初始化，成功换代清除旧草稿。已提交选集及 UUID 冻结，结果未知只查询原 UUID。合法旧对账报告可直接启用新交互，不要求重新扫描或新的 AI 调用；旧分析报告仍只读。
8. **界面边界。** 保持移动优先、中英文同步。每组同时展示账本、成员、方向、金额、记录时间及原有分类／来源／备注，保留提示理由。所有复选框、禁用原因及应用结果具备可访问名称与反馈；长记录列表不遮挡最终应用入口。

### 技术决策

- 继续使用现有 React 对账组件、共享控制器、确定性预览和 `POST /api/reports/reconcile`。分组由报告公开记录及提示引用确定，不解析 AI 自然语言、不调整模型协议或调用预算。
- 保持 AI 报告正文 v1、数据库实体及财务恢复包 v3 的实体集合。新增应用协议 v3，以 `keepRefs` 表达多个明确保留项；原 v1／v2 输入、摘要、回执和查询关闭标记按原规则处理，不补字段后重算，也不批量转换历史载荷。
- 新人工组完整携带候选 `refs` 与保留子集，服务端从原报告断言解析真实交易，重核提示来源、同向等额、同账本／原成员、记录可写与未处理状态。客户端不提交真实交易 ID、金额或数据库补丁。新旧人工动作不调用自动挑保留项的 `canonicalRefs`。
- 复用家庭优先锁序、有效账号／成员／会话复核、来源依赖校验、分块更新、最小审计及原子回执。新协议纳入现有受保护载荷、换钥、局部处理投影和恢复校验；不新增明文财务索引、数据库迁移或依赖。
- 沿用 16 KiB 应用正文、单个人工组最多 500 笔、AI 建议与有操作的人工组合计最多 200 项、合计最多 1,000 笔不同参与记录，以及每代成功回执最多 200 笔／解密后 JSON 合计 1 MiB 等既有限制。超限明确拒绝，不截断、静默拆组、多请求分批提交或扩大预算。

## 设计视图

### 功能设计

报告继续分开呈现原 AI 可应用建议与人工关联提示。人工区汇集各提示产生的候选组，按已确认的组间规则排序，每组保留所属提示的理由和稳定身份。不同提示即使条件相同也分别展示；相交记录引起的选择冲突在组旁和汇总区说明。单条记录及不可操作记录作为证据保留展示，不出现暗示可以删除的禁用选择。

人工区首次加载时，可用候选中至少两笔组成一组，第一笔勾选“保留”，其余显示“待删除”。复选框旁就地展示完整记录信息，不再复制一份单选保留列表。用户勾选另一笔会增加保留项；取消某项会将其加入待删除，保留项为零时显示错误并禁用应用。将一组设为全部保留即可跳过该组；界面须为跳过冲突或失效组提供可用操作，不能因禁用了记录控件而无法跳过。

例如同组有 08:30、08:31、08:33 的三笔 20 元支出，初始只保留 08:30，预览删除两笔、支出减少 40 元。再勾选 08:33 后保留两笔，预览只删除 08:31、支出减少 20 元。三笔全选后，该组不参与本次应用。

预览随选择更新，同时包括勾选的原 AI 建议。汇总区明确展示参与组数、保留／待删除笔数、金额影响和“未调整的组将按默认选择处理”的说明，最终“应用”是唯一改账确认。没有任何人工删除或已选 AI 建议时禁用应用，不发送空请求。人工去重支出或收入都会改变结余，不沿用退款抵扣的“完整选集结余不变”说明。

报告已知的已处理／归档记录显示具体状态，不进入新初始化的可操作候选；剩余可用记录不足两笔时只展示。已有草稿因状态更新失效时不自动缩小参与范围、重选第一笔或重解释删除决定，须保留受影响状态并提示跳过该组或重新核对。成功后只把实际提交组的全部参与记录标为已处理，父提示不整体完成，全选保留的组仍可后续处理。

提交期间冻结本次选集，禁止勾选变化产生替换请求。成功刷新账目与处理状态；明确拒绝时保留可解释的草稿，冲突要求重新核对或扫描；未知结果沿用原核验入口。切换范围只切换各报告的内存草稿，不把旧 ref 套到新报告；重新扫描成功后明确提示旧选择已清除。

### 技术设计

#### 整体方案

分组纯函数接收当前报告提示、公开记录和可用状态，按 `noticeId + ledgerAlias + memberAlias + type + amountFen` 建立稳定组键。记录排序比较实际 `occurredAt` 与数字 ref，分组身份不包含排序位置或当前勾选内容。界面用公开别名分组，服务端用断言中的真实账本／原成员 ID 重新校验，别名不是授权依据。

共享控制器以原 `reportId/generation` 保存人工候选及 `keepRefs`，首次激活时生成默认项；后续读取已有草稿。状态刷新不重建用户选择，已知不可用记录与新失效草稿按功能设计分别处理。分组超出单组容量时保留整组展示并标为不能应用，允许全部保留以跳过；用户可缩小扫描范围重新生成，不自动截取前 500 笔。

序列化选集时忽略全部保留的组，对其他组做完整校验和确定性规范化。客户端预览与服务端共用“`keepRefs` 中为 keep、其余为 delete”的纯函数；人工金额使用原 `amountFen`。整批动作在任务 ref 和真实交易 ID 两层拒绝重叠；服务端重新计算最终预览，不信任客户端合计。

#### 关键结构

| 对象 | 约定 |
| --- | --- |
| v3 应用输入 | `{ version: 3, requestId, reportId, generation, suggestionIds, manualGroups }`；至少一个 AI 建议或有删除动作的人工组。纯 AI 提交仍可沿用 v1。 |
| v3 人工组 | `{ noticeId, refs, keepRefs }`。`refs` 为同一提示中的 2～500 个不同引用，`keepRefs` 为其中非空、无重复的真子集；每个参与引用均为 keep 或 delete。全保留组只存在于客户端草稿，不发送；服务端拒绝 v3 空操作组。 |
| 输入摘要 | 显式包含版本、用途、报告、代次、排序后的 AI 建议 ID、人工组的提示及排序后的 `refs/keepRefs`。集合顺序变化不改摘要，保留集合或分组变化必须改摘要；重复、未知或重叠引用拒绝，不经去重悄悄修正。v1／v2 原摘要构造保持。 |
| v3 受保护事实 | 沿用应用实体，保存版本、原输入摘要、终态、预览、参与真实交易 IDs、抵扣消费 IDs，以及每组引用／真实交易映射、`keepTransactionIds` 和 `deletedTransactionIds`。保留与删除集合必须无交集且完整覆盖该组。 |
| 公开回执 | 新成功结果带 `version: 3` 及对应 `manualGroups`，不返回真实交易映射。明确业务拒绝、未知及查询关闭继续遵守原终态协议，不能把访问失败伪装成已保存业务终态。 |
| 已处理与抵扣 | v3 成功人工组的全部 `refs`（包括每个保留项）投影为该代次已处理；跳过组不参与投影。新协议的 `consumedIncomeIds` 只来自真实 AI 抵扣，不把人工删除重复收入计为抵扣，v1／v2 历史事实不重写。 |
| 历史与恢复 | v1／v2 仍由原解析规则读取，v3 校验多保留项及真实映射。恢复时核验保存时的事实与家庭历史引用，不按交易后来的金额、移账、归档或报告换代重算人工决定。原恢复包版本与实体证明规则保持。 |

协议不要求提交组必须等于提示内所有同条件记录，保留旧手工客户端选择子集的安全边界；新界面按自动分组提交完整候选。所有被提交引用仍须来自指定提示并满足同向等额与授权约束，不因公开分组键或客户端保留列表放宽。

#### 实现流程

1. 读取已授权报告与局部处理状态；对合法 v1 对账正文直接生成候选组并激活内存草稿，无新扫描或供应商调用。旧分析正文仍走原只读视图。
2. 人工勾选更新对应组的保留集合，共用预览函数生成 keep／delete 动作，与所选 AI 动作合并。前端说明零保留、重叠、不可用及数量／正文超限；跳过组不占应用预算。
3. 点击应用后固定原身份、报告、代次、UUID 和规范化选集，冻结草稿。普通本机持久化仍只保存身份绑定的非财务核验指针，不保存分组、保留项、理由、金额或家庭码。
4. 服务端按版本解析输入与摘要，沿原锁序核验授权、账本及报告；相同 UUID 先返回原稳定终态，输入不同则冲突，不覆盖已有回执。新应用批量核验全部参与记录、来源依赖、已处理事实及范围，保留项也须核验。
5. 确定性生成混合动作与最终预览，检查现有回执读取和新增写入容量；全部通过后在同一短事务中分块软删除、写最小审计和 v3 受保护回执。人工保留项不写入，金额和其他字段不拼接；任一失败整批零改账。
6. 回执查询、报告局部状态、受保护转换／换钥与隔离恢复分别按 v1／v2／v3 解析，不用新默认选项补齐历史字段。成功更新当前报告实际参与状态；结果未知仅查询原 UUID，不重复执行或自动提交其余组。

## 验收

- 单条提示含多金额／方向／账本／历史成员、不同来源／分类／备注或跨日期记录 → 只按已确认四个条件在原提示内分组，组内时间升序，组间按最早时间升序；不足两笔只展示；纯函数及移动端浏览器验证。
- 不同提示的同条件记录、相同时间和 `r2/r10` 引用、日级／补齐／未知精度 → 不跨提示合并，时间相同时按数字 ref 稳定排序，精度标签真实；重复渲染和中文／英文组件验证。
- 打开含多组的合法旧报告 → 所有可操作组默认只勾选第一笔，默认选集立即预览；未调整组也进入最终确认说明，打开和勾选过程零写入、零新增 AI 调用；浏览器与服务验证。
- 三笔等额支出分别保留一笔、两笔、全部及零笔 → 前三种依次删除两笔、一笔、零笔，零笔保留阻止提交；收入去重同步正确减少收入与结余；纯函数、真实数据库和预览一致性验证。
- 全部人工组都全选保留且无 AI 建议 → 应用禁用、无请求及空回执；与有效 AI 建议混合时只提交实际动作；控制器与接口验证。
- 同一记录出现在两条提示或已选 AI 建议中 → 相交的活动选集明确冲突并阻止提交，将某组全部保留或取消相交 AI 项后可提交；保留项同样不能重复参与；客户端和服务端验证。
- 已知已处理／归档记录及后续轮询使草稿失效 → 初始化排除已知不可用记录但保留展示，已有选择不被自动重设或缩小，失效组可跳过或重新核对；轮询、共享成员及浏览器验证。
- 调整多保留项后切页、切月份／账本／成员再返回 → 同代次草稿保留且不会误套引用；刷新／关闭后不从普通本机存储恢复财务选择，成功换代清旧草稿；控制器、浏览器和存储检查。
- 缺少保留项、保留项不在组内、重复／未知 ref、伪造提示、跨家庭／账本／原成员、异向／异额、归档或已软删除 → 服务端拒绝且零改账，不依赖 UI 限制；协议及真实数据库越权验证。
- 单组超 500、总项超 200、请求超 16 KiB 或回执预算超限 → 明确受控拒绝，保留完整草稿和既有报告可读，不截断、自动拆组或部分提交；真实可达容量使用合法报告正文预算内的夹具验证，不承诺各维度上限同时可达。
- 请求声称参与超过 1,000 笔或包含报告中不存在的引用 → 协议／伪造请求验证拒绝且零改账；不向数据库注入超过正文或记录上限的报告，不把不可达的选集称为真实流程容量证据。
- 一组有多个保留项且另一组全保留，应用后再次查看／重开 → 实际参与组全部成员均标为已处理，全保留组可继续核对，父提示不整条完成，保留项原字段未改；服务、局部状态及数据库验证。
- 混合 AI 与人工选集、任一记录编辑／移动／删除、来源依赖变化、会话撤销或身份失效 → 统一锁内拒绝，零部分改账／审计；正常提交的整体、分日／分月预览与实际一致；事务、并发和授权回归验证。
