# ACP Agent 辅助导入分类映射

## 目标

在账单导入时由 Codex CLI 为尚未选择的分类映射组生成建议，减少重复选择分类的工作。用户检查或修改预填结果后保存，再按原流程复核、确认入账。

## 决策基线

### 需求边界

- 入口为现有 `/records/import` 分类映射区域，支持随手记、微信支付、支付宝和招商银行账单。沿用实际来源解析器生成的 mapping key；支付宝仍以交易分类聚合，不把其交易对方加入 mapping key。
- 用户点击“智能推荐”触发，只处理当前表单尚未选择且草稿仍待映射的分组。已保存的实际分类／忽略规则和用户手动选择优先，推荐期间的新选择也不能被迟到结果覆盖。
- Agent 可以建议现有分类或“忽略”；不确定时留空。三种结果必须显式区分，空值／缺项／解析失败不能当成忽略。
- 预填不写共享规则、草稿决定或交易。只有用户点击原“保存映射”才按现有事务更新草稿和家庭共享规则；“确认导入”继续单独执行。
- 发送给模型的信息限定为本次草稿的来源、收支类型、映射组原分类／商户或交易对方、每组少量商品描述和现有启用分类清单。允许上述内容经 Codex 发送到其配置的模型服务。原始文件、原始备注、金额、日期、成员身份、账号、订单号、来源指纹和历史账本不作为输入。
- 推荐失败、超时、服务繁忙或未登录时，保留已有表单选择，显示中英文可操作提示，允许重试和手动映射。成功批次可以继续保留，无法判断的组保持空白。
- 不改变现有成员归属、退款、重复判断、单条跳过、金额整数分、上海时区和家庭隔离规则。不增加分类、聊天页或多供应商管理界面。

### 技术决策

- 首期使用 Codex CLI，通过 ACP 连接；优先采用固定版本的 `@agentclientprotocol/codex-acp` 适配器和 ACP SDK。适配器在内部连接 Codex app-server，应用不将普通 CLI 文本输出当成 ACP。
- 独立 `import-agent` 容器与应用共同部署，通过 Compose 内部网络提供受限分类接口，不发布主机端口、不接入 nginx/frp。容器使用专用 Codex 配置／认证卷和工作目录，不挂载用户 HOME、仓库、数据库或 Docker socket，不接收数据库／应用会话凭据。
- BillBoard 负责有效 AppSession、家庭成员和草稿权限、允许发送的数据提取、推荐目标和分类类型校验。Agent 容器只获得匿名任务内 group/category ID 和明确允许的字段；共享随机内部 token 只认证应用到容器，不传给 CLI。
- 每个分类批次新建 ACP 会话及 CLI 进程，限定批次和输入／输出长度、并发、请求时限；完成、失败、取消或超时均回收进程。无工具能力的客户端拒绝权限请求，Codex 使用受限模式与专用运行环境；不依赖 prompt 作为数据访问边界。
- 应用和 Agent 通信的结果使用显式 `map`、`ignore`、`uncertain` 判别字段。只有目标组存在且分类启用、类型匹配的结果才可预填；重复组、未知目标或格式异常拒绝该批次。结果返回时再次核对草稿状态、共享规则与可用分类。
- 建议保留在当前表单，不新增业务数据库表或历史聊天功能。按有界批次逐步推荐，客户端只合并仍为空的组；推荐生成与映射保存复用现有业务边界。
- 专用认证和实际模型调用必须在发布验收中单独验证；不能用模拟响应替代真实 ACP 连通性和 Codex 分类证据。

## 设计视图

### 功能设计

映射表单展示“智能推荐”和简短数据范围说明。触发时捕获待处理的空白组，分批提交并展示进度。用户可以继续修改分类，返回的建议只填入仍未选择的组；每批返回后分类／忽略选择与手工选择一起由原保存按钮提交。无法判断与无建议都保留空白。已有忽略组继续通过原控件编辑，但不被 Agent 自动重新判断。

已完成草稿不提供推荐。服务端拒绝伪造草稿、来源、分组、越权家庭和不合法分类。草稿在处理过程中完成或分组规则被其他页面修改时，迟到的建议不改变这些结果。错误提示不包含 CLI 输出、模型原文或私有配置。

### 技术设计

#### 整体方案

`ImportCategoryMappingForm` 调用独立推荐 server action。服务层从 session 和数据库构造白名单输入，用任务内 ID 替代真实家庭、草稿和分类标识，通过带 token 的内部 HTTP 请求交给独立 Agent 服务。

Agent 服务校验协议与容量，建立 ACP 连接、初始化和创建新会话，发送固定分类指令及数据，收集最终文本并验证结构化结果，随后销毁运行进程。模型只需在给定分类中选择或显式建议忽略／无法判断。服务层将任务内 ID 映射回当前可用分组和分类，再回传表单。

分类建议服务不调用现有映射保存函数。保存仍由现有 `saveImportDraftMappings` 负责授权、分组存在性、分类匹配、草稿锁和事务。Agent 不直接读取或修改数据库。

#### 关键结构

- 内部请求：协议版本、匿名分组列表、匿名候选分类列表；每组含来源、收支、原主／子分类和至多三条长度受限的商品描述。仅从现有解析后的“商品”字段提取描述，不把完整 note 或 raw 字段发出。
- 内部响应：每项包含 groupId 和 action；只有 `map` 携带 categoryId，`ignore` 和 `uncertain` 不携带分类。遗漏组按无法判断处理。
- 页面响应：映射键和实际分类 ID／明确忽略结果；错误为固定代码。建议清单不持久化到浏览器存储或分析日志。
- 容器配置：内部 URL/token、专用 Codex 认证位置、可选模型和推理强度；所有真实值只存私有环境或命名卷，示例仅使用占位值。

### 预估改动面

- `src/lib/imports/`：独立协议、最小化输入构建、结果验证、推荐业务服务；`src/app/(app)/records/import/`：独立推荐 action。

## 验收

- 四来源待映射组点击推荐 → 现有分类与忽略可预填，无法判断保持空白；单元、数据库集成及浏览器证据。
- 生成建议与用户保存分开 → 推荐前后数据库规则、草稿决定和交易相同，保存后按现有逻辑生效，后续草稿复用；数据库快照与 e2e。
- 已保存／已忽略规则、手动选择、推荐期间的新选择 → 都不被覆盖；纯逻辑、集成与延迟响应浏览器测试。
- 同源退款、重复、手动跳过和成员映射 → 推荐仅处理可映射组，既有保护与确认流程回归通过；导入完整测试。
- 恶意客户端或 Agent 返回越权／不存在组、分类停用、类型不符、重复项、把空值当忽略 → 拒绝且无写入；协议与数据库集成测试。
- 输入带原始备注、金额、成员、指纹、账号或超长内容 → 出站只有已批准字段且有数量／长度上限；捕获真实 HTTP 请求验证。
- 超时、退出、拒绝、非法 JSON、服务繁忙或登录失效 → 进程有界回收，界面不丢选择，可继续手动映射；模拟进程／网络边界及 e2e。
- 容器部署 → 无新增公开端口、无应用／数据库凭据进入 CLI、专用卷与非特权进程、内部 token 校验、健康检查通过；配置、安全审查和容器检查。
- 真实 Codex 分类 → 使用合成数据完成 ACP initialize/session/prompt 和实际分类／忽略结果，记录脱敏证据；不发送真实账单进行 smoke test。
- 最终实现 → lint、unit、integration、e2e 全部通过，完成依赖审查、安全审查 Findings/Verification/Residual Risk；提交合回并推送 master、核对远端 SHA、生产镜像与健康检查，已有生产库不 seed。
