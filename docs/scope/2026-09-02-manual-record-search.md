# 记录页手动搜索

## 目标

在记录页提供一个明确的手动关键词搜索入口，使家庭成员能够在当前账单复盘范围内快速找到包含特定备注、分类或记账成员的记录，同时保持现有的时间范围、成员视角、类型、分类、排序和分页行为。

## 决策基线

### 需求边界

- 功能入口固定在 `/records` 现有筛选栏中；顶部现有搜索图标继续跳转到筛选区。
- 搜索关键词匹配三个字段：记录备注、分类展示名、记账成员名称。创建人、金额和日期不属于关键词搜索字段。
- 关键词先去除首尾空格，再进行不区分大小写的包含匹配；空白关键词等同于未搜索。
- 分类按当前界面语言的展示名匹配：中文界面匹配中文分类名，英文界面匹配英文分类名。
- 用户按回车或点击搜索按钮后才提交搜索，不在输入过程中实时刷新或请求。
- 搜索与现有时间范围、成员视角、类型和分类条件叠加，结果必须同时满足所有条件；清空关键词时保留其他条件。
- 搜索提交后从第一页显示结果；若当前打开的记录仍满足新的搜索条件则保留详情，若已不再匹配则关闭详情；搜索状态可由 URL 保留，但 URL 不得保存原始关键词。
- 无匹配结果时保留已提交关键词，沿用现有空状态，并提供清空搜索操作以恢复结果。
- 搜索只影响记录页，不扩展为首页报表、记账页或导入页的共享筛选条件。
- 保持现有记录查询的家庭隔离、当前 session 派生的成员权限、`deletedAt: null` 有效记录约束、编辑/删除和导入兼容行为。

### 技术决策

- 沿用 `listRecords` 的服务端查询链路，在数据库查询阶段应用关键词条件；禁止只过滤浏览器当前已加载页，以保证分页和完整结果集正确。
- 使用记录页 URL 参数 `search` 保存已提交关键词的服务端加密不透明令牌。筛选栏通过同源 POST 提交原始关键词，服务端使用现有 `AUTH_SECRET` 生成绑定当前家庭的不透明令牌后重定向；URL 不出现原始备注或关键词。筛选栏更新 URL 时保留现有参数，搜索变化清除 `page` 但不主动删除 `record`，由页面按完整过滤条件判断详情是否仍有效；其他既有筛选继续遵循当前各控件的 `record` 处理行为。
- 关键词字段在查询中按 OR 关系匹配备注、`actorMember.memberName` 和启用分类；这些字段的匹配结果再与时间范围、视角、类型、分类和 `deletedAt: null` 条件按 AND 关系组合。
- 分类展示名由当前 locale 的 `getCategoryDisplayName` 解析为可搜索的启用分类 ID 集合，再传入记录查询；数据库仍保存英文分类名，不新增本地化存储字段。搜索不需要匹配历史停用分类，也不改变现有分类下拉框仅展示启用分类的行为。
- 不新增数据库字段、索引或 Prisma migration；不向浏览器发送整批记录后再本地过滤。
- 新增的搜索标签、按钮、占位提示和清空操作文案必须同时加入 `src/lib/i18n.ts` 的中文和英文消息；原始关键词不得写入 URL、客户端持久化存储或应用日志。

## 设计视图

### 功能设计

记录页筛选栏新增一个关键词输入控件和搜索提交操作。输入框以当前 URL 中的 `search` 令牌对应的服务端解密值为持续来源；用户输入后按回车或点击按钮，页面以当前所有筛选条件查询并回到第一页。关键词未提交前不改变记录列表；任何导致 URL 变化的导航都会使输入框同步到新的服务端值，未提交草稿不脱离 URL 单独保留。

搜索结果按现有排序规则显示，分页只针对搜索后的结果集。用户切换时间范围、成员视角、类型、分类或排序时，已提交的关键词继续保留，搜索结果随新条件重新计算。清空搜索会删除 `search` 参数并保留其他条件。搜索条件变化时，当前打开的记录若仍属于新的完整结果集则保持详情，否则关闭详情。

搜索无结果时仍显示输入的关键词和现有空状态，并提供清空搜索操作；清空后恢复同一组非关键词筛选条件下的记录。未输入关键词时，记录页行为与现有实现一致。

### 技术设计

#### 整体方案

`RecordsPage` 从 URL 解密当前家庭的 `search` 令牌并规范化关键词，结合当前 locale 解析可匹配的分类 ID，再把关键词和已有查询条件交给 `listRecords`。`RecordsFilterBar` 负责输入状态、回车/按钮提交和清空操作；同源搜索 POST 路由负责把原始关键词转换为加密令牌；服务端列表查询负责权限、有效记录、范围、视角、类型、分类、关键词、排序和分页的统一组合。

关键词搜索的数据流如下：

```text
输入关键词
    │ 按回车 / 点击搜索
    ▼
RecordsFilterBar ── POST /records/search（原始关键词只在请求体）
    │ 服务端返回 /records?search=<opaque-token>，保留其他参数，删除 page
    ▼
RecordsPage ── 规范化关键词 + 按 locale 解析分类 ID
    ▼
listRecords ── session household + perspective + range + filters + keyword
    ▼
有效记录分页结果
```

`listRecords` 必须继续从服务端 session 对应的 `householdId` 和 `currentMemberId` 校验家庭成员，再限制 `householdId`、`deletedAt: null` 和视角解析出的 `actorMemberId`。关键词条件只能缩小该安全边界，不能替代或放宽它。

#### 关键结构

- 记录查询输入新增可选的规范化关键词，以及为当前 locale 预解析的分类 ID 集合；未提供关键词时不增加关键词条件。
- 关键词对备注、记账成员名称和启用分类 ID 集合执行 OR 匹配；已有 `categoryId` 选择仍作为独立 AND 条件。
- URL 中的 `search` 保存服务端加密令牌而非原始提交值；空白值不保存。URL 是输入框的持续来源，页面解密后把规范化值传给输入框；无效或跨家庭令牌按未搜索处理；现有未知或非法筛选参数继续按当前页面规则处理。
- 令牌使用现有 `AUTH_SECRET` 派生的 AES-GCM 密钥并绑定 `householdId`；原始关键词只存在于同源 POST 请求体和当前内存中的输入草稿，不写入 URL、客户端持久化存储或应用日志。
- 搜索提交不主动删除 `record`。页面使用与列表相同的完整过滤谓词验证选中记录，仅在记录不再匹配时清理选中状态并关闭详情；匹配时继续渲染详情。
- 结果分页沿用 `RECORDS_PAGE_SIZE + 1` 的窗口查询；筛选变化清除页码，避免沿用旧结果集的页码。

#### 实现流程

页面加载时解密当前家庭的 `search` 令牌并执行首尾空白规范化。筛选栏以服务端解密值作为输入值，并在 URL 变化时重新同步；用户编辑输入不会触发路由变化。提交时通过同源 POST 发送规范化关键词，请求体不进入 URL；服务端生成不透明令牌，删除 `page`，保留 `record` 供页面验证；清空时删除 `search`，保留其余筛选参数。

服务端收到请求后，使用当前 session 的家庭和成员上下文构造已有记录查询。若存在关键词，备注和记账成员名称使用不区分大小写的包含条件；启用分类先按当前 locale 将展示名称匹配到分类 ID，再把匹配的 ID 加入同一 OR 条件。之后按现有范围、视角、类型、分类、有效记录、排序和分页规则执行查询。若 URL 带有 `record`，页面用同一组完整过滤条件验证该记录；匹配时保留详情，不匹配时清理选中状态并关闭详情。查询为空时页面保留关键词并显示清空操作；查询成功时列表、分页链接和记录详情链接继续携带完整筛选 URL。

## 验收

- 输入备注、分类展示名或记账成员名称 → 列表显示至少一个字段匹配关键词且满足其他筛选的有效记录，不匹配任一字段的记录不显示；三种字段分别使用隔离数据并增加多个字段同时命中的 OR 用例；输入过程不触发路由变化；单元测试与 e2e 通过。
- 输入包含大小写差异、子串或首尾空格的关键词 → 按不区分大小写的包含匹配命中，提交值去除首尾空格；集成测试通过。
- 输入分类展示名 → 当前 locale 下对应的启用分类记录命中，中文和英文展示名分别可用；历史停用分类不作为搜索候选；分类匹配测试覆盖两种 locale。
- 输入记账成员名称 → 当前其他筛选范围和成员视角内、记账成员名称匹配的记录命中；创建人名称不作为匹配字段；集成测试通过。
- 同时启用时间范围、成员视角、类型、分类与关键词 → 结果同时满足所有筛选；切换任一筛选后关键词保留且从第一页重新查询；页面集成测试通过。
- 搜索结果超过一页 → 下一页和上一页只遍历关键词过滤后的结果，页码链接保留 `search`；分页集成测试通过。
- 当前打开的记录仍符合新搜索 → 详情抽屉保持；记录不再符合新搜索 → 详情抽屉关闭并清理选中状态；页面集成测试通过。
- 输入空白或执行清空搜索 → 删除 `search`，保留其他筛选并恢复未搜索结果；单元测试与 e2e 通过。
- 搜索无结果 → 输入值保留，显示现有空状态和清空搜索操作；点击清空后恢复结果；页面测试与 e2e 通过。
- 查询安全边界 → 搜索不能返回其他家庭、软删除记录或视角之外的记录，且不改变现有编辑、删除、导入和 session 权限行为；记录查询集成测试通过。
- URL 中的 `search` 发生变化 → 输入框同步到服务端解密后的值，覆盖提交、清空、浏览器前进/后退和其他筛选触发的 URL 更新；URL 不包含原始关键词；组件测试与 e2e 通过。
- 中英文界面 → 新增搜索标签、按钮、提示和清空文案均存在对应 locale，语言切换后记录页可正常渲染；i18n 单元测试和 e2e 通过。
- 兼容性 → 未提供 `search` 时现有记录页查询、排序、分页、详情链接和跨页面共享筛选行为保持不变；完整相关测试通过。
- 浏览器暴露 → 搜索原文不出现在地址栏、客户端持久化存储、应用日志或分析数据中；服务端令牌绑定 `AUTH_SECRET` 和当前家庭，安全审查通过。
