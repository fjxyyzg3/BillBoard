# 导入分类映射支持忽略

## 目标

在文件导入的分类映射中提供“忽略”选项，一次排除同分类组的全部记录，并保存为家庭共享规则，减少后续导入时逐条选择“不导入”的操作。

## 决策基线

### 需求边界

- 入口保持 `/records/import`，支持随手记 `.xlsx`、微信支付 `.xlsx`、支付宝 `.csv`、招商银行借记卡交易流水 `.pdf`。忽略与现有分类映射使用同一个分组：`source|transactionType|primaryCategory|secondaryCategory`；不同来源、收支类型或任一分类名称不同的组互不影响。
- 在待映射分类组的下拉框中增加“忽略”。点击“保存映射”后，当前草稿中该组仍参与导入复核的记录全部设为不导入；分页和筛选不得缩小生效范围。已经不导入的记录保持不导入。
- 忽略规则长期保存在当前家庭，家庭成员共享；以后新建的相同来源分类组草稿自动应用。保存规则不回写其他现存草稿、不改变已入账交易，也不产生用于同源去重的交易记录。
- 保存只更新本次明确修改的分组。未修改的已忽略组不重新发布家庭规则，即使它与另一草稿修改后的家庭规则不同，也保留该草稿原有跳过结果；保存其他组或没有任何修改时，不得恢复已被撤销的忽略规则。
- 被分类规则忽略的记录计入现有“已跳过”，不计入可导入、待分类映射或待成员映射，不阻碍其他组确认导入。全部可处理记录均被忽略时允许完成草稿，新增交易数为零。
- 被忽略的分类组保留可编辑入口。重新选择实际分类并保存，即撤销该组忽略规则，恢复当前草稿中仅因分类忽略而跳过的记录；单独手动跳过的记录仍跳过。正常分类选项继续限于现有启用且收支类型匹配的分类。
- 保留现有逐条“导入 / 不导入”操作。恢复一条无分类的忽略记录后，先进入待映射；仅恢复行决定不删除家庭忽略规则，保存该组的实际分类时才替换规则。撤销分类忽略后，疑似重复继续按现有规则默认不导入，需要逐条选择导入。
- 无效行、同源重复行、全额退款及需手工调整的受保护退款行保留原状态、原因和操作限制。招商银行默认不导入的资金移动记录也不得因撤销分类忽略而自动导入。
- 中文和英文同步提供选项、规则说明及跳过原因；不新增真实账本分类、独立设置页面或一般分类映射管理能力。

### 技术决策

- 复用 `ImportCategoryMapping`，将 `categoryId` 及对应关联改为可空，保留现有家庭内唯一约束和分类外键，明确维持 `onDelete: Restrict`、`onUpdate: Cascade`，避免分类删除把正常映射自动变为忽略：没有映射记录表示未映射；记录存在且 `categoryId` 非空表示实际分类；记录存在且 `categoryId` 为空表示忽略。迁移只解除分类字段的非空限制，保留已有映射和交易数据，不执行 seed。
- 服务层显式区分未映射、实际分类和忽略，不能继续通过 `get(key) ?? null` 将未映射与忽略混为一谈。表单中的“忽略”专用值转换为忽略结果，空选项仍表示未选择，不得被当成忽略或分类 ID。
- 映射表单以本次呈现的初始选项为基线，提交用户最终选择与基线不同的分组变更集；未提交的分组表示保持原状，不表示清除或重写规则。Action 和服务只处理变更集，不得补齐其他草稿分组，也不得将旧草稿与当前家庭规则的差异当成用户修改。初始选项与变更识别只表达操作意图，不替代服务端权限、分组和分类校验。
- 草稿沿用 `ImportDraftRowStatus.USER_SKIPPED` 和 `ImportRowDecision.SKIP`，以稳定原因代码 `CATEGORY_MAPPING_IGNORED` 区分分类忽略与现有手动跳过、默认跳过及退款处置；不增加行状态枚举或持久化行字段。
- 规则保存与当前草稿行更新必须原子完成，并与确认导入、行决定更新按同一草稿锁串行化。服务端校验当前 session 家庭、草稿为 `PENDING`、映射来源和分组确实存在于该草稿；普通分类分支继续校验分类启用状态和收支类型。完成草稿或伪造输入不得修改规则和行。
- 按分组批量处理行；大组使用批量读取、分块更新及明确的 Prisma transaction timeout，不逐行查询或写入。确认导入继续复用现有批量写入与幂等保护。
- 权限、`amountFen` 整数分、`Asia/Shanghai` 日期、来源信息和包含软删除记录的同源去重规则保持现有约束，不新增敏感数据到 URL、日志或客户端持久化存储。
- 本次不更新 wiki。Spec 与实现使用同一 feature 提交；实现完成后按仓库规则同步 feature 版本、完整验证、安全审查、合回并推送 `master`，再重启正式服务和健康检查。

## 设计视图

### 功能设计

上传解析后，用户在现有分类映射表单内为每个待处理分组选择实际分类或“忽略”，再统一保存本次修改的分组。未触碰的默认“忽略”选项仅展示该草稿当前决定，不随其他组的保存重新写入家庭规则。忽略生效后，汇总和复核区展示更新后的“已跳过”数量，明细显示“分类映射已忽略”；成员映射只要求仍参与导入的记录完成，不会因已忽略成员阻碍确认。

当前草稿因分类忽略而跳过的分组继续显示在同一映射区域，下拉框默认选中“忽略”，并提供现有实际分类选项，便于撤销。正常已完成分类映射的组维持现有展示方式。后续新草稿自动忽略的组也提供相同的撤销入口；不存在因分类忽略而跳过的可处理行时，现有逐条恢复与待映射入口仍可处理需要恢复的记录。

撤销忽略后，系统重新计算该组的可导入和疑似重复状态。用户原先单独选择“不导入”的明细、银行默认跳过及受保护记录保持原决定。保存失败显示错误，规则与行不发生部分更新，当前表单选择及变更集保留以便重试；成功后按新的草稿展示重建基线，已完成草稿不能再保存映射。

### 技术设计

#### 整体方案

Prisma 保存家庭映射规则，通用草稿服务负责加载规则、生成行状态、分组更新和汇总。来源解析器继续负责文件解析与退款归并，不承担忽略决策，也不修改现有 mapping key 或来源指纹算法。

导入页面与映射表单负责选项呈现和变更识别，server action 接收结构化变更集，所有授权和状态校验在服务层执行。草稿汇总从当前草稿行恢复被分类忽略的分组，不能直接读取新规则来反向改写既有草稿的决定；新增草稿则在创建时批量加载当前家庭规则。复核组件继续使用现有行决定和确认接口，新增原因由 i18n 提供中英文显示。

#### 关键结构

| 数据 | 含义 | 处理方式 |
| --- | --- | --- |
| 没有家庭映射记录 | 未映射 | 普通可处理行进入 `NEEDS_MAPPING` |
| 家庭映射记录有 `categoryId` | 实际分类映射 | 应用实际分类并沿用现有行状态判断 |
| 家庭映射记录的 `categoryId` 为 `null` | 分类组忽略 | 普通可处理行进入 `USER_SKIPPED + SKIP`，原因是 `CATEGORY_MAPPING_IGNORED` |
| 手动、银行默认或受保护原因的跳过行 | 既有独立跳过决定 | 保存和撤销分类忽略均不得将其自动改为导入 |

`missingMappings` 继续描述需要实际决策的分组，补充从 `CATEGORY_MAPPING_IGNORED` 行聚合的可编辑忽略分组。两者按相同 mapping key 汇总，不重复展示。待映射组以空选项为初值，只有忽略行的组以“忽略”为初值；若逐条恢复使同组同时存在待映射行和其余忽略行，优先使用待映射组的空初值，用户可明确选择“忽略”重新跳过或选择实际分类撤销忽略。分组的展示状态不能替代服务端对草稿行和家庭范围的校验。

#### 实现流程

1. 创建草稿时批量读取当前家庭和来源的映射规则，显式识别忽略。现有无效、同源重复、退款和银行默认跳过的判断保留优先级，其余行根据规则进入对应状态；忽略不会生成交易或新分类。
2. 保存表单时只提交相对初始选项实际改变的分组。服务层锁定属于当前家庭的草稿，确认未完成，验证变更集中所有分组与分类结果，再在同一事务内仅保存这些规则并更新当前草稿对应行。没有变更时不写入规则或行。保存任一项失败则整体回滚，客户端保留选择及待提交变更集，不前移初始基线，并显示可重试的中英文错误。
3. 保存忽略时，将匹配组的 `NEEDS_MAPPING`、`READY`、`POSSIBLE_DUPLICATE` 行分块设为 `USER_SKIPPED + SKIP + CATEGORY_MAPPING_IGNORED` 并清空行分类。已有因分类忽略而跳过的行保持忽略；其余原本已跳过或不可操作的行保留原有原因与决定。
4. 保存实际分类时，覆盖该组家庭规则，处理原有待映射保留行，并恢复原因仍为 `CATEGORY_MAPPING_IGNORED` 的行。无重复候选者进入 `READY + KEEP`，有候选者进入 `POSSIBLE_DUPLICATE + SKIP`；所有更新均设置有效分类并清除分类忽略原因。其他跳过原因的行不参与自动恢复。
5. 单条恢复沿用现有状态计算；没有分类时回到待映射，实际分类保存前不得入账。忽略规则由分组映射保存操作管理，逐条操作不会悄悄修改其他草稿或未来导入规则。
6. 重新生成汇总和复核展示；确认导入仅处理保留且满足现有完整性条件的行，继续跳过分类忽略行，并按原有保护处理退款、同源冲突、重复确认和大草稿。

## 验收

- 四种来源的映射下拉都提供“忽略”，表单可混合提交实际分类与忽略，空选项不产生忽略规则 → 页面和 action 集成测试；端到端验证中文及英文选项、保存和展示。
- 同一组有多行并跨复核页时选择忽略，其他组正常映射并确认 → 被忽略行全部不产生 `Transaction`，待分类和待成员映射要求移除，跳过数准确，其他组按现有规则入账；服务集成与端到端验证。
- 草稿中全部可处理行被忽略 → 确认成功、草稿完成、创建数为零，重复确认无新增交易；服务集成验证。
- 同家庭另一成员再次导入相同来源分类组 → 新草稿自动忽略；改变来源、收支类型、一级或二级分类以及更换家庭的对照组不被忽略；服务集成验证。
- 当前草稿已保存忽略或新草稿自动复用忽略 → 在原映射区域可改选实际分类；因分类规则跳过的行恢复，手动跳过、银行默认跳过与受保护行不自动恢复；未来新草稿使用新分类；集成与端到端验证。
- 草稿 A、B 都忽略分类组 X，B 另有待映射组 Y；A 将 X 改成实际分类后，B 仅修改 Y 并保存 → B 的 X 行仍保持原跳过决定，X 的家庭规则仍为 A 设置的实际分类，新草稿按实际分类处理 X；覆盖 B 保留旧页面和重新打开页面两种情况，使用服务、action 与真实表单端到端验证。
- 已忽略组选项保持初值，或修改后又改回初值，并保存其他组；没有任何修改时直接保存 → 未修改组不进入变更集，家庭规则和对应行不被重写；保存失败重试仍只提交原有改动组，成功后的再次保存不重复提交；表单逻辑、action 与端到端验证。
- 逐条恢复没有分类的忽略行 → 行回到待映射且不能直接入账，家庭忽略规则暂时保留；保存实际分类后才替换规则；服务集成验证。
- 同一组保留忽略行且逐条恢复出待映射行 → 映射控件以空选项为初值，选择“忽略”会作为明确变更重新跳过该组，选择实际分类会撤销忽略，不被未修改选项过滤误吞；集成与端到端验证。
- 同组包含无效行、同源重复、全额退款或需手工调整的退款 → 原状态、原因、金额和操作限制不变；软删除交易仍参与同源去重，既有退款回归测试通过。
- 保存忽略、撤销忽略、读取或确认使用其他家庭草稿、伪造来源或不存在的组、无效或类型不符的分类，或操作已完成草稿 → 服务端拒绝且规则与行均未部分变更；集成测试覆盖正常和忽略两个分支。
- 映射保存与确认或行决定同时执行，或多组提交中的任一项失败 → 按草稿锁收敛为一致结果，失败整体回滚，无“完成后改行”及规则和行不同步；事务与并发集成验证，表单失败重试端到端验证。
- 大分类组保存忽略、撤销并确认 → 使用批量读取和分块更新，不逐行数据库访问、不发生事务超时；扩展现有大草稿和批量映射集成验证。
- 迁移前已有实际分类映射 → 迁移后仍正确复用，已有交易、草稿和指纹不被回填或清空，分类外键仍为 `ON DELETE RESTRICT / ON UPDATE CASCADE`，不执行 seed；migration 静态核对及开发或测试库的迁移与集成证据。
- 最终实现 → `npm run lint`、`npm run test:unit`、`npm run test:integration`、`npm run test:e2e` 全部通过，仓库安全审查报告含 Findings、Verification、Residual Risk；feature 版本一致、提交和远端 `master` SHA 可核对，生产重启后健康检查通过。
