# 月度与年度 AI 账单分析

## 目标

用户选择 BillBoard 内已有账目的月份或年份，主动交由 Astra 分析，获得有账目依据的收支复盘和可执行改进建议，并与家庭成员共享、回看最新报告。分析服务复盘，不修改账目，保留现有快速记账、导入、查询及家庭加密行为。

## 决策基线

### 需求边界

- 数据来源仅为站内账目，不新增外部文件分析入口。入口位于 `/home`，仅月、年模式可发起；跟随发起时首页的账本查看范围和归属成员筛选，默认整个家庭。查看范围与新增记账目标分离，不使用记账目标代替分析范围。
- 全家庭范围包含归档账本与同家庭历史成员；单账本、单成员范围保留相同语义。只分析有效交易，排除软删除记录，保持现有收支、退款和整数分口径。
- 所选期间提供全部逐笔日期、收支方向、`amountFen`、分类和备注。成员显示名替换为本任务内一致的代号；多账本使用代号区分，不附加真实账本名。备注按原文发送，不承诺其中的姓名、邮箱或其他个人信息已脱敏。内部行号用于引用，不另行附加数据库 ID、账号邮箱、来源指纹、导入原始字段、登录凭据或家庭码。
- 月报附上月、去年同期的统计摘要，年报附上一年统计摘要；不发送比较期逐笔明细或备注。比较期与本期使用相同账本、成员范围，按现有上海时间比较口径对齐；基期无记录、部分可比及零基数必须明确区分。
- 输出一次性报告，内容为收支复盘、值得关注的变化或消费问题，以及有依据的改进建议。没有证据时少给或不给具体建议，明确数据限制；不得把“无已记录数据”解释成没有消费或账目完整。首期不提供报告追问、自动通知、定时生成、预算管理或自动改账。
- 账目较多时自动分批完整分析，再汇总为一份报告；全部批次覆盖预检通过的本期明细，不抽样、不截断备注。单行、总量、批次数或耗时超限时明确失败，不将部分分析冒称完整报告。
- 允许在同一应用页面会话内切换记账、明细等页面继续生成，并可主动取消。刷新、关闭应用或网络中断会触发未完成请求取消；不保证离开应用后继续，不提供服务器持久后台队列。提交已完成但响应丢失时，只查询原任务结果，不把未知状态当失败自动重发。
- 报告归家庭共享，当前有效成员均可回看，不要求创建者仍是有效成员。每个“月或年 + 所选月/年 + 账本范围 + 归属成员范围”只保留最新一份；报告语言不是另一份报告的唯一维度。重新生成成功后原子替换，失败、取消、超限或授权失效保留旧报告。
- 报告标明分析期间、筛选范围、数据快照时间、实际统计截止日期、生成时间和生成语言。其内容为生成时的历史快照，后续补录、修改或删除账目不自动更新；用户需要时主动重新生成。回看不重新调用 AI，切换界面语言不自动翻译既有正文。
- 中文默认，新增交互与文案同步中英文；报告按发起时界面语言生成。保持移动优先，沿用现有首页分析和应用内任务提示方式。

### 技术决策

- 复用现有独立 `import-agent` 与 WheelMaker Responses API，新增账单分析协议和任务运行器；账单分析使用独立服务端配置 `BILL_ANALYSIS_AGENT_MODEL=gpt-6-astra`、`BILL_ANALYSIS_AGENT_REASONING_EFFORT=high`。浏览器不可指定模型、推理强度、供应商地址或预算；不切换导入分类、自然语言记账现有模型，不回退到其他模型。
- `WHEELMAKER_BASE_URL`、`WHEELMAKER_API_KEY` 继续仅注入 Agent。每次模型调用使用独立临时请求，保持 `ephemeral: true`、`store: false`、禁用工具，不复用供应商会话，不自动重试。Agent 无数据库访问，服务端负责取数、匿名代号、数学统计、分批和结果校验。
- 新建家庭共享报告及分析请求回执模型，增加数据库迁移；不改既有交易、导入或自然语言请求结果。两个模型均纳入现有财务加密、转换、换钥和恢复边界。旧恢复包必须显式兼容，不削弱其摘要、proof、删除检查点或授权校验。
- 由有效 `AppSession` 派生账号、成员和家庭，在服务端核验账本读取与成员筛选授权。归档账本分析使用读取授权，不套用禁止向归档账本写账的检查；报告写入不改变账本或交易。最终保存采用短事务，遵循现有家庭、成员/账号、会话及必要账本锁序，复核原会话、原身份、家庭状态、查看范围、加密模式代次及资源租约。
- 发起前明确披露“所选期间逐笔账目及原文备注、比较期摘要将交由 Astra 处理”，并检查本人账号已有 AI 选择；不从以往使用推定允许，也不把成员代号描述成全面匿名化。完整输入、快照和分批计划通过检查并正式受理后，可完成这一个固定输入的任务；关闭 AI 选择不授权新任务或追加范围。回看已保存报告无需再次开启 AI。
- 账目在同一一致快照中读取，服务端计算总额、笔数、分类、日期/月走势、金额分布与比较指标，网络推理不占数据库事务。原始输入、家庭解锁材料与批次中间结果仅保留在本次有界服务端执行的内存，不写入队列、临时文件、客户端持久存储、URL、日志或分析平台。
- 分批调用顺序执行，复用数据库共享的 `ai` 全局/家庭/成员并发和窗口，不建立可绕过原 AI 额度的新资源类别。扩展服务端任务档位以支持分析租期和时限，保留原记账、导入 AI 的 45 秒 Agent 调用与 75 秒租约默认值。长任务占用共享 AI 槽期间，其他 AI 请求按既有规则提示繁忙，普通手工记账仍可使用。
- 分析以原 UUID 和原会话/成员/家庭/加密代次固定输入。页面切换与筛选变化不重定向在途任务；刷新只用原 UUID 查终态，不读取新的账目替原任务续跑。原任务不自动恢复执行，人工重新生成使用新 UUID。

## 设计视图

### 功能设计

首页月、年范围提供“AI 分析”入口，展示所选期间、账本和成员范围。进入后可以查看该范围已有的最新报告，或在清晰的数据发送说明下点击生成/重新生成；其他日期模式提示先选择月份或年份，不把任意范围偷偷转换成月、年请求。

首次生成前复用本人 AI 选择入口，未开启时不请求供应商。无本期有效记录时展示无数据，不调用模型，也不删除或覆盖既有报告。只有收入或只有支出时仍可分析，不填造不存在的收支和建议。当前月/年截止上海今日，报告明确是期间内截至该日的已记录账目；比较期按相同进度对齐。

生成中显示取数、分批分析、等待额度恢复、汇总与保存阶段，并提供取消。进度来源于实际完成的批次，不模拟百分比。等待额度恢复只适用于已受理任务的后续调用，仍受原总时限和租约限制，不创建新的后台任务。应用级控制器拥有请求生命周期，离开首页但仍在应用内不会取消；切换账本、成员或日期后，进度始终标明原范围，旧响应不会覆盖当前选择下的报告。完成后显示轻提示并可返回原范围查看。

报告由确定性统计概况、AI 观察与改进建议组成。关键证据以服务端提供的金额、日期、分类、笔数或对应快照记录展示；事实与可能原因、建议分开，不凭消费类别断言动机、必要程度或成员过错。建议可说明可尝试的行动和核对事项，不假定收入完整、个人目标、资产负债或家庭成员偏好。

首页入口提供该家庭已有最新报告的简洁回看列表，标明期间和范围，便于跨月份、年份回看；列表只列已完成报告，按生成时间倒序分批加载，不为重新生成保留版本列表。打开列表中的其他范围报告不改变在途任务。历史成员或账本改名后仍用稳定身份引用，范围标签通过获准家庭数据解析；旧生成正文保持原快照。

断网或刷新后，报告入口用已留存的最小请求标识查询状态：已成功则加载报告；仍在清理则显示中断处理中并阻止重复生成；已失败/取消则允许手动重试。查询失败或暂不可判定时显示状态未知，保留原 UUID 继续查询，不自动重新扣额或换 UUID；在原有效会话下由数据库确认不存在回执时，按与首次受理相同的请求锁原子写入 `NOT_ACCEPTED` 终态，随后可由用户手动以新 UUID 重试，迟到原请求不得再次受理。若某次成功报告后来已被同范围新报告替换，原回执显示“已完成，已有更新报告”，不恢复旧正文。

取消与最终保存以数据库事务结果为准：取消先在短事务中持久标记 `STOPPING`，最终保存便须拒绝；供应商及本地 HTTP 清理结束后才标记取消终态。保存先完成则取消返回已完成，不谎称报告未生成。超时、响应格式错误、批次证据校验失败、供应商不可用、资源繁忙、原身份失效或模式变化均显示可解释状态，保留原报告和所选范围。

### 技术设计

#### 整体方案

`/home` 延续现有月/年与查看范围解析。应用壳内的分析控制器维护唯一在途任务；分析组件只负责当前范围的报告展示和用户操作。分析专用同源 POST 接口承接生成、状态/报告读取及取消；采用与现有受保护接口一致的 Origin、请求体类型/大小、身份检查与 `no-store`。生成接口使用带阶段进度及保活的响应流，由应用级控制器消费；流中成功通知必须晚于数据库提交，不以保持连接代替总时限。加密家庭的读取和生成都经携钥 POST，初始 SSR 不包含财务正文。

web 的分析服务负责快照、预检、原 UUID 回执、资源占用、批次调度、结果校验和原子保存。Agent 只接受版本化的明细分析或汇总协议，采用对应分析档位的请求大小、响应大小和超时；原 `/suggest`、`/parse-expenses` 的默认协议与预算保持不变。

数据路径为：用户明确发起 → 原身份与 AI 选择检查 → 有界一致快照与分批预检 → 固定输入受理 → Astra 顺序分析各批 → Astra 汇总已验证批次发现与全局统计 → 服务端验证 → 原授权短事务替换报告 → 返回回执并释放资源。供应商调用和清理完全结束后才释放本地占用，沿用仓库定义的 HTTP 取消边界，不增加远端停止确认接口。

长响应的可用性须通过实际 HTTPS 域名转发 → frps/frpc → 本机应用链路核验，沿用 `docs/runbooks/home-network-checklist.md` 的实际入口原则。以授权测试家庭的虚构账目、受控延迟和同一鉴权生成接口验证阶段流及时透传、无意外缓冲、空闲及绝对请求时限，并覆盖接近 8 分钟预算的完成和客户端断开取消。保活、loopback e2e、Hub 单独调用或 HTTPS 200 均不能替代该证据；不新增公开探测端点，不记录真实入口、账目或响应正文。链路无法承载时，依据实际限制修正传输或预算并复验，保持应用内继续、刷新取消和完整分析边界，不以健康检查冒充验收。

#### 关键结构

**账目快照与模型输入**

- 以一个 `RepeatableRead` 财务快照固定查询时点，批量读取本期明细并计算本期/比较期指标。所有查询由服务器限定家庭与合法查看范围，包含 `deletedAt: null`；未加密和加密路径得出相同统计结果，加密路径沿用受保护查询及既有解密扫描上限。
- 本期记录按上海发生日期及稳定行顺序分配 `rowRef`，分类、成员、账本用任务内代号。发往模型的成员只含代号，不含账号、真实显示名、创建人或内部 ID；只发送归属成员维度。类别保留展示名以供分析，原始备注完整保留。
- 比较期发送收支总额/笔数、分类汇总、必要的按月走势及可比性标识；未找到记录不作为完整零消费证明。本期所有统计与比较摘要来自同一快照，不在汇总时重新查询更新后的账目。
- 预检按序列化后的实际 UTF-8 字节及记录数切分。每条明细完整属于且只属于一个明细批次，分批清单与输入摘要固定；中间批次可以携带本期全局摘要作为背景，但不得将其重复求和。最终汇总只接收已验证批次发现、引用、全局指标和比较摘要，不再次附带其他期间明细。

**初始硬上限**

这些限制由服务端常量及协议共同约束，不新增用户配置项；超限有明确错误，不自动扩大预算或降低覆盖率。

| 项目 | 上限/语义 |
| --- | --- |
| 本期明细 | 10,000 条；完整本期模型输入及比较摘要合计 8 MiB，二者任一超出即拒绝。 |
| 明细批次 | 每批最多 500 条且整个 Agent 请求 JSON 不超过 256 KiB，最多 24 批；单行无法放入一批时拒绝，不截断备注。 |
| 供应商调用 | 每批一次，最后汇总一次，最多 25 次；不自动重试，不添加模型后备链路。 |
| 中间及最终输出 | 每批结构化发现最多 4 KiB，最终报告最多 64 KiB；全局指标/比较摘要用于汇总的序列化部分最多 64 KiB，汇总 Agent 请求含全部已验证中间结果及协议封装不超过 256 KiB，供应商完整响应限制为 256 KiB。 |
| 执行时间 | 从生成请求进入服务至最终保存总计最多 8 分钟；单次明细推理最多 90 秒，最终汇总最多 120 秒，均受剩余总时限约束。 |
| 资源租约 | 分析档位最多 9 分钟，为取消和本地 HTTP 清理保留余量；不续期、不重新获取租约续跑同一任务，过期禁止保存。清理未结束时执行占用仍保留。 |
| 并发与窗口 | 使用原 `ai` 全局/家庭/成员并发及每分钟额度，额度按每次实际供应商调用尝试计入；检查三个窗口均允许后一次性扣额。已受理任务的后续调用在原租约/总时限内等待本地窗口恢复；等待和重复查询原回执不扣额。 |
| 快照与回执查询 | 数据库事务复用财务快照和短写事务预算，不跨模型调用持锁；生成/查询/取消的用户 POST JSON 最多 16 KiB，回看列表每次最多 20 份。 |

快照读取前先取得原 `ai` 并发租约，以延迟扣额方式保护取数资源；快照和分批总量预检在首次供应商扣额/调用前完成，明知超限或无数据的请求不消耗 AI 调用额度，并完成清理后释放占用。正式受理沿用同一租约，不重新申请以延长截止。输出超限、汇总输入无法容纳全部批次证据或总时限不足均收敛为失败，不交付删减版。额度扣除代表实际尝试，不因供应商返回错误回退；未被允许的调用不得部分扣除其他窗口。

首次准入的资源繁忙仍按既有规则直接拒绝，不排队受理新任务。正式受理后，仅对尚未尝试的后续调用，在本地数据库窗口额度不足时等待全部受限窗口的恢复时点，再原子重验和扣额；使用数据库时钟及受取消信号约束的定时等待，不持有数据库事务/业务锁，不忙轮询。等待始终占用同一个原执行租约，计入原 8 分钟总时限，既不续租，也不增加批次或调用次数。等待恢复将超过总截止或原租约时按超时收敛；取消、原身份失效或模式变化时停止等待。恢复后先复核原身份、模式、请求状态与租约，再判断所有窗口；任一窗口仍不允许则继续在原预算内等待，不部分扣额。上游供应商的 429、网络错误或失败响应不进入此等待机制，不重试已尝试调用。

**结构化结果与可信证据**

模型输出版本化 JSON，将概况、观察、建议与数据限制分开；观察和建议使用 `metricRef` 或本次本期 `rowRef` 引用，服务端校验引用属于固定快照。总额、笔数、分类变化和比例由服务端计算、渲染，不以模型自报数字覆盖。可量化的预算示例必须明确是建议假设，不伪装成账目事实。

每批回执携带该批绑定标识；服务端独立核对覆盖清单，未知引用、重复/缺失批次、越界字段或不合法结果使整个任务失败。汇总只能引用已验证全局指标或本期证据，不能扩大到比较期逐笔、其他家庭或未提供的历史。分类名、备注和模型正文都是不可信数据；模型禁用工具，UI 使用文本/受限结构渲染，不执行 HTML、任意 URL 或账务动作。语义上的建议仍属 AI 判断，不宣称校验能证明所有建议正确。

**持久化与唯一报告**

- `BillAnalysisReport` 归属于家庭，保存最新成功正文、固定范围定义、生成语言、输入快照摘要、确定性指标、必要证据映射及生成成员历史引用。不复制完整原始明细、原始备注或中间批次结果；证据只保存展示必要的快照事实和同家庭交易引用。匿名成员与内部身份对应关系只在应用服务内使用，不发送供应商。
- `BillAnalysisRequest` 保存原 `clientRequestId`、原 AppSession/成员/家庭、目标报告、任务代次、终态、有效截止和最小错误码。范围、输入摘要和业务结果等敏感字段纳入受保护载荷；不保存可再次执行任务的原始明细、家庭码或模型会话。
- 报告和请求的创建成员、请求所指报告均通过包含 `householdId` 的组合外键保持同家庭关联；待预检请求的报告关联可空，正式受理后固定。原 AppSession 标识是不可改写的历史授权绑定，恢复财务快照时不重建或恢复该会话；成员离开不级联删除报告或回执。
- 请求 UUID 在家庭及原成员内唯一，不加入账本、月份、年份或后来登录状态扩宽唯一性。重复 UUID 只返回原状态；同 UUID 改范围或换会话不能变成新调用。同一原会话的正常状态查询不重新受理，旧会话撤销/过期不得被新会话重新授权。
- 首次回执建立与“不存在即关闭”共用该 UUID 的事务锁；先认证原有效会话，再锁请求，存在回执就按原绑定返回，绝不把正在预检/执行的任务改成未受理。不存在时只写最小 `NOT_ACCEPTED` 回执，不需要恢复原始范围或输入，不占 AI 执行槽、不扣供应商额度，也不创建报告槽。该终态禁止任何迟到的首次 POST 为同 UUID 取数、取得执行租约或调用模型；查询事务与首次受理事务无论谁先提交，都只有一种合法结果。数据库不可用、授权/模式屏障导致不能安全写入或事务结果不明时返回未知，不能把查询失败推定为不存在；新会话不得借此查询或恢复旧回执。
- 规范化报告范围由月/年模式、所选月/年、全家庭或同家庭账本 ID、全部或同家庭成员 ID 构成，不含“当前截止日”、显示名或语言，因此当月后续日期及成员/账本改名仍更新同一报告。家庭写锁内按解密后的规范化范围查找/创建报告槽，控制并发唯一性；不新建可枚举日期/金额的明文 hash 索引，也不依赖会随换钥改变的单版本盲索引判断逻辑唯一性。
- 每个报告槽只允许一个有效生成代次。新报告正文、成功回执与报告槽代次核对在同一短事务内提交，旧/晚到任务不能覆盖新代次。保留旧正文直到成功替换，失败终态不清空旧正文；只有首次失败的空槽不出现在回看列表。
- 请求回执不保存历次正文。成功回执绑定所产生的报告代次；报告已更新时，只能显示完成及存在新报告，不把最新正文冒充该次原结果。报告按家庭业务数据保留，账号停用/成员离开不会级联删除；回执只保留幂等和授权所需的最小信息，不提供版本历史。

**加密、恢复与任务生命周期**

新增两个模型登记至 `protectedFields`/`protectedModels`，补齐原生 SQL 护栏与财务实体查询；报告正文、范围、统计、证据、输入摘要及业务状态说明受同家庭模式保护，授权 ID、原 UUID、状态、操作时间与必要代次可作为最小元数据。开启/关闭加密、换钥、快照与恢复须覆盖新实体；不修改既有交易密文或原请求结果语义。

恢复格式明确区分旧 v1 固定实体集合与新增报告/回执的新版集合：旧包先按原结构验证原 manifest digest、proof 和字段，再在内部视图补空的新实体；新包显式声明新版本及实体集合，验证缺项时失败，不能将被删掉的新表误判为合法旧包。新快照计数、恢复逐值比较、同家庭引用和确认删除检查点覆盖报告与回执；旧授权/删除检查点不能被拿来声称证明新增实体的最新保留状态。备份恢复仍只在已核实空的隔离目标执行，不复制旧账号/成员/会话，不恢复可执行的在途任务。

生成请求绑定原会话与加密请求上下文，服务端只在现有临时解锁时限内持有材料。应用级控制器保留原请求及 `AbortController`；站内导航不卸载执行者，筛选变化只改变展示。刷新/退出/关闭、主动取消、原身份失效、模式变化、租约到期或应用/Agent 停止均传播取消；客户端卸载的通知仅作尽力中止，服务端仍以请求断开、总时限、原授权和租约约束实际执行，不能依赖 `beforeunload` 保证取消到达。

客户端仅在当前应用页面会话的 `sessionStorage` 保存身份绑定的 UUID 和协议版本，不保存期间、金额、备注、家庭码或原始请求内容；同身份刷新后只恢复查询，不自动重启生成。查询使用当前有效访问者鉴权：家庭报告可正常读取，但原任务回执只能在其原有效 AppSession 下查询；在允许写入的原会话请求上下文中确认该 UUID 未建立回执时，按请求锁写 `NOT_ACCEPTED`，不能因客户端没有原始输入而永久停在未知。重新登录可按当前家庭权限查看已保存报告，不能恢复旧请求执行或以新身份查询其未完成内容。

在每个新批次调用前核验原身份、模式代次、任务状态和租约，供应商返回后再次核验。AI 选择在正式受理后关闭不取消该固定输入任务，但不允许替换输入或开启另一任务。取消与最终保存采用相同锁序核对原请求和报告代次：取消事务先将状态改为 `STOPPING`；保存要求原请求仍为 `RUNNING` 且未被取消，故停止中先提交就禁止保存。等待本地 HTTP 调用及流清理结束后才记取消终态并释放执行占用；关闭/换钥转换沿用资源收敛屏障。

在途执行不进入恢复队列。新增分析占用登记可验证的本地执行者实例及启动代次；正常停止等待本地执行清理，硬崩溃后的回收须先由服务监督/重启路径确认原本地执行者已停止，再持久封禁原任务保存并回收它的 execution/lease，使请求成为不可续跑的中断终态。普通状态查询不能只凭 TTL、缺少心跳、HTTP 断联或新进程启动就删除可能仍在执行的占用；无法核实原执行者停止时保持受控繁忙并给出运维核验条件。不增加逐请求 Hub 停止确认，不通过本地记录推定远端运行器清理状态；本次只补齐新分析任务的所有权及回收，不顺手改造其他任务的崩溃恢复。

#### 实现流程

1. 解析月/年及页面查看范围；认证、读取授权、AI 数据披露和本人选择检查通过后，在与状态查询共用的原 UUID 事务锁下建立待受理上下文与回执，并取得延迟扣额的共享 AI 并发租约。重复 UUID 返回原回执；已为 `NOT_ACCEPTED` 的迟到请求不重新取数或调用模型。状态查询确认无回执时在同一锁下关闭 UUID，查询失败则保持未知，不擅自重发。
2. 在同一财务快照内读取并匿名化本期明细，计算比较摘要、确定性指标与固定引用，完整预检记录数、字节数和批次数；无数据或超限不调用模型，原回执收敛为对应终态。受理短事务复核原身份、AI 选择、模式及原租约，绑定报告槽/代次，固定该次完整输入。
3. 每次调用前按实际供应商调用扣共享窗口额度，已受理任务的后续调用遇到本地窗口额度不足时在原预算内等待恢复，复核原授权后才扣额发出；不重试上游失败调用。顺序交付完整明细批次并校验结构、引用和覆盖，应用中展示真实阶段及等待额度状态，可切页和取消；等待与调用同时受原请求取消和总时限约束，调用另受单次上限约束。
4. 将全部已验证批次发现与全局统计、比较摘要发送 Astra 汇总；校验输出及证据。任何批次失败、中断或剩余预算不足，收敛该原任务，不自动重试或以新输入补跑。
5. 在家庭优先的短事务内复核原授权、读取范围、模式、租约和报告代次，原子保存最终正文与成功回执。回看时只读取获准家庭报告，历史事实与当前账目链接区分，不因交易后续变化改写旧正文。
6. 等待执行和本地 HTTP 清理结束，释放资源并丢弃内存输入及中间结果；返回成功、失败或取消终态。响应丢失只触发原 UUID 状态查询，不重复生成。日志与最小业务事件不记录期间、备注、财务数字、模型原文、请求正文或凭据。

## 验收

- 首页选择月/年及账本、成员 → 发起说明、服务端取数与报告范围一致；全家庭包含归档账本/历史成员，单范围不夹带其他记录，其他日期模式不能直接生成；范围单元测试、查询集成及 e2e 证据。
- 上海日界、短月、闰年、未完月/年及历史完整周期 → 本期截止和上月/去年对齐与现有报表相同，金额使用安全整数分，未来日期不参与；固定时钟范围及统计测试。
- 本期逐笔与比较摘要 → 模型捕获的请求完整覆盖预检明细和原文备注，成员/账本为任务内代号，结构化字段不额外附加真实显示名、数据库 ID、账号邮箱、原始导入字段、来源指纹或家庭码，比较期无逐笔备注；含姓名/邮箱的备注样例仍按已披露的原文语义处理，不作全面脱敏保证；脱敏样例与模型输入断言。
- AI 未开启、未有效受理或伪造前端操作 → 无供应商调用；正式受理后关闭选择仅允许原固定输入任务完成，新任务拒绝；本人选择及受理竞态集成测试。
- 生成期间插入/编辑/删除账目 → 各批统计和引用仍来自同一原快照，报告明确截止/快照，后续变化仅由重新生成反映；并发快照测试及报告回看检查。
- 空范围、仅收入、仅支出、无基期、部分可比或基数为零 → 空范围零调用且旧报告保留，其余结果不制造交易、无穷比例、完整性或省钱结论；统计、协议和 UI 测试。
- 多批次、长备注、边界条数/字节与汇总输入 → 每条只属于一个明细批次，所有批次先验证后汇总，24 批/25 次及所有字节上限生效；超限、单行过大或中间结果过大明确失败、不截断、不部分发布；容量单元及集成测试。
- Astra 实际接入 → 现有 Hub 在合成账单上按独立模型/推理配置完成明细及汇总协议；既有分类和自然语言仍走原模型/预算；供应商鉴权、模型不可用、超时或无效响应无回退，失败不覆盖旧报告；运行器测试和合成数据 smoke check。
- 实际公网长响应 → 同一鉴权分析接口在真实 HTTPS 转发/frp 链路及时透传阶段及保活、无意外缓冲，空闲/绝对时限支持接近 8 分钟预算的受控生成，客户端断开后取消可传播并按本地清理规则释放；使用虚构账目和受控延迟分别记录成功、预算到期及提前断开证据，不输出入口或正文，不以 loopback、Hub 单测或健康检查替代；实际链路 smoke 与转发配置核验。
- 非法模型 JSON、未知证据、错批/漏批、恶意备注或脚本正文 → 返回受控失败或安全文本，不能取得数据库/工具权限、生成任意执行链接或改变账目；协议、安全渲染及提示注入测试。语义建议质量以虚构样例人工核对，不能仅靠 JSON 格式宣称正确。
- 生成时站内导航、切换范围及重复点击 → 只有一个原在途任务，继续处理原范围，不增加每账本额度，不覆盖当前不同范围；主动取消、刷新/断网、结束应用会话后不自动重发，提交响应丢失只查原 UUID；控制器及 e2e 测试。
- 首次请求未送达、回执提交前失败、查询先到及原请求迟到 → 数据库确认无回执时在共同请求锁下生成 `NOT_ACCEPTED`，迟到同 UUID 不取数、不调用模型，用户可手动以新 UUID 重试；先建立回执的原任务只返回其实际状态。数据库/网络失败或模式屏障不可判定时保持未知，不能错误关闭已受理请求；不要求恢复原始输入；未受理终结竞态与断网恢复测试。
- 同范围重新生成/跨成员回看 → 成功原子替换最新报告，失败/取消保留旧正文，回看列表不出现失败空槽或旧版本，原成功回执被新报告替换后如实标明；共享/代次及并发测试。
- 跨家庭 ID、伪造成员/账本、过期/撤销 AppSession、成员离开/重加、关闭家庭及生成中模式变化 → 拒绝越权读取/最终保存，旧任务不能绑定新身份，创建者离开后报告仍由当前家庭合法成员读取；授权及撤销竞态集成测试。
- 共享资源、连续批次、超时与取消 → 原全局/家庭/成员窗口和并发有效，拒绝不部分扣额，重登/换账本不能绕过，原 AI 默认时限不变；`STOPPING` 先提交时禁止保存，保存先提交时取消返回完成，取消等待本地调用和清理后释放，超时/模式屏障后的迟到输出不得保存；资源与延迟供应商竞态集成测试。
- 快速多批窗口恢复 → 固定时钟下 5,000 条分 10 批在首个成员窗口内完成时，第 11 次汇总保持原租约等待窗口恢复，并在原 8 分钟预算内恰好调用一次；等待期间无重复扣额或长事务，三个窗口原子重验，跨窗、预算耗尽、取消、身份失效及模式变化均按约定收敛；本地窗口等待不重试供应商 429 或其他失败；资源窗口与快速模型 fixture 测试。
